# 群链接导入失效判定 - 规格

## 背景

当前“导入链接”会先新增、复活或收编 `group_link`，再访问 WhatsApp 公开邀请页抓取群名和头像。
公开页请求失败或没有识别到群资料时，导入仍被记为成功，因此格式正确但已经失效的邀请链接会进入群组主表。

业务口径调整为：公开邀请页获取不到 WhatsApp 真实群名，代表该链接失效。失效行必须在导入明细中反馈失败，
且不能新增、复活或收编到群组主表。

## 判定口径

- 继续先执行现有格式归一化，只接受 `chat.whatsapp.com/<22 位邀请码>`。
- 格式错误仍记为 `失败/格式错误`，不访问公开邀请页。
- 批内重复以及已经进入导入链接分组的链接仍记为 `失败/重复`。
- 对可能新增、复活或收编的链接访问 WhatsApp 公开邀请页。
- 只有 `GroupInvitePageMetadata.waSubject` 非空时，链接才允许写入群组主表并记为导入成功。
- 公开页返回非 2xx、请求超时、网络异常、页面解析不到群名，或者只获取到头像，都统一记为
  `失败/链接失效`。
- “链接失效”只表示本次导入无法从公开邀请页确认群名，不新增新的健康状态枚举，也不调用在线账号或协议层。

## 处理顺序

单条唯一链接按以下顺序处理：

1. 查询当前租户下同 URL 的 `group_link`。
2. 如果链接活跃且已经属于某个导入分组，直接返回重复，不请求公开页。
3. 对全新链接、软删除链接和未进入导入分组的已有链接抓取公开邀请页。
4. 如果没有群名，返回链接失效；不插入新行、不复活软删除行、不收编已有活跃行。
5. 如果有群名，再按现有四态规则新增、复活或收编 `group_link`。
6. 使用本次已经取得的公开页元数据更新 `group_link_preview`，不再二次请求公开页。
7. 在内存中生成逐行明细；全部行处理完成后，沿用现有批量写入明细和更新批次统计的流程。

导入批次头仍在逐行处理前创建。批次头、群组主表、预览表、导入明细和批次统计继续处于同一个事务中；
数据库写入异常时整批回滚。

## 明细与统计

新增失败原因常量：

```text
LINK_INVALID = "链接失效"
```

失效明细字段：

- `result = 失败`
- `fail_reason = 链接失效`
- `group_link_id = NULL`
- `success_type = NULL`
- `existing_origin = NULL`
- `group_name = NULL`

失效行计入批次 `failed_rows` 和接口 `failedRows`，不计入 `inserted_rows`、`adopted_rows`、
`duplicate_rows` 或 `formatErrorRows`。接口结构保持不变；`errors` 列表增加对应的
“第 N 行：链接失效”描述，便于调用方直接提示。

新增 Flyway `V054` 只调整字段注释：

- `group_link_import_batch.failed_rows` 改为“失败总数(重复 + 格式错误 + 链接失效)”。
- `group_link_import_detail.fail_reason` 改为“失败原因:重复/格式错误/链接失效;成功时为空”。

不修改历史导入结果，不回溯检测已经入库的群链接。

## 前端与接口

- 继续使用现有 `POST /api/group-links/import`，不新增预检测接口。
- 导入明细和失败 CSV 沿用现有 `failReason` 字段，自然展示“链接失效”。
- 本次不改导入页面交互，不增加在线账号选择。
- 当前前端提交成功后没有消费逐行 `errors`；本次后端保证明细和失败导出可见，页面即时展示逐行错误不在范围内。

## 测试

后端单元测试先失败、再实现：

- 全新链接获取不到群名时，明细为链接失效，失败数增加，且不插入 `group_link`。
- 公开页抓取抛异常时，同样记为链接失效并且不插入主表。
- 只有头像、没有群名时仍判定链接失效。
- 软删除链接失效时不复活。
- 未进入导入分组的已有链接失效时不收编。
- 获取到群名时才新增或收编，并复用元数据写入预览表。
- 已在导入分组中的链接仍优先判重复，且不请求公开页。
- 批次统计满足 `total = success + duplicate + formatError + invalid`，其中
  `failed = duplicate + formatError + invalid`。

后端数据库测试：

- 失效链接只有失败明细，不存在新建的 `group_link`。
- 软删除失效链接保持软删除，未分组失效链接保持原归属。
- 迁移后的字段注释包含“链接失效”。

## 非目标

- 不使用协议层账号执行真实进群或深度健康检测。
- 不新增独立的失效数量响应字段。
- 不回溯清理历史上已经导入但当前无群名的链接。
- 不改变 TXT、CSV、Excel 的解析规则和 22 位邀请码格式规则。

## 自检

- 无待定项或占位符。
- “获取不到群名即失效”覆盖网络失败、非 2xx、空页面资料和仅头像四种情况。
- 失效判定发生在群组主表变更前，不会产生失败明细与活跃主表数据并存的半成功状态。
- 重复、格式错误和链接失效三种失败原因互斥，批次统计可以闭合。
- 接口、数据库注释、明细展示和失败导出口径一致。
