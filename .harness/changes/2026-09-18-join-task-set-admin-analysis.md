## 关键设计决策

- 现有进群 SUCCESS 保留为入群事实，管理员阶段单独记录，整体步骤结果派生。
- 目标进群账号与操作管理员分离，按操作管理员协议路由。
- 用户截图明确：在分配方式/执行间隔之后、失败处理之前新增“群管理设置”区域，本期区域内放“设置管理员”开关。
- 由本群原有的受控管理员给新进群账号设置管理员，进群与设置结果及失败原因分别展示于进群任务详情。
- 后续“踢出其他管理员”放入同一区域，本期不增加该操作或预留死字段；原账号表的状态列不是本次开关。
- 新 source `join_task_admin`、aggregate `JOIN_TASK_ADMIN`，不伪造 PullTask 关联字段。
- 失败只重试管理员阶段；未知结果需核实；当前角色以群域事实为准。
- 候选只含同租户、发起人名下或未分配归属的共享账号，排除其他用户已归属账号和本条进群目标；派发前查询当前群角色。
- 任务创建原来没有保存 owner_user_id；开启功能时从可信登录身份写入，历史草稿首次开启同样处理。
- 管理员阶段与账号下一条进群串行；设置失败保留进群成功，计整步失败。默认最多核实 300000ms（最低 30000ms），次数沿用任务重试配置但单独累计。
