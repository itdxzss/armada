# 营销任务列表展示营销模板信息设计

## 1. 目标

在普通「营销任务」列表中新增两列：

- **营销模板预览**：展示任务所引用营销模板的内容摘要，过长时省略，点击后查看完整内容。
- **推广链接**：展示营销模板的推广链接；为空时展示全角 `—`，过长时省略，悬停查看完整链接，并可点击跳转。

本需求只补充任务列表的模板展示信息，不改变任务创建、调度、发送、状态流转和模板编辑规则。

## 2. 已确认业务口径

1. 一个营销模板可以被多个营销任务引用。
2. 一个营销任务只引用一个营销模板，通过 `marketing_template_id` 关联。
3. 列表展示营销模板当前最新内容，不建设任务创建时的内容快照。
4. 模板更新后，刷新营销任务列表即可看到最新内容。
5. 「营销模板预览」展示模板的 `content` 和 `body_text`；推广链接单独展示，不重复拼入内容摘要。
6. 按钮模板的按钮跳转地址属于按钮配置，不属于 `promotion_link`；`promotion_link` 为空时推广链接列显示 `—`。

## 3. 当前事实与缺口

### 3.1 后端

- `marketing_task` 只保存 `marketing_template_id` 和模板名称快照。
- 模板内容保存在 `marketing_template.content`、`body_text`、`promotion_link`。
- `GET /api/marketing-tasks` 当前只查询任务表并返回 `MarketingTaskVO`，没有模板正文和推广链接。
- 现有租户行拦截器会为 `marketing_template` 查询注入 `tenant_id`，模板补充查询必须继续经过 MyBatis Mapper。

### 3.2 前端

- `MarketingTaskRow` 当前只有 `marketingTemplateId`、`marketingTemplateName`。
- 任务列表已有列设置、Element Plus 表格、固定操作列和分页能力。
- 营销模板页面已有链接省略、悬停和跳转交互，可沿用其 Element Plus 交互风格。
- 页面加载的模板选项用于新增/修改任务，不作为本需求的数据来源。

因此，本需求是前后端契约缺口，不是数据库结构或协议层缺口。

## 4. 方案比较

### 4.1 推荐：分页任务查询后，后端按模板 ID 批量补充

流程：

1. 按现有 SQL 分页查询当前页营销任务。
2. 提取当前页非空 `marketingTemplateId`，去重后批量查询有效营销模板。
3. 按模板 ID 建立映射，将模板信息写入对应 `MarketingTaskVO`。

优点：

- 不改变现有任务分页、筛选和统计 SQL。
- 当前页只增加一次模板批量查询，不产生 N+1。
- 多个任务引用同一模板时只查询、转换一次。
- 不需要把模板投影字段塞进 `MarketingTask` 实体。
- 租户隔离继续由现有 MyBatis 租户拦截器保证。

代价：每次任务列表请求由一次 SQL 增为两次 SQL；当前默认每页 10 条，模板 ID 还会去重，成本可控。

### 4.2 备选：任务列表 SQL 直接 `LEFT JOIN marketing_template`

优点：一次 SQL 返回全部数据。

缺点：现有 `selectPage` 直接映射 `MarketingTask` 实体，联表后需要新增列表投影或污染任务实体；同时要为任务列和筛选条件补齐表别名，改动面更大。该方案不如批量补充符合当前代码结构。

### 4.3 不采用：前端另查模板列表后自行匹配

任务列表响应会依赖另一分页接口的加载范围和刷新时序，无法保证每个任务引用的模板都已加载。任务列表应由自身 API 返回完成展示所需的数据，因此不采用。

## 5. API 设计

`GET /api/marketing-tasks` 的每条 `MarketingTaskVO` 在现有字段后新增三个可空字段：

```json
{
  "marketingTemplateContent": "标题 / 核心卖点",
  "marketingTemplateBodyText": "正文 / 活动说明",
  "marketingTemplatePromotionLink": "https://example.com/activity"
}
```

字段语义：

| 字段 | 类型 | 说明 |
|------|------|------|
| `marketingTemplateContent` | `string \| null` | 模板内容 `content` |
| `marketingTemplateBodyText` | `string \| null` | 模板正文 `body_text` |
| `marketingTemplatePromotionLink` | `string \| null` | 模板推广链接 `promotion_link` |

模板不存在或已软删除时，三个字段返回 `null`，任务行仍正常返回。

`MarketingTaskVO` 同时用于创建及生命周期操作响应。为保持响应一致，返回单个任务时按其模板 ID 查询一次模板并填充新增字段；列表接口使用批量查询。这样前端启动、暂停、继续或关闭任务后替换列表行时，不会丢失模板展示信息。

## 6. 后端设计

### 6.1 Mapper

在 `MarketingTemplateMapper` 增加按 ID 集合查询有效模板的方法：

```java
List<MarketingTemplate> selectByIds(@Param("ids") List<Long> ids);
```

约束：

- 调用方保证集合非空、已去重。
- SQL 使用 `id IN (...) AND deleted_at IS NULL`。
- 不手写 `tenant_id`，继续由租户拦截器注入。
- 不修改现有模板分页查询。

### 6.2 Service

`MarketingTaskServiceImpl.listTasks` 在取得当前页任务后：

1. 提取并去重模板 ID。
2. 一次批量查询模板。
3. 转为 `Map<Long, MarketingTemplate>`。
4. 调整 `toVO`，接收可空模板并填充三个新增字段。

单任务返回路径复用相同的 VO 转换逻辑，只查询当前任务的一个模板。

### 6.3 数据与状态影响

- 不新增或修改数据库字段、索引和 Flyway。
- 不修改任务状态机、账号占用、轮次调度和发送消息组装。
- 不修改营销模板保存规则。
- 不调用协议层。

## 7. 前端设计

### 7.1 类型和列顺序

`MarketingTaskRow` 增加与 API 一致的三个可空字段。

两列放在「任务名称」之后：

1. ID
2. 任务名称
3. 营销模板预览
4. 推广链接
5. 其余现有业务列
6. 操作

同步更新 `taskColumns` 和 `dynamicColumns` 索引，让两列参与现有列设置。

### 7.2 营销模板预览

摘要规则：

1. 对 `marketingTemplateContent`、`marketingTemplateBodyText` 分别去除首尾空白。
2. 过滤空值后用一个空格连接。
3. 没有内容时显示 `—`。
4. 表格单元格单行省略，不撑宽表格。

有内容时以可点击的主色文字展示。点击后打开任务域内的只读 Element Plus 对话框：

- 标题：`营销模板：{marketingTemplateName}`。
- 分别展示「内容」和「文本」。
- 使用 `white-space: pre-wrap` 保留换行。
- 空字段显示 `—`。
- 对话框只读，不提供编辑或保存入口。

列表响应已经包含完整文本，点击时不再请求接口。

### 7.3 推广链接

- 空字符串、纯空白或 `null` 显示全角 `—`。
- 有值时单行省略，并用 `ElTooltip` 展示完整值。
- 仅 `http:`、`https:` URL 可点击。
- 合法链接使用 `ElLink`，`target="_blank"`，并设置 `rel="noopener noreferrer"`。
- 非法协议的历史值只显示文本和 tooltip，不提供跳转，避免 `javascript:` 等风险。

### 7.4 模板更新后的列表同步

任务侧「修改营销素材」成功后调用 `refreshTasks()` 刷新当前页。由于同一模板可以被多条任务引用，不能只更新当前操作行；刷新可以确保当前页所有引用该模板的任务同时显示最新内容。

## 8. 错误处理

- 任务列表或模板批量查询失败：沿用现有「营销任务加载失败」错误反馈，不返回半成品分页结果。
- 单个任务找不到有效模板：新增字段为 `null`，任务行仍显示，模板预览和推广链接均显示 `—`。
- 点击预览不发生网络请求，因此没有独立 loading 或错误状态。
- 非法链接不跳转，不通过 `v-html` 渲染任何模板内容。

## 9. 测试与验证

### 9.1 后端测试

1. 两个任务引用同一个模板，列表两行均返回相同内容、正文和推广链接。
2. 不同任务引用不同模板，字段按 ID 正确匹配。
3. 模板推广链接为空时返回 `null`。
4. 模板不存在或软删除时任务仍返回，新增字段为 `null`。
5. 列表分页、筛选和总数不变。
6. 切换租户后不能补充其他租户模板数据。
7. 创建、启动、暂停、继续、关闭返回的 `MarketingTaskVO` 不丢失新增字段。

验证命令以实施计划为准，至少包含相关 Java 单测和真库 DbTest。

### 9.2 前端测试

1. 表格存在「营销模板预览」「推广链接」两列并参与列设置。
2. 摘要正确组合内容和正文，空值显示 `—`。
3. 点击摘要打开完整内容对话框并保留换行。
4. 空推广链接显示 `—`。
5. 合法长链接支持省略、tooltip 和新窗口跳转。
6. 非 HTTP(S) 链接不可点击。
7. 修改共享模板成功后刷新任务列表。

最终运行前端相关测试、`pnpm typecheck` 和 `pnpm build`。

## 10. 部署与回滚

部署顺序：先后端、后前端。新增 JSON 字段对旧前端向后兼容。

回滚只需回退后端 VO/Mapper/Service 和前端两列及预览组件；没有数据库数据和协议层回滚动作。

## 11. 验收标准

1. 营销任务列表新增两列，列顺序和列设置正常。
2. 模板内容过长时不撑破表格，点击能查看全部内容。
3. 推广链接为空显示 `—`，长链接可悬停查看并点击跳转。
4. 多个任务引用同一模板时均展示正确模板信息。
5. 模板修改并刷新后，所有引用任务展示最新内容。
6. 原有列表分页、搜索、任务操作和发送行为不受影响。
