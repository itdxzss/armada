## 已确定的差异与未确定项

- 之前直接将历史 provider_id=222 固定为当前 API providerIds，缺少当前报价有效性核对，不能当作已经对齐网页购买行为。历史商家与当前报价名单不同、网页有等待逻辑，是目前已确定的差异。
- 尚不能确定 222 不在当前列表是库存变化、渠道差异还是其他平台规则；没有证据证明它与 196 存在 ID 映射。不能声称已查明唯一根因，也不能把静态报价当作真实可采购保证。
- API 规定 providerIds 是指定商家列表，maxPrice 为最高价；Armada 还会在成交后核对精确价格。参考 `https://grizzlysms.com/docs-old` 与 `https://api.grizzlysms.com/docs/client`。

## 现有代码缺口

- 控端：`AccountRegistrationCreateDTO`、前端 `AccountRegistrationRequest` 与创建表单只有国家/价格/数量，没有指定商家字段。报价返回中已有 providerIds。
- 后端：V197 的 task.provider_id 已存在，但当前仅手机许可写入；worker 也仅 IOS_DEVICE 分支识别该值。控端新增选择需同时贯通 DTO、校验、Store、幂等参数比对、任务展示及 worker，不能只加一个下拉框。
- IPA：r6 只显示许可商家，不能自行选择。认证配置同时固定 requestId、国家、价格和商家；只增加手机输入框仍会被服务端许可限制，不能满足免部署切换。
- 现有控端创建会继续进入 Cobalt、导入和上线链路，与手机原生注册不同。若本阶段仅验证取号，需显式的取号验证流程，避免用完整 Cobalt 任务顺带验证其他功能。

## 调整方案及顺序

1. 控端先提供国家 → 价格档位 → 商家选择（默认使用该档实时商家列表；可手动指定其中一个 API 商家）。确认页显示数量、单价、商家和本次行为；过时报价或不可用商家先刷新/提示，不能静默换商家或提高价格。
2. 第一阶段建议仅验证同一后端采购链路成功分配一个号码并记录订单/成交价；清晰区分“取号成功”“收码成功”“注册成功”。订单必须有后续接续或按供应商规则取消的路径，不能为了验证而留下无人处理的订单。新的付费尝试在参数确定后由用户明确开始，失败不自动补购。
3. 控端验收后，IPA 一次性升级为从服务端拉取实时国家/档位/商家，支持手动选择有效商家码，开始前显示最终价格。既有任务锁定原参数，新选择只作用于下一次用户手动开始的任务。
4. 服务端把设备认证与每次注册意图分开：设备凭证只认证身份与权限；本次选择经服务器校验后保存为独立任务快照，requestId 仍保证重复点击不重复采购。可调整的策略在控端管理，不再为每次选择修改环境变量和重启。供应商 API key 保持仅在服务端。
5. 若后续需要接近网页的等待体验，单独设计有时长/次数上限的“等待号码”；只能对明确未分配的 NO_NUMBERS 等待重试，超时/未知结果停下来核对。此项不随商家选择自动启用，本轮不运行。

## 影响与验证边界

- API：控端创建/查询增加商家选择与实际约束展示；手机需报价和新的注册意图确认接口，不能直接放开任意付费请求体。
- 数据：优先复用 task.provider_id 及当前任务聚合；设备权限与可调整策略的存储需实施前核对现有配置能力，必要的 schema 修改必须 Flyway。
- 租户/并发：报价选择、设备许可和任务均在认证租户内校验；重复请求参数不一致返回冲突；已拿号/未知结果任务不能换号。
- 验证：真实 Mapper/H2 保存及幂等、HTTP 参数契约、报价过期/缺号/未知结果、前端选择联动；最后再进行明确范围的真实单号验收。模拟器或控端 Cobalt 成功不能替代 iPhone 原生注册成功。
- 部署：本轮没有代码实现或部署，r6 保持原有单次任务状态。后续需要一次后端/控端发布和一次 IPA 升级，完成后常规更换商家不再需要重新部署或打包。
- 回滚：关闭新建任务入口、回滚本次 UI/API 版本；保留所有已创建订单和已确认参数，不重置已付费或未知结果任务。

## r7 实施决策（用户已于本轮授权调整）

- IPA 文件采用短名 `WA-r7.ipa`。本次先交付控端取号验证入口；手机商家选择在开始前生效。
- 新增 `account_registration_device_permit` 属于设备采购授权聚合，每租户每设备一条当前许可。现有 task 是已提交、不可变的采购执行事实，不能通过修改已执行 task 表达尚未消费的新许可；现有数据模型没有等价设备注册许可表。旧环境配置中的许可约束迁移到控端写入的这张表，环境只保留 token/tenantId/deviceId 身份，不留两份可变许可来源。
- 许可保存 country/price/默认 provider/expiry、requestId 和替代请求引用；task 仍保存开始时的实际选择快照，两者分别是采购授权和执行事实。手机只能在控端授权的国家/价格档位中选择当前有效商家，不能改变价格上限或自行创造下一笔许可。
- 控端保存许可不取号；点击“取号验证”明确确认后使用与手机相同的 IOS_DEVICE 采购链路，成功后等待手机接续，不运行 Cobalt/导入/上线。已分配号码不能被新许可覆盖。
- 新许可保存和开始通过同一设备许可行锁串行化，防止切换许可与旧 start 并发产生两单。requestId 必须保持同键同参数；旧客户端缺少显式商家字段被拒绝。
