## 目标（一句话）

## 关键设计决策

- 不放宽群列表的可用管理员判定；`在群 + 管理员 + 在线 + 正常 + 已绑定协议` 仍是严格条件。
- 不修改 Web/Android 协议的轻量群列表上报。管理员事实来自既有完整群 metadata，避免数千群列表同步携带全成员造成额外协议和网络负载。
- 完整快照先替换成员行，再按 `account.ws_phone = snapshot.phone` 识别当前租户未软删的上控账号。
- 同一账号可能同时出现 PN 和 LID 身份，按账号聚合并取更强角色，避免重复关系写入和管理员降级。
- 关系事实时间使用 metadata 请求开始时间；继续复用 `GROUP_SNAPSHOT` 与现有事件优先级，旧快照不会覆盖更新的 `WGP2_REMOVE` / `WGP2_LEAVE` 等精确事件。
- 不增加一次性历史快照 SQL 回填。存量快照可能早于最新退群或降权事实，直接回填存在误复活关系或留下陈旧管理员角色的风险；由新鲜 metadata 周期/手动刷新安全修复。
- 不新增表、字段、索引、API 字段或协议消息。
- 邀请码选号直接信任本轮完整 metadata 已确认的管理员号码，只在当前群租户内匹配在线、正常、
  已绑定协议的账号；账号群关系仅用于候选排序，不再作为首次同步的准入条件。
