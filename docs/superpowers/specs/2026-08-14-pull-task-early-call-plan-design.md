# 普通群链接前期拉人调用计划

## 需求与现状

普通群链接任务已经在进入拉人阶段时冻结完整初始调用波次，但当前所有调用都按
`pullCountMin`～`pullCountMax` 分批。创建页缺少“前期单次拉人数”和
“前期拉人执行次数”，因此无法让前几次调用使用更小的固定人数。

本次用户要求覆盖 2026-08-02/03 设计中“两个前期拉人字段暂不接入”的旧口径。

## 合同与持久化

- 创建请求增加 `earlyPullCount`、`earlyPullCallCount`，均为必填正整数。
- `pull_task_standard_setting` 增加 `early_pull_count`、
  `early_pull_call_count`；新任务页面默认分别为 `1`、`2`，创建时冻结用户提交值。
- 升级前已存在的冻结任务按 `early_pull_call_count=0` 保持原计划语义，不会因部署自动增加前期调用。
- 任务详情的 `standardSetting` 原样回读两个字段，前端“已保存任务配置”展示它们。

## 调用计划规则

每个执行行创建初始拉人波次时：

1. 从尚未消费的料子开头取最多 `earlyPullCallCount` 批；每批固定最多
   `earlyPullCount` 人。
2. 剩余料子继续按现有 `pullCountMin`～`pullCountMax` 选择器分批。
3. 料子不足时最后一批取实际剩余人数，不制造空调用。
4. 重试波次只处理上一波的安全重试候选，继续使用原人数范围，不再次套用前期规则。
5. 站台数量、拉人间隔、粘性拉手和回执结算规则不变。

## 影响与验证

- 前端：创建表单、默认值、请求类型/载荷、已保存配置回显。
- 后端：创建 DTO/校验、冻结配置、Mapper、详情 VO、初始波次分批。
- 数据库：Flyway V115；现有任务补齐为 `1` 人、`0` 次以保持原计划，新创建任务由 API 显式写值。
- 协议层：单次调用载荷没有新增字段，不需要修改。
- 验证：JSON 合同、H2 创建/回读、H2 完整波次规划、迁移结构测试、前端字段测试、
  typecheck 与构建。
