# 控端自动商家分配：精确价格边界

## 用户目标
把已成功的直接接口试验用于控端：自动模式不传商家ID，minPrice=maxPrice=所选单价；手动指定商家仍保留。5秒/最多50次以及订单不明不重购沿用。没有再次购买验证授权，不触发新采购。

## 实现
- AccountRegistrationWorker 删除自动模式查询报价后筛选供应商的路径，直接生成精确上下界、空商家列表的请求；手动模式维持现有固定商家请求。
- 创建任务仍验证价格与库存；自动模式不再要求报价返回供应商ID列表，手动模式仍检查供应商存在。
- 控端普通新建注册、手机取号验证均标明“自动（平台分配，不限定商家）”，提示清空商家即恢复自动；列表显示自动分配。
- 成交价仍须等于用户选价，意外高低价仍保存订单并走原异常取消流程。旧终态任务不复活，不修改现有许可、IPA或历史订单。
- 无DB/API/Redis结构变更，无新增配置。串行调度公平性不在本次修改范围。

## 验证与评审
- 测试覆盖实际HTTP上下界与无providerIds/exceptProviderIds；自动模式不依赖采购期间的商家目录，手动商家保持不回退；更低与更高成交价仍拒绝。
- 初次测试受沙箱Mockito attach限制，非业务失败；获准JDK17重跑：注册/设备/Grizzly相关199项零失败，包含真实H2已有SQL回归。
- 前端Node/tsx19项通过，vue-tsc、变更文件ESLint、prettier与diff检查通过。
- 自审未发现本次改动的阻断问题：参数构建共用同一执行器，保留授权/幂等/租约/成交复核，未使用新存储或绕过租户边界。
