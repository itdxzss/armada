## 关键设计决策

- `mute_status` 新语义：`NULL` 未受限、`1` 消息发送受限、`2` 拉人受限、`3` 两者都受限。
- `cooldown_until` 是唯一恢复截止时间。不同能力重复受限时状态合并，截止时间取较晚值。
- 按能力类型放行：消息发送受限(1)只拦营销发消息，拉人受限(2)只拦普通拉人，双重受限(3)才同时拦截两类动作。
- 恢复 SQL 由 `(cooldown_until, id)` 索引定位到期区间，每次只更新 500 行；不把全表加载到 JVM。
- 到期恢复只清空当前限制状态与截止时间，保留最近原因和事实时间作为诊断历史。
- 只有明确终态的账号受限失败才换号；UNKNOWN/非终态继续使用原 command 对账，单钩或双钩后不回退。
- 换号重发递增 `dispatch_attempt` 并生成新 commandId；旧尝试迟到回调按身份识别后忽略，防止污染新尝试。
- 软受限账号退出当前超链任务的可用集合，但不记为永久失效/封号；即使最大使用账号数为 1，也允许一换一补选替代账号。
- 未采用 `puller_restriction_status / puller_restriction_until`，避免同一账号限制事实出现两套权威来源。
