# 超链营销六菜单多 Agent 验收包

## 目标

把超链营销六个菜单的接口、浏览器、权限、租户和端到端验收拆成可由独立 Agent 直接执行的文档，并明确依赖顺序和证据格式。

## 缺口拆解

- [x] 建立总入口和 API/浏览器分工说明。
- [x] 建立公共门禁 Agent 文档。
- [x] 把超链任务拆成列表编辑器、生命周期、详情统计三个 Agent 文档。
- [x] 为数据包、模板、策略、图片素材、市场分析分别建立 Agent 文档。
- [x] 建立最终端到端、RBAC、跨租户和清理 Agent 文档。
- [x] 标注硬前置、软前置、可并行关系和 canary 授权边界。

## 关键决策

- 测试采用“API 约 60%～70% + 浏览器约 30%～40%”，不能只调用接口或只点击页面。
- API 用于边界、权限、租户、并发、幂等和状态机；浏览器用于真实用户路径、交互和错误呈现。
- 浏览器用例统一使用已安装的 `browser:control-in-app-browser` 技能及应用内 Browser，不安装重复技能副本。
- 真实 WhatsApp、钱包和公网短链属于 canary，必须单独确认白名单与安全信封。
- 每个 Agent 使用独立 RUN_ID 命名空间，依赖通过脱敏 fixture 别名交接，减少共享环境冲突。

## 影响范围

- 仅新增测试执行文档和本变更记录。
- 不修改 Java、SQL、前端、配置、Redis、Kafka、协议或任何真实环境数据。
