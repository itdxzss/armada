# 养群管理三菜单实施契约

日期：2026-09-10。状态：本地实现与聚焦验证完成，尚未部署、运行迁移或做真实发送验收。

本文件以用户本次反馈为准，替代之前分析中尚未落定的实施细节。原型仅作为需求参考；本轮修改 Armada 后端和 Vue 前端，未修改原型或协议仓库。

## 1. 业务流程与三个菜单

剧本素材库 → 养群剧本 → 养群任务。业务人员先在已有进群任务完成踩链接进群、间隔和失败处理，再回来检查并启动营销。

| 菜单 | 本轮行为 | 数据来源 |
|---|---|---|
| 剧本素材库 | 按名称、消息类型查询，新建、编辑、复制文字/图片/图文/按钮消息 | 复用 marketing_template；图片引用同一 marketing_template_file |
| 养群剧本 | 编排角色、内容、顺序和逐项间隔；查询、新建、编辑、复制、启停与软删除 | 新的 script_marketing_definition 定义聚合，不绑定实际账号 |
| 养群任务 | 选用剧本副本或直接编排，选择推手分组、目标群与管理员，保存草稿、检查、启动和查看结果 | 既有 script_marketing_task / group / send_record 聚合 |

完整消息按既有 link_mode 区分类型；纯图片允许无文字。图片不按超链/剧本复制成两张表。消息选入剧本、剧本选入任务都复制内容快照，后续编辑或删除定义不会追改既有任务。图片引用保护同时覆盖定义和任务。

素材库没有新增删除接口，避免通过这个入口触发既有普通营销任务的素材删除终止逻辑。原型中的语言/分类等附加字段、本轮未确认的引用回复与可配置跳过策略不属于本次实现。

## 2. 角色与账号

- 每个发送项由业务人员选择 ADMIN / PROMOTER，设置稳定且可读的 roleKey。同名角色多次发言只计算一个人；同名不能混用身份或管理员账号。
- 管理员沿用手动选择。本轮已提出可选的管理员分组自动分配问题，未收到改为自动分配的要求，按已说明的默认方案实施。业务角色“管理员”不替代 WhatsApp 群内的真实发言资格。
- 推手不手工绑定账号。启动时每个群分别从所选分组中本群可用账号随机匹配角色，同群不同角色不能占用同一账号，管理员账号不计入推手候选。
- 分组账号总数严格大于不同推手角色数，例如 5 个推手要求分组至少 6 个账号。这是容量门槛；每个群另需至少 5 个真实在群、账号可用且具备发送能力的不同推手。
- 同一角色的全部消息都必须匹配账号的协议能力。不能用支持不了该角色按钮消息的账号凑数。
- 全部群检查通过后，启动在任务锁与同一事务中保存各群 bindings_json，再进入发送。暂停、恢复及服务重启不重新抽账号。

## 3. 选择群与缺口报告

群候选来源为推手分组账号的真实在群关系，支持群名称搜索与分页。切换搜索保留已勾选群；最终以明确勾选的群为任务目标，同一群 JID 禁止重复。

保存草稿不要求资源已齐备，也不发送。表单检查、任务列表检查和启动拦截都展示完整报告：群名称及 JID、所需推手、已确认可用、缺口、离线/受限、没有发言权限、关系或发言资格未确认等原因。人数按不同账号计算，不按群总成员数或消息条数计算。

示例：需要 5 个推手，已确认可用 1 个，缺 4 个；请到进群任务补齐推手，完成后重新检查。

- 报告可持续查看，支持只看不达标群与分页；不只弹瞬时提示。
- 任一已选群不达标，整个任务保持零消息提交；不静默删除该群，不先发送其他群。
- “去进群任务”仅导航到 /task/join。编辑页先保存草稿，再导航，避免丢失配置。
- “重新检查”读取群模块的成员/发言事实和账号状态，不以进群任务已完成替代；检查通过仍需显式启动。
- 启动时后端再次检查全部目标；定时首次实际提交前再次检查全部原绑定，失败则暂停整个任务并保持零提交。
- 营销不自动创建进群任务、不踩链接、不重抽进群账号、不增加进群回调或审批状态机。

## 4. 间隔与执行

每项配置 waitMinSeconds / waitMaxSeconds（0–86400 秒），相等为固定间隔。任务默认间隔仅用于新建发送项默认值。

第一条在到达任务开始时间后立即进入调度。后项计划时间为上一项实际入队时刻加本项随机等待；等待值只抽一次并持久化 next_at。意图、原命令 outbox 和下项时间同一事务提交，入队不表示发送成功。

提交进度和回执分别推进：下一项不等待前项回执；迟到回执只更新原记录，不重复推进、不创建新发送。每群执行完整剧本，各群独立推进。预计等待展示每群间隔总和，不含第一条等待、发送、排队或异常耗时。

暂停尽可能挂起尚未投递的原命令；在途消息继续跟踪结果。恢复复核原绑定，恢复原命令及原进度，下一未提交项立即进入调度，丢弃剩余等待。result_deadline_at 单独记录等待结果的截止，恢复不能篡改原 submitted_at。

## 5. 首版异常处理

| 情况 | 当前行为 |
|---|---|
| 全任务首次提交前资格变化或准备失败 | 暂停全任务，保持零提交，业务人员处理后重新检查/继续 |
| 已开始后某群账号离线、退群、无法发言或群已不可用 | 暂停该群，保留角色和未处理项；其他群继续；处理后复核原绑定再继续 |
| 单项明确发送失败或后续项局部准备失败 | 据实记录失败，继续后项；失败时间作为下一项计时依据 |
| 结果等待超时 | 明确未发送的命令取消并记失败；无法确认的记未知，不自动重发 |
| 迟到回执 | 只更新对应原命令，已关闭任务不重新打开 |
| 单群暂停/继续 | 全任务必须运行中；不能绕过全任务暂停或截止时间 |
| 关闭或截止 | 停止后续提交，取消明确未投递命令，在途结果继续补记 |
| 所有项处理完但仍有待收敛原命令 | 保持执行状态，直至结果/超时收敛；处理进度与成功数分别展示 |

没有自动替换已绑定账号，没有未知结果重试。首版异常处理采用明确的暂停群/继续后项规则，未提供策略下拉选择或“跳过该账号后续消息”。引用回复需要单独验证跨协议能力，本轮未增加引用字段或降级发送逻辑。

## 6. 模型、权限与兼容

| 新结构 | 所属聚合与必要性 |
|---|---|
| task.account_group_id | 记录任务选定的推手池，不重复账号分组归属事实；NULL 标识存量固定账号任务 |
| group.bindings_json | 启动时的逐群随机结果；不同群候选不同，不能存成全任务唯一一套账号 |
| task.pause_reason | 整任务复核/准备失败原因 |
| group.paused / pause_reason | 单群暂停及原因，与整任务状态独立 |
| send_record.result_deadline_at | 回执截止与不可改写的原提交时间分离，支持挂起后恢复原命令 |
| script_marketing_definition | 可复用定义的名称、状态、角色消息 JSON 与所有者；执行实例保存独立快照，不能混入任务状态表或图片表 |

新增 V185 / V186，不修改已应用 V180。未新增 Redis 结构、图片表、群成员副本或进群准备表。存量 account_group_id 为 NULL 的任务保留旧固定账号、结果后计时语义；新建任务必须填写分组，编辑旧草稿时显式补齐配置。

权限继续使用 tenant:script_marketing:view/create/edit/operate；任务与剧本定义限制当前租户及本人，公共素材沿用租户内公共模板范围。服务端复核群、分组、账号和图片访问资格。移动既有任务菜单时保留 ID、路由和原按钮权限，新素材/剧本菜单通过现有角色管理分配。

## 7. 验证与发布边界

聚焦验证结果和命令见 [验证记录](../../.harness/changes/script-marketing-refinement/test-summary.md)。本地 H2 真跑生产 Mapper XML、租户插件与事务；浏览器仅调用测试夹具 API。它们不代表测试环境接口联调、真实 MySQL 迁移或 WhatsApp 实际送达验收。

发布前需确认目标环境，再执行 Flyway、更新前后端并配置菜单授权；对指定测试群验证资格变化、真实发送和回执。每日重复调度未加入。

数据模型 wiki 为真库 information_schema 导出的自动文档。本轮只新增迁移文件，没有修改共享 schema，且没有当前目标环境快照，故未伪造或手改 wiki；迁移后按规则重新导出并运行 gen_datamodel.py。回退必须先收敛新任务和原命令，保留绑定及发送事实，不能让旧执行器接管新配置。
