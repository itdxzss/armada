# 普通群链接拉群任务测试排查手册设计

日期：2026-08-04

状态：已确认，待编写手册与只读 SQL 附录

范围：拉群任务 → 群链接模式 → 普通群链接版

## 1. 目标

为普通群链接拉群任务提供一套轻量、只读、可重复使用的测试排查材料。测试人员只需保留目标环境、测试时间、任务 ID 和页面现象，排查人员即可沿任务、执行行、业务动作、协议命令和结果回写定位卡点。

本设计不新增产品功能、页面、接口、数据库结构或运行时诊断逻辑。

## 2. 交付物

交付两个文件：

- `docs/operations/pull-task-normal-link-diagnosis.md`：快速排查手册。
- `docs/operations/pull-task-normal-link-diagnosis.sql`：以 `taskId` 为入口的只读 MySQL 查询附录。

正文保持简短，SQL 和日志检索方法放在附录。后续状态或字段调整时，以当前代码、Mapper 和 Flyway 迁移为事实源更新文档。

## 3. 使用流程

测试人员提供：

```text
环境：测试环境
测试时间：2026-08-04 15:30 左右
任务 ID：123
操作：点击启动
现象：页面一直显示执行中
补充：可选截图
```

排查顺序固定为：

```text
父任务
→ 群执行行
→ 当前执行阶段
→ 角色账号和业务动作
→ protocol_command_outbox
→ Armada 日志
→ 协议层日志
→ 结果回调与状态收口
```

排查回复统一包含结论、证据、影响、建议和确定性。确定性只使用“已确认”“高概率”“信息不足”三类，避免把推断表述为事实。

## 4. 执行阶段映射

手册按 `PullTaskExecutionStage` 的七个阶段定位：

| 阶段 | 主要检查事实 | 典型定位 |
| --- | --- | --- |
| 1 链接校验 | `group_jid`、原因码、`next_run_at` | 链接失效、网络预检、后端校验 |
| 2 管理入群 | 管理角色、踩链接动作、在群状态 | 账号选择、协议进群、入群待审批 |
| 3 管理—拉手联系人 | 双向 `SAVE_CONTACT` 动作 | 联系人命令；明确标注失败通常不阻断主流程 |
| 4 管理邀请拉手 | `INVITE_TO_GROUP`、拉手在群状态 | 管理权限、拉手账号、协议邀请 |
| 5 拉人执行 | `pull_task_pull_call`、料子和站台逐成员结果 | 拉手分配、批量拉人、协议结果回写 |
| 6 料子提权 | `admin_status`、`admin_command_id` | 管理员设置命令及结果 |
| 7 收口 | 拉手释放、执行行终态、父任务状态 | 状态汇总或资源释放 |

## 5. 卡点判定

卡点不能只按停留时长判断，必须同时检查任务状态、执行行状态、当前阶段、`next_run_at`、调度租约、业务事实、`commandId`、Outbox 和结果回写。

核心判定规则：

| 事实 | 判断 |
| --- | --- |
| 尚未生成业务动作 | 后端调度或阶段状态机 |
| 业务动作为待执行且没有 `commandId` | 事务编排或 Outbox 入库前 |
| Outbox 为 `PENDING`、`LOCKED` 或 `DISPATCHING` | Armada 命令发布链路 |
| Outbox 为 `DEAD` | Kafka 发布失败，以 `last_error` 为直接证据 |
| Outbox 为 `SENT`，业务事实仍为已提交 | 协议 worker 执行或结果回传链路 |
| 协议日志已有结果，业务事实未变化 | Armada 回调消费、关联或落库 |
| 业务事实为 `UNKNOWN` | 结果无法确认，检查自动核对流程 |
| 执行行为 `WAIT_RESOURCE` | 管理、拉手或站台资源等待，不直接判为程序卡死 |
| `next_run_at` 尚未到达 | 正常排期 |
| `next_run_at` 已到且租约过期，长期无人领取 | 调度器、领取 SQL 或实例异常 |

所有结论分成：

- 确认事实：数据库或日志直接证明。
- 初步判断：根据事实推断的故障层。
- 待确认项：需要继续查询的证据。

## 6. SQL 附录设计

SQL 文件只接受 `@task_id`，先从 `pull_task` 确认租户、任务类型和模式，防止误查其他拉群业务。全部语句为 `SELECT`，不创建临时表、不加锁、不调用写存储过程。

SQL 按顺序输出：

1. 父任务概况：任务类型、模式、状态、启动与结束时间、版本。
2. 群执行行概况：执行 ID、状态、阶段、原因、排期、租约和最近业务动作时间。
3. 角色账号：管理、拉手、站台的在群、管理员、可用性、占用与释放状态。
4. 账号动作与 Outbox：保存联系人、邀请、踩链接及相同 `commandId` 的发送事实。
5. 拉人调用与 Outbox：计划人数、拉手、调用状态、命令和结果。
6. 料子结果：入群状态和提权状态的分类汇总及异常行。
7. 异常摘要：到期未执行、过期租约、无命令动作、Outbox 死信、已发送未回写、未知结果、资源等待和父子状态未收口。

默认结果不输出完整群链接、完整号码或 `payload_json`。需要继续查协议层时，仅提取 `commandId`、时间范围和必要的协议账号标识。

## 7. 故障分类

手册将问题归入以下一类，避免用“后端问题”笼统收口：

1. 创建链路：草稿、链接解析、TXT 解析、匹配或提交冻结。
2. 生命周期：启动、暂停、恢复、结束或父任务状态。
3. 后端调度：候选未领取、租约未回收或阶段未推进。
4. 资源分配：管理、拉手、站台不足或账号不可用。
5. 业务编排：动作或拉人调用没有正确生成。
6. Outbox/Kafka：命令待发送、发送中、取消或死信。
7. 协议路由：命令没有到达账号所属 worker。
8. 协议执行：worker 已收到命令，但 WhatsApp 操作失败或没有确认结果。
9. 回调处理：协议已有结果，Armada 未关联或落库。
10. 结果核对：未知结果没有按预期收敛。
11. 执行收口：单群终态、资源释放或父任务汇总异常。

## 8. 安全与范围边界

- 只覆盖 `STANDARD + NORMAL_LINK` 普通群链接版。
- 不混入旧建群营销、拉群营销、历史群拉人或其他拉群模式。
- 查询默认只读，不自动重试、恢复、释放账号或修改任务状态。
- 不重启 Armada、协议层、Kafka 或数据库。
- 连接远程环境前必须由用户确认目标测试环境；生产环境需再次明确确认。
- 私钥、凭据、完整号码、完整群链接和命令载荷不得写入文档或排查回复。

## 9. 验收标准

1. 输入有效 `taskId` 后，能够确认任务是否创建、是否启动。
2. 能定位到具体 `executionId` 和七阶段之一。
3. 能区分正常排期、资源等待、结果未知和真正卡死。
4. 有 `commandId` 时，能串联业务事实、Outbox 和协议日志。
5. 能判断故障属于前端、Armada、Kafka、协议 worker 或 WhatsApp。
6. 所有查询均为只读，默认不输出敏感业务数据。
7. 每个结论包含直接证据，并明确事实与推断。
8. SQL 中的表、列和状态映射与当前代码、Mapper、Flyway 迁移一致。

## 10. 非目标

- 不建设产品内诊断页面或接口。
- 不建设通用链路追踪、指标平台或日志采集系统。
- 不提供自动修复、重试、状态回写或资源释放能力。
- 不在本次扩展完整业务测试用例矩阵；手册只服务于测试期间的快速定位。
