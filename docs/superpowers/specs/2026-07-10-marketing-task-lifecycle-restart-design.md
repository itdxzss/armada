# 营销任务按计划启动与重新启动设计

## 目标

修正群组营销任务的启动时间语义，并为已按结束时间自动结束的任务提供可配置的重新启动能力。

本次只处理任务生命周期时间，不调整实时查群、好友数量、已排队消息、账号群 joinedAt 或 72 小时上限规则。

## 已确认业务规则

### 普通启动

- 任务始终受 `task_start_at` 和 `task_end_at` 约束，点击“启动”不能提前发送。
- `now < task_start_at` 时，启动操作成功后任务保持 `PENDING`，等待调度器到时启动。
- `task_start_at <= now < task_end_at` 时，启动操作将任务置为 `SENDING`，并允许立即生成下一轮。
- `now >= task_end_at` 时，普通启动失败；已结束任务必须走重新启动流程。
- 新建的未来任务本身已经处于等待状态，即使用户不点击启动，调度器也会在开始时间到达后自动执行。
- 用户提前点击等待任务的启动按钮时，接口幂等返回当前等待状态，前端提示“任务已进入等待，将按计划时间执行”。

### 已停止任务恢复

- `STOPPED` 任务恢复时仍使用原计划时间窗口。
- 当前时间早于原开始时间时，恢复为 `PENDING`。
- 当前时间处于原开始、结束时间之间时，恢复为 `SENDING`。
- 当前时间已经达到原结束时间时，不能普通恢复，必须走重新启动流程。

### 已结束任务重新启动

- `ENDED` 任务使用独立的重新启动接口，普通启动接口不处理 `ENDED`。
- 前端弹窗填写新的任务开始时间和任务结束时间。
- 默认开始时间为当前时间。
- 默认结束时间为“当前时间 + 原任务持续时长”；若原持续时长不可用，则默认 24 小时。
- 用户可以修改默认时间，但必须满足 `taskEndAt > taskStartAt` 且 `taskEndAt > now`。
- 新开始时间在未来时重新进入 `PENDING`；新开始时间已到时进入 `SENDING`。
- `account_group_send_at` 保持任务创建时的固定值，不因重新启动改变。
- 清空 `finished_at`，避免运行中的任务仍携带旧结束标记。
- `started_at` 保留首次实际启动时间，继续表达“首次启动”。
- 任务目标、发送计数、轮次号和历史发送记录继续累计，不清零。

## 后端设计

### 普通启动接口

保留 `POST /api/marketing-tasks/{id}/start`，由服务层根据当前时间与计划窗口决定目标状态：

- 等待窗口：状态保持或恢复为 `PENDING`，`next_round_at` 置空。
- 执行窗口：状态变为 `SENDING`，`next_round_at` 设为当前时间。
- 已过结束时间：返回业务校验错误，提示使用重新启动。

SQL 更新必须同时携带预期原状态，避免并发状态变化导致错误覆盖。

### 重新启动接口

新增 `POST /api/marketing-tasks/{id}/restart`，请求体：

```json
{
  "taskStartAt": 1783650000000,
  "taskEndAt": 1783736400000
}
```

接口只接受当前状态为 `ENDED` 的任务。更新计划时间、状态、`next_round_at` 和 `finished_at`，不更新 `account_group_send_at`、目标、计数或历史记录。

### Worker 防御

`MarketingRoundWorker` 在生成本轮发送前再次校验：

- `now < task_start_at`：不生成 attempt/outbox，并确保任务回到等待调度的状态。
- `now >= task_end_at`：结束任务，不生成 attempt/outbox。

调度 SQL 仍作为第一道时间闸门，Worker 校验作为并发和脏状态兜底。

## 前端设计

- `PENDING`、`STOPPED` 使用现有“启动”操作。
- `ENDED` 显示“重新启动”，点击后打开日期时间弹窗。
- 弹窗默认值按原任务持续时长推导，并复用创建任务的时间合法性规则。
- 普通启动返回 `PENDING` 时显示等待提示；返回 `SENDING` 时显示启动成功。
- 前端校验用于即时反馈，后端保持完整校验作为最终事实源。

## 错误处理

- 普通启动发现结束时间已到：提示“任务计划已结束，请重新设置开始和结束时间”。
- 重新启动非 `ENDED` 任务：提示任务状态已变化，请刷新后重试。
- 开始或结束时间缺失、结束时间不晚于开始时间、结束时间不晚于当前时间：拒绝请求。
- 并发更新未命中：提示任务状态已变化，请刷新后重试。

## 测试范围

### 后端

- 未来 `PENDING` 任务点击启动后仍为等待状态。
- 已到开始时间且未到结束时间的 `PENDING`/`STOPPED` 任务进入发送中。
- 已过结束时间的任务不能普通启动。
- `ENDED` 任务使用新时间重新启动，并保持 `account_group_send_at`、计数和历史数据不变。
- Worker 遇到未来开始时间不生成发送记录和 outbox。
- Mapper SQL 带有状态和计划时间并发守卫。

### 前端

- `ENDED` 行展示重新启动入口。
- 重新启动弹窗按原持续时长生成默认时间。
- 非法时间不会调用接口。
- 合法时间调用 restart API，并刷新任务列表。

## 非目标

- 不取消已经进入 outbox 或 Kafka 的消息。
- 不新增账号占用表或账号释放逻辑。
- 不改变账号群数据读取方式。
- 不改变账号群组发送时间最大追溯 72 小时规则。
- 不修复好友数量或 membership 重新入群时间。
