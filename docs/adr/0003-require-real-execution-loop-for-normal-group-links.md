# ADR-0003：普通群链接版必须形成真实执行闭环

日期：2026-08-02
状态：已接受

## 背景

当前 `POST /api/pull-tasks` 只把前端请求保存为 JSON 配置快照。启动、暂停和停止接口明确返回“执行器尚未接入”，群组明细返回空页；新 HTML 中的看板、任务详情和群组工作台也主要是静态样例。

## 决定

普通群链接版本期必须交付真实执行闭环，不把页面完成或配置落库视为业务完成。

闭环最低包含：

1. 结构化创建与启动前资源复核。
2. 持久化任务、单群、执行角色、料子/目标号码和执行检查点。
3. 通过真实协议账号执行进群、分批拉人以及本任务启用的群资料/权限和退出动作。
4. 保存逐号码/逐批结果、失败原因和任务聚合，不用演示数值填充列表。
5. 支持幂等回调和服务重启后的检查点恢复；第一阶段不开放人工失败重试。
6. 列表、任务详情、单群明细和执行记录可追溯真实状态。
7. 单任务生命周期动作重复校验状态、租户和权限，并记录审计。

## 影响

- 现有不透明 `config_json` 可以保留兼容快照，但不能继续充当唯一生产模型。
- 需要新增普通群链接任务的执行事实和调度状态，不能复用营销统计表冒充。
- 协议原子能力大多已经存在；主要建设量位于 Armada 的资源编排、状态机、幂等、回写和恢复。
- 图片已排除批量暂停/恢复；本期保留任务级与单群暂停、恢复、结束，不开放任务级“重试”或单群“重新执行”。
- 暂停只阻止新协议动作，在途调用允许完成并回写；暂停释放并发槽位和拉手租约但保留选择及检查点。结束不可恢复，取消未发动作并保留历史明细。
- 明确成功或失败的动作均为终态；资源不足通过人工补充后续跑，结果未知通过状态查询或协议回调收敛。需要整体重做时新建任务。
- 允许把闭环拆成多个可独立验收的纵切分阶段实施；每个阶段必须记录真实范围和验证证据。
- 中间阶段可以只覆盖部分链路，但不得用“静态按钮成功”“Mock 明细”填补未实现能力，也不得提前宣称普通群链接版整体完成。
- 第一阶段本身必须可创建并启动一个最小场景任务，执行真实协议拉人并持久化回写结果；不允许把第一阶段定义为纯页面或纯配置保存。
- 并发增强、完整暂停恢复、任务看板和导出可以安排在后续纵切，但必须在页面和文档中明确未接入。

## 被否决方案

只完成前端和配置保存：现状已经具备配置保存，继续增加静态页面无法让用户完成一次拉群任务，也无法验收执行结果。
