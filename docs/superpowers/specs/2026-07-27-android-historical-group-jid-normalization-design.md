# Android 历史群 JID 规范化设计

## 背景

第一套环境的 Zhuan 当前群接口返回裸群 ID，例如 `120363000000000000`；账号导入基线保存完整群 JID，例如 `120363000000000000@g.us`。Armada 当前按字符串精确求交，导致仍在群的 Android 历史群被误判为已退出。

## 方案

只在 Android 当前群响应 Mapper 边界规范化 `group_id`：

- 已包含 `@` 的非空值保持不变。
- 不包含 `@` 的非空值补充 `@g.us`。
- 缺失或空白值继续按现有协议响应异常处理。
- Web 协议、历史群业务服务、数据库基线和 Zhuan 服务均不改动。

Android Mapper 输出统一使用完整群 JID，因此历史群服务现有精确匹配和摘要查询逻辑无需增加协议判断。

## 测试

先增加回归测试，使用第一套环境的真实响应形态：Android `group_id` 为裸 ID，请求中的 baseline JID 带 `@g.us`。测试必须先证明当前实现无法匹配，再实现最小修复，并验证：

- 当前群列表输出完整 `@g.us` JID。
- metadata 摘要能够命中同一个完整 baseline JID。
- 已经是完整 JID 的响应保持不变。
- 缺失 `group_id` 的既有异常行为不变。

## 范围与交付

本次只修改 Android Mapper 及其单元测试；不部署、不修改远程数据、不提交 commit，并保留工作区其他在途改动。
