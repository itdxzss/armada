# 普通拉群管理员自动换号

用户要求：管理员触达受限、离线、封禁等不可用时，继续从任务选定的管理员分组取号。仅在主仓库修改，不部署。

## 行为

首次随机选管理员、已选管理员执行前复核、资源等待恢复共用管理员资格：租户内未删除，在线，生命周期正常/被抢登/抢登中，协议明确为 WEB/ANDROID 且身份完整，无风险或操作限制。在线本身不足以证明可执行管理员操作；这里不沿用“消息受限仍可拉人”的拉手资格。

没有可用管理员时，恢复事务只从冻结配置 manager_group_id 选本执行行尚未使用的健康账号。替补失败后继续选下一个；分组耗尽则保留等待，新增健康候选后下一轮恢复。已失败或已移出的本行账号不自动重复尝试；保留失败记录，不删除账号、不触发账号上线。

替换使用现有角色记录：旧角色 availability=REMOVED，新角色 source=SUPPLEMENT、selection=AUTOMATIC、entry=JOIN_BY_LINK、role_seq 递增。首次资源恢复没有历史角色时 source=INITIAL。恢复需重新竞争原任务的并发名额；等名额时复用已选替补。角色写入和执行行 CAS 失败时整体回滚。

自动替补走正常持久化 outbox 入群、入群回执、管理员提权、联系人和后续拉人链路。人工补充处理器只接管有效的人工补充记录，避免历史人工记录截住自动替补。已移出管理员的迟到入群/提权回执不推进执行行。

账号仍健康但结果 UNKNOWN、等待审批，继续原有结果核实/审批流程；不是把未确认当明确失败。缺少在线的我方群主/管理员来执行提权时，仍等待提权执行人，不盲目替换健康目标账号。暂停和结束的父任务不自动恢复。

## 影响和验证边界

后端 account 与 task 两域，通过账号域 Service 访问资格；无 API、前端、表结构、Redis 或协议层契约变化。账号查询和角色/执行行写入沿用租户插件、真实 MyBatis Mapper 和事务。

覆盖 H2 资格/租户隔离、失败保留、多个检查点换号、连续失败、耗尽后恢复、并发等待、暂停、失效租约回滚、迟到回执、自动/人工补充分流。Web、Android、混合协议的本地端到端测试验证替换后完成入群、提权、拉人、料子管理员及父任务收口；协议外部响应由测试替身提供，不等同真实 WhatsApp 业务验收。

回滚只撤销本次源码补丁；无数据库迁移。任务未部署、未恢复第二套已结束任务。
