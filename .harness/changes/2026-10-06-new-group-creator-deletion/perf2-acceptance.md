# 第二套环境（perf2）真实业务验收步骤

本文件是待部署后的操作步骤。本次没有执行其中的部署、真库访问、发送、建群或注销。

## 准备与部署验收

1. 明确目标是 Armada 第二套环境 perf2，核对各协议节点归属、版本、Redis 命名空间与持久化设置。不要在共享主机上操作 Athena/WB Pro 服务。
2. 先部署带严格证明接口的 Android 与 Web 协议，再部署后端（运行 Flyway V211、V212），最后前端。服务端密钥通过现有密钥渠道分别注入，禁止复制到前端、任务参数、工单和日志。确认正常 API key 鉴权依旧生效。
3. 核对 Flyway 校验和、规范化身份索引存在、两个账本唯一索引存在；服务重启后协议删除记录仍可读取。以上是部署核查，不是业务验收。
4. 由业务人员明确批准少量专用测试账号用于永久注销，记录 tenantId/accountId 和哈希；确认账号无其他任务、角色或业务依赖。准备独立接管管理账号和少量可控测试成员。不得从现有生产账号池临时挑号试删。

## 关闭兼容

- 打开新任务，新开关默认关闭；群链接模式不展示。保存关闭草稿、刷新、查看详情，值始终关闭。
- 用关闭开关的新群任务及一条存量任务走原流程，确认没有注销账本、没有 delete POST，原 creatorLeaveAfterPull 单群退群语义保持不变。
- 用 NEW_GROUP 开启开关保存草稿，刷新回显；提交为待开始任务后在详情修改，再启动。首次启动后任何页面或 API 修改都应返回拒绝，暂停/恢复后也不得编辑。

## 单行完整验收

分别使用 Android 管理号与 Web 管理号各验一条，经明确批准的建群账号都是 Android 主设备：

1. 创建仅一个执行行的 NEW_GROUP 任务，开启开关，资料设置保持 enabled + BEFORE_PULL。使用少量中性测试成员。
2. 在建群前读取 `account_creator_deletion` 和 `pull_task_creator_deletion`，确认两个记录的 tenant/task/execution/creator 身份一致，账号唯一占用、建群 operationId 和注销 operationId 已冻结。
3. 保存群 JID、邀请链接、群资料验证命令及成功回读证据。管理号作为初始成员已在群时应直接继续提权，无重复入群请求。
4. 在 MANAGER_ADMIN 后确认管理号新发群查询，实际仍在线、在群且为管理员，创建者身份与建群时冻结身份匹配；仅数据库 SUCCESS 或提权响应不能放行。
5. 观察阶段 11 → 12。每个账号的删除 IQ 只出现一次；结果 operationId、accountHash、iqId、responseType=result 与业务账本对应。ACCEPTED 但群 Creator/CreatorPN 仍存在时，执行行显示等待创建者清理，不能出现拉人命令。
6. 等待新鲜查询明确号码未注册、原建群者已不在成员、Creator/CreatorPN 为空、Creation 与删除前一致、管理号仍是管理员。保存源 LIVE_IQ 证明及时间；只有这时账本 COMPLETE，并进入 MANAGER_PULLER_CONTACT。
7. 验证随后联系人、邀请拉手和受控拉人实际完成；保存成员查询及逐号码结果。HTTP 200、页面完成、任务状态本身不能代替真实入群证据。
8. 确认账号生命周期 DELETED、离线意图、占用释放和历史关系保留；尝试普通选号/恢复时不能重用、重连，末尾不能再给原建群账号发旧退群命令。

## 阻断与恢复验收

优先在本地测试或协议故障注入环境演练；真实环境只使用已批准的小范围测试任务：

- 开启任务选择 Web/iOS/非主设备建群账号，应在校验或选号处阻断，删除请求计数为零。
- 管理员提权未确认、管理号离线、管理号被替换、群异常、冻结身份变化时不得注销，原因可读。
- 两个执行行/任务争用同一号码（包括两个后台账号别名）只能有一个预留者；有其他活动业务依赖时不得删号。
- 在“保存发送意图”之后注入请求超时、进程重启、重复调度，恢复后仅 GET 原 operationId。UNKNOWN 应立即暂停；查不到记录不能自行换 ID 再 POST。
- ACCEPTED 后停止任务，不应再出现新删除或其他业务派发；恢复只能继续同一账本对账。停止前已发送的在途请求可能返回，须保留该证据。
- 创建者未清理、注册状态未知、缺少 CreatorPN/Creation、响应结构异常均不得拉人；超过窗口暂停且显示原因。恢复后仍保留原 operationId。
- 其他租户尝试读写配置或使用不匹配 task/tenant/account 签名必须拒绝；签名只在服务端出现。

## 验收结论格式

分别记录“部署成功”“迁移完成”“本地测试”“真实注销已接受”“实时创建者清理确认”“实际拉人成功”。每条结论附 tenant/task/execution/accountId（或哈希）、operationId、时间与证据路径。不得记录密钥、完整手机号或邀请链接。

实验证据只支持协议创建者信息延后清理；不承诺所有客户端或既有欢迎卡立即隐藏创建者。不要把界面缓存显示作为删号成功或失败的唯一依据。
