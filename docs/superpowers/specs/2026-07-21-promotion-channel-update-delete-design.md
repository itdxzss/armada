# 渠道编辑与删除接口设计

## 目标

在现有渠道新增、分页实现上补充编辑和单条删除能力，完整复用已有模板、国家、域名、推广平台和 Token 安全规则，不修改公共响应、分页、租户或异常组件。

## 已确认范围

- 主题色由前端控制，本次不作为接口字段、不落库、不修改表结构。
- 编辑接口为 `PUT /api/promotion-channels/{id}`，成功返回统一空响应；页面保存成功后刷新分页列表。
- 删除接口为 `DELETE /api/promotion-channels/{id}`，执行软删除并返回统一空响应。
- 不增加编辑详情接口；前端沿用分页行和当前表单默认值组装编辑请求。
- 不新增 Flyway 迁移，不增加 revision、is_active 或操作日志表。

## 编辑业务规则

1. 路径 ID 必须为正整数，且渠道必须属于当前租户、未软删除。
2. 渠道名称、归属用户、目标国家、模板、访问域名、预选区号、推广平台、应用内打开、参加营销和状态允许修改。
3. 渠道码、创建人、创建时间保持不变；当前阶段 `updated_by` 继续使用表单中的归属用户 ID。
4. 模板、目标国家、预选区号继续调用现有模板 Mapper 和 `CountryService` 校验。
5. 域名先执行现有规范化；编辑到新域名时复用或创建对应域名记录，不直接修改原域名行，避免影响共享该域名的其他渠道。
6. 同一域名已绑定其他模板时拒绝编辑，保持现有“域名只能绑定一个模板”规则。
7. Facebook/TikTok 支持追踪配置；Access Token 非空时重新加密并替换。仅当平台、追踪 ID 均未变化且旧密文完整时，空 Token 才表示保留原值；平台或追踪 ID 变化时必须提供新 Token，清空追踪 ID 时清除旧凭据。响应始终不回显 Token。
8. 切换到快手/MGSKY Ads 时软删除当前追踪配置；以后切回支持 CAPI 的平台时复活原配置行，避免唯一键冲突。
9. 更新渠道主表影响行数不是 1 时抛 `NOT_FOUND`，整个事务回滚。

## 删除业务规则

1. 删除采用 `deleted_at` 软删除，不执行物理 `DELETE`。
2. 编辑和删除都先锁定并更新渠道主记录，再处理追踪配置，统一 InnoDB 加锁顺序；任一步失败时事务整体回滚。
3. 域名可能被其他渠道共享，因此不删除 `promotion_domain`。
4. 历史账号可能持有 `promotion_channel_id` 和渠道名称快照，因此不级联修改账号数据。
5. 已删除或不存在的渠道返回 `NOT_FOUND`，避免前端把重复删除误认为成功。

## 数据与安全

- 所有 SQL 继续由 MyBatis 租户拦截器注入 `tenant_id` 条件。
- 更新 SQL 不读取或记录 Access Token 明文。
- Token 密文字段只有请求提供新 Token 时才更新；仅平台、追踪 ID 均未变化且旧密文完整时，空 Token 才保留原值。
- 分页 SQL 保持不变，`deleted_at IS NULL` 会自动排除已删除渠道。

## 验证

- Controller 测试锁定 PUT/DELETE 路由、请求绑定和统一响应。
- Service 测试锁定域名复用、Token 替换/保留、非 CAPI 配置软删、渠道不存在和删除事务调用。
- Mapper SQL 合同测试锁定软删除、租户友好条件、Token 动态更新和禁止物理删除。
- 运行渠道定向 Maven 测试和编译；真库 DbTest 仅在本地测试库配置可用时执行。
