# 拉群数据包：模型选择与菜单复刻验收范围

- 日期：2026-09-15。
- 状态：用户已确认采用四张表，并要求避免过度设计；本地代码已实现，相关验收见 `group-pull-data-package-implementation.md`；未部署。
- 用户要求：优先普通版竞品，先做拉群数据包，说明是否新增模型，以及本菜单复刻到什么程度。
- 已确认决策：四张表、避免过度设计，以及点击趋势后续接入。下文“当前事实”保留设计时点背景，实现结果以实施记录为准。

## 1. 结论

采用独立的拉群数据包聚合，资源部分固定为四张表；复用现有导入、导出、分页、国家识别、权限和任务执行的实现经验与可用公共组件。
现有超链数据包的发送状态、领取任务及清理逻辑继续属于超链业务。拉群任务的协议执行结果继续由现有任务成员和尝试记录保存。

复刻目标按可见菜单逐项验收：筛选、列结构、组合指标、按钮位置、弹窗、禁用条件、导入导出及任务回写都要覆盖。
用户在实施中明确选择：本次完成数据包菜单及拉群取用、回写闭环，点击/访问趋势后续接入。历史隐私过滤仍在本次范围内。
点击功能保留在竞品对照清单中注明延期；不增加预留PV/UV列，不提供固定空图或常量点击数。
功能可以分步骤实施，最终验收清单不随实施步骤静默缩水。

### 用户确认的实现约束：避免过度设计

- **四表各司其职**：包信息、号码、导入批次、当前统计；执行记录沿用现有拉群表。
- **字段必须立即有用途**：逐列写清当前哪个接口或执行流程写入、哪个页面或流程读取。能够从已有事实简单计算的展示值不重复存储；不预留渠道、插件、策略或未来业务字段。
- **沿用现有分层**：Controller → Service → Mapper；按实际职责拆方法，不建设通用数据包框架、策略注册器、工作流引擎或新的消息链路。
- **先用现有事务完成一致性**：号码状态和统计一起更新；仅保留防止并发重复领取、重复回写所需的条件更新和来源引用。版本覆盖用于保护已冻结任务，不扩展为历史版本管理产品。
- **后台任务按实际需要增加**：首版不提前建设独立对账调度器、自动归档平台或异步导入作业系统；保留可重算的SQL和测试即可。后续遇到明确容量或一致性问题再针对性处理。
- **菜单验收仍按清单执行**：简化放在实现结构；权限、失败回滚、UNKNOWN保护、A/a标记和真实结果回写仍是基础正确性要求。

## 2. 当前事实与上次问题

1. 当前存在真实超链数据包：`data_package`、`data_package_phone`、`data_package_import`、`data_package_stat`。
   其状态是未使用、领取、单钩、送达、可重试失败、未注册；领取字段为 `claimed_by_hyperlink_task_id`。
2. 当前拉群成员 `pull_task_material_member` 归属执行行，草稿删除会删除成员，不能直接承担可重复选择、独立管理的数据包。
3. 当前标准拉群正式入口使用 TXT 文件计划；隐藏整合创建页虽然有数据包字段，但没有候选数据，最终提交仍是接口未确认提示。
4. 既有纠偏设计明确记载了此前验收问题：交付资源子集、表格列不一致、按钮未实现；组合列曾被拆成普通统计列。
5. 当前超链数据包的访问趋势仍是汇总值与固定空态，没有真实时间趋势请求。不能直接复制该实现来通过本次验收。
6. 竞品包只有前端构建产物。可证明页面、参数、前端判断；不能证明其表结构、事务、并发领取或结果可靠性。

## 3. 模型取舍

| 方案 | 影响 | 建议 |
|---|---|---|
| 直接复用现有拉群成员表作为数据包 | 成员依附执行行，草稿清理和换群重试都会操作该表；独立资源生命周期无法表达 | 不采用 |
| 给超链四表增加拉群状态和领取字段 | 需要修改超链领取、回执、统计、导入与清理；同一状态列混入发送和入群语义 | 本次不采用 |
| 新增拉群数据包聚合，连接既有任务成员事实 | 资源生命周期与执行生命周期各自清晰；改动可控制在新菜单及拉群接入点 | 推荐 |

同一个手机号在两个业务包中代表两份独立的资源使用事实，不表示复制同一条协议执行事实。
本次不顺带把两个业务重构成全站通用名单平台。

### 已确认四表

| 表 | 聚合归属及必要性 | 最小事实与主要读写方 |
|---|---|---|
| `group_data_package` | 拉群资源包；现有表没有拉群资源的独立生命周期 | 名称、备注、当前版本、创建/删除审计、乐观锁；列表、编辑、覆盖导入、任务选包读取 |
| `group_data_package_phone` | 包内某版本的号码及当前分配状态 | 规范号码、国家、导入批次、原始行号、稳定顺序、A/a管理员标记；当前分配任务/逻辑执行单元/分配版本；号码详情、领取、结果回写和导出读写 |
| `group_data_package_import` | 每次文件导入的审计 | 原文件名、追加/覆盖、版本、原始/有效/重复/错误/隐私过滤数、操作人、完成状态；导入前独立记录，成功或失败可追溯 |
| `group_data_package_stat` | 当前包版本的列表统计投影 | 未使用、占用、入群成功、明确失败、待确认及失败原因子类统计；导入、分配、释放、结果、重置实际写入，列表读取；可从事实重算 |

第四张表有明确的列表查询和状态更新用途，避免每次翻页扫描十万或五十万号码。统计是可重算的投影，不是第二份独立结果真值。
不新增第二套任务、协议尝试或执行日志表。需要追溯时沿现有任务成员、执行行和尝试记录查询。

租户级四表均有 `tenant_id`。可见范围遵循当前资源菜单的租户和权限合同；创建人用于审计，不能把它冒充已实现的用户数据权限。
查询、导出、重置和任务选包均重新校验包属于当前租户并有相应权限，不接受客户端传入租户作为权威。

### 与当前拉群关联

- 在现有任务料子快照中增加来源包号码与分配版本引用；具体列名、索引和迁移编号在实现前按最新代码核定。
- 同一份料子的逻辑身份按任务及稳定执行单元识别。换群产生的新执行行沿用来源引用和分配版本，不能再次扣用数据包。
- 包负责“现在能否再次分配”，任务成员与尝试记录负责“当时实际发生了什么”。旧任务的成功与失败不被重置按钮改写。
- 追加不改变已领取内容；覆盖写新版本，历史任务保留冻结的号码、顺序、管理员标记及来源快照。
- `UNKNOWN`/已提交未确认不能自动回到未使用；只有确认没有外部执行的占用才可归还。
- 结果回写须匹配分配版本、逻辑执行单元及有效尝试，重复/过期回调不重复计数。换群重试也不能因旧执行行回调而覆盖新结果。
- 料子导出保留管理员标记和稳定顺序。沿用现有“料子执行单元与可替换群资源分开”的规则，不能仅为了套竞品一个包的字段而把多份料子默默混成一份。

## 5. 明确列出的业务适配

这些差异必须在实现验收表中明示，不能作为遗漏偷偷处理。

1. **隐私拒绝不叫未注册。** 竞品“未开通”实际包含隐私403，属于失败子集。我们写“隐私拒绝”，真实未注册另按可靠结果分类。
2. **状态不重复相加。** 未使用/占用/成功/失败/待确认组成互斥资源状态；“已使用”和失败子类按定义派生。显示层解释分母，不把失败和已使用当独立分区再累计。
3. **保留现有料子语义。** 7–15位规范号码与A/a、格式清洗、原文件顺序继续有效；竞品6–20位纯数字规则不能直接替换当前拉群合同。
4. **国家禁导不能照搬。** 竞品硬编码美/加/中/港/澳/台/马/新；当前标准拉群没有这份禁导合同。本次不因复制组件引入这些限制。
5. **导出门槛明确适配。** 竞品要求包被任务用过才能导出；我们的建议是有导出权限即可导出已导入内容，不制造只能导入不能取回的商业门槛。
6. **消费业务名称来自我们实际接入点。** 未实现炸群/拉粉/剧本取号时，不把这些词做成虚构消费记录；只有真正接入后才产生对应事实。
7. **点击率只是定义明确的比率。** 竞品为UV/成功入群数，可超过100%；未做号码级归因不能称为“这些号码的真实转化率”。
8. **修正竞品前端缺陷。** 竞品名称在当前页过滤、摘要只算当前页、“随机预览”实际前5条；我们使用真实全量名称筛选，摘要与预览文案如实说明范围。

## 6. 实施顺序与完成边界

1. 资源模型及接口：四表、版本覆盖、导入审计、真实筛选/分页/统计、详情、状态导出与安全重置。
2. 菜单与全部弹窗：按上表逐项对照，先用受控本地测试数据验证真实接口和下载。
3. 正式标准拉群接入：来源选择和可审查分配计划；原料子执行单元不变，任务占用和回写加入相同事务边界。
4. 历史隐私筛选：使用可核实的拉群拒绝历史；点击归因与趋势按用户选择延期。
5. 浏览器逐项验收与端到端验证，记录完成、偏差、依赖和实测证据。

本次完成口径为“数据包管理及标准拉群消费闭环完成，点击趋势按用户选择延期”；不声称竞品含点击功能的菜单全部复刻完成。
特别是访问趋势不能只在数据包四表中增加没有写入方的PV/UV列；需要群任务消息链路实际记录来源，表和接口按具体事实另行论证。
隐藏整合创建页、旧建群营销、剧本/拉粉任务的全面重做不应被顺带承诺为本数据包菜单已经完成。
