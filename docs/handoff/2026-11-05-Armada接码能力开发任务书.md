日期：2026-11-05。文档状态：待实施任务书；本文不执行真实查询、购号、发码、数据库迁移或部署。

## 1. 目标与交付边界

在 Armada 提供可审计、可恢复的接码资源能力：查询平台目录与报价，在明确预算内购买号码，维护短信订单状态，获取 OTP，并向有权限的调用方交付号码和 OTP。

本任务的业务对象是接码订单、供应商操作记录和交付记录。调用方如何使用号码及 OTP，不属于接码订单状态机。

交付范围包括：

- 服务及国家目录、价格档位、库存与商家筛选。
- 预算校验、幂等创建、采购意图持久化、供应商订单绑定。
- 定时或显式刷新短信状态，区分等待、新码、旧码、取消与结果不明。
- 受控号码交付、有限有效期 OTP 交付、稳定事件 ID 与交付确认。
- 显式取消、完成、到期处理，以及采购和订单修改结果不明的对账入口。
- 本地离线测试、迁移定义、运维开关、脱敏审计和开发结果记录。

本任务不把“号码已购买”“OTP 已收到”“调用方已确认收件”解释成号码使用方的业务成功。
不得通过本任务创建自动充值、无限补买、无限重发或任意供应商地址调用能力。

## 4. 目录、报价与采购输入

1. 通过目录取得服务代码；WhatsApp 的当前代码不得仅凭历史记录写死为 `wa`。
2. `country` 使用供应商国家目录 ID，不从电话区号或地区显示名直接推导。
3. `providerId` 为供应商商家 ID；指定商家后不得静默换成其他商家。
4. 明确接码能力允许的国家范围。现有上层服务只展示美国渠道，扩展范围需要显式设计与测试，不能误当已有全国家支持。
5. 报价输出包含服务、国家、单价、库存、可选商家、获取时间及有效性说明；不宣称锁价或预留库存。
6. 档位总库存与某商家库存分别表达；不能因档位库存足够且商家出现过，就保证该商家能满足整批数量。
7. 价格和余额使用 `BigDecimal`；原接口未返回币种时明确标为未提供，不自动标成美元或进行隐式换算。
8. 采购输入必须明确最高单价、数量上限、总预算上限、采购截止时间，以及精确档位或价格上限策略。
9. 预算单位必须与该供应商账户计价口径一致；币种配置未确认或与购号响应冲突时停止新增采购并保留核对状态。
10. 购买响应保存 `activationCost` 和 `currency`。实际成本违反选定策略时不得视作正常完成，也不能先记退款再等待取消。

现有手动商家采购只传最高价和商家，而自动商家采购使用等额最低价/最高价；价格偏离后的取消行为见 [AccountRegistrationWorker.java:169](../../armada-api/src/main/java/com/armada/account/service/impl/AccountRegistrationWorker.java#L169)。
开发时必须在 DTO、界面文案或内部调用合同中明确所选价格策略，不能依赖调用者猜测旧分支。

## 5. 目标接口语义

下表是**待开发的目标设计**，不是当前已经可调用的 HTTP 端点。
可在正确业务域新增专门的接码资源 API，也可由有权限的内部 Service 提供同等能力；进入实现前确定一种正式接入方式。
如提供 HTTP 接入，采用项目现有鉴权、DTO/VO、响应信封、错误码及路径命名规范。

| 能力 | 输入 | 输出与约束 |
|---|---|---|
| 查询目录与报价 | 服务选择、国家、商家筛选 | 目录和报价快照；不产生订单或预算占用 |
| 创建接码订单 | 幂等键、报价条件、数量/金额上限、截止时间、`callerReference` | 内部订单 ID、当前状态、已预留预算；返回受理不等于已购得号码 |
| 查询订单 | 内部订单 ID | 本地持久化状态、成本、脱敏号码、交付状态；查询不得隐式购买或重发 |
| 获取号码交付 | 内部订单 ID、交付游标或事件 ID | 受控号码事件、稳定事件 ID、创建时间、归属与版本 |
| 获取 OTP 交付 | 内部订单 ID、交付游标或事件 ID | 有效期内的 OTP 事件、稳定事件 ID、`expiresAt`；列表和普通详情不输出明文 OTP |
| 确认交付 | 交付事件 ID、调用方身份 | 幂等 ACK；只确认调用方收到该事件 |
| 更新供应商订单 | 内部订单 ID、操作幂等键、就绪/取消/完成指令 | 本地操作记录与已确认/待核对结果；不接受任意裸供应商订单 ID |
| 查询与处理对账项 | 内部订单或操作 ID、受控核对依据 | 结果不明原因、核对记录和明确后续动作，不自动补买 |

- `tenantId`、操作者和调用方身份来自可信鉴权上下文，不采信请求体自行声明的归属。
- `callerReference` 是有长度与字符限制的不透明关联引用；不能决定租户权限，也不能暗示号码使用方处理成功。
- 内部订单 ID、供应商 activation ID、交付事件 ID 和调用方关联引用分别建模，不共用一个泛化 ID。
- 普通租户不得直接传任意 activation ID 查询或变更平台账户中的其他订单。
- 同一幂等键、同一作用域与相同输入返回同一订单；不同输入复用该键必须明确冲突。
- 供应商状态变更同样保存操作键与请求指纹；同键同参重放原结果，变参冲突。同一订单的就绪、取消、完成等变更通过数据库约束串行受理。
- ACK 丢失后允许调用方重新获取并确认同一交付事件；不能因 ACK 丢失再购号码或再次调用供应商修改操作。
- 如增加推送交付，只使用服务端配置的接收方 ID 和地址白名单；调用方不能提交任意 callback URL。
- 完成订单由调用方明确请求或预先约定且可审计的短信订单规则触发；交付 ACK 本身不等于供应商完成 ACK。

## 6. 数据归属与持久化设计

先完成聚合设计说明，再决定复用现有表、抽取可复用部件或新增接码聚合；本文不预设加列名单或指定复用某张旧表。
设计说明必须回答：每项事实归属哪个聚合、为何需要保存、现有字段为何不足、是否造成同一事实两处维护，以及旧任务如何继续运行。

需要承载的事实包括：

- 订单归属：租户、操作者、授权调用方、内部 ID、幂等键、输入指纹、关联引用。
- 采购约束：供应商账户引用、服务/国家/商家、报价策略、数量和金额上限、预留额度、截止时间。
- 供应商事实：activation ID、号码、实际成本与币种、供应商状态、原始时间文本及观测时间。
- 操作事实：操作类型、稳定操作 ID、意图提交时间、结果分类、尝试次数、待核对原因与恢复依据。
- 交付事实：稳定事件 ID、事件种类、收码轮次、加密载荷引用、创建/失效时间、ACK 时间与调用方。
- 调度事实：版本、租约、下次查询时间、有限重试计数和终止条件。

OTP 不进入长期明文订单字段、普通日志、异常正文或审计内容；审计只保留必要的非敏感事件信息。
需要跨重启重放交付时，短期载荷采用注入密钥的认证加密并绑定租户、订单和事件；设置有限 TTL，失效后清除载荷，备份与清理策略同样纳入设计。
重复收码识别若需保存指纹，应使用受控密钥的摘要方案，不能以可离线穷举的裸 OTP 哈希替代保护。
凭据只由服务端受控配置取得；平台 API 密钥不写入业务 DTO、交付事件或表的普通配置字段。

数据变更只能通过 Flyway；核对迁移版本冲突，准备回滚说明，按规范刷新生成的数据模型文档。
租户表执行真实 MySQL/MyBatis 持久化；租户拦截器、操作者权限、调用方权限均应有可运行测试。
跨租户管理核对仅走受权管理入口，按照项目要求声明豁免原因，不向普通调用方暴露平台活动订单清单。

## 7. 状态、预算与故障恢复

订单状态与交付状态分别维护，名称在实现时收敛为领域枚举，不混入号码使用方的业务阶段。

| 状态轴 | 建议语义 | 关键约束 |
|---|---|---|
| 采购 | 待采购、采购中、已购得、明确失败、结果不明 | 采购前持久化意图；结果不明不能回到可自动采购状态 |
| 短信订单 | 等待短信、已收码、取消中、完成中、已取消、已完成、已到期、待核对 | 供应商确认与本地请求分开；超时不虚构供应商终态 |
| 交付 | 待交付、可重放、已确认、已失效 | 同一事件稳定重放，ACK 幂等；TTL 不因重放而延长 |

- 外部 HTTP 置于短数据库事务之外；使用“原子记录意图 → 调用 → 原子记录结果”的边界。
- 采购预算使用数据库约束、行锁或比较更新原子预留；多个节点不能靠进程内计数突破额度。
- 本地幂等只保证不重复受理同一业务意图；供应商没有对应幂等键时，不宣称严格一次采购。
- 采购调用后断连、进程退出、解析失败或结果保存失败，均保留潜在消费与预算占用，不自动释放后补买。
- 明确 `NO_NUMBERS` 可按经过批准的有限次数及间隔重试；`NO_BALANCE`、配置禁用、输入错误不得形成忙循环。
- 所有重试仍受截止时间、尝试上限和预算约束；取消申请、租约失效和节点重启后须再次判断能否继续。
- 查询采用有界频率、退避和总期限；`WAIT_RETRY` 保留旧码，`WAIT_RESEND` 不触发目标服务重发。
- 默认只交付本订单已确认的新 OTP；扩展再次收码必须明确供应商能力、轮次和显式操作许可。
- 同一订单同一轮次重复观察到相同 OTP，复用原事件 ID；没有供应商消息 ID 时，不宣称能区分两条同码短信。
- TTL 到期后不重新创建同一 OTP 的新事件，也不通过重复轮询延长其可交付期限。
- 取消/完成的传输失败或非匹配 ACK 进入待核对；不能仅凭调用结束就认定成功、退款到账或预算恢复。
- 存在在途或结果未知的状态变更时，新操作键不能触发重复或相矛盾的 setStatus；先核对原操作结果，再判断是否允许后续变更。
- 已知 activation ID 的恢复先查询该订单；未知 activation ID 的采购保留待核对，禁止随意归属活动列表新增项。
- 若新增 active activations 查询，仅作受控对账证据。明确匹配依据、并发限制与人工裁决路径，不把列表差集作为可靠幂等机制。
- 停购需阻止新的采购意图；已有订单的查询与授权清理另行说明。不能把关闭开关解释成撤销已发出的供应商请求。
- 新接码订单必须由明确的查询条件和调度入口识别；测试证明旧 `AccountRegistrationWorker` 不会领取或推进这些订单。

## 10. 真实 API 验收与完成标准

真实 API 验收单独记录。执行前必须明确目标环境、受控供应商账户、服务/国家/商家、数量、单价与总额上限、允许操作、截止时间和在途订单处理人。
输入未明确前不调用真实供应商 API、不采购、不运行真库迁移、不部署；离线实现与检查可以完成并如实交付。

获得具体范围后，真实验收分别报告：目录/报价查询结果、采购受理、成本与币种保存、号码交付、收到 OTP、OTP 交付及 ACK、订单取消或完成的供应商确认、未知结果核对情况。
未收到短信、供应商无库存或返回挑战性状态时，记录实际结果；不得通过自动补买扩张数量或预算，也不得用替身结果填补真实验收。

本地开发完成必须同时满足：

- 有可调用的接码 Service 或经鉴权的目标 API、真实持久化与明确调度归属，不只提交接口声明或测试假实现。
- 目录/报价、预算购号、状态查询、号码与 OTP 交付、取消/完成、未知结果恢复均有实现及离线验证。
- 幂等与预算约束由数据库落实；恢复、交付重放和租户隔离的关键失败路径已验证。
- OTP 有限 TTL、加密保护、过期清理和日志脱敏已落地，密钥没有运行默认值或硬编码值。
- 新订单不会被旧调度接管；既有接口与历史订单兼容性有实际测试证据。
- 提供文件清单、迁移与回滚说明、配置开关、实际检查结果，以及未验证项；未做真实验收时明确标记“真实 API 验收未执行”。

接码能力验收止于供应商订单管理及向授权调用方交付号码和 OTP，不以调用方后续处理结果作为完成标准。
