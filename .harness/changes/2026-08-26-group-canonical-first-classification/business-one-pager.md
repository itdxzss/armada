# 业务一页纸：一个群只有一个首次分类

## 当前问题

现在群分类实际跟着账号走。同一个群对先导入的 A 账号可能是“上控后群”，对后来导入的 B 账号又是“历史群”，于是群列表同时显示两类。运营看到的是一个群，却必须理解多个账号的历史，筛选和后续业务都没有唯一答案。

## 推荐改变

把分类固定在群上：一个群第一次被可靠的账号控制事实识别时，只能定为“历史群”或“上控后群”之一，以后任何其他账号加入、上线、退出、重连或消息重放都不改变它。

- 第一次来自账号首次完整群清单：历史群。
- 第一次来自账号已经上控后的可靠进群/新增群事实：上控后群。
- 仅导入链接或查看群资料：暂不分类。
- 同一个群在页面上最多显示一枚分类标签。

## 推荐第一纵切

1. 先把后端最终事实放到租户内唯一群身份上。
2. 用原子首次写保证多账号并发也只成功一次。
3. 旧双分类数据先出 dry-run 报告，再按可证明的最早事实迁移；证据不足时保守按历史群处理。
4. API 过渡一个发布窗口，页面本期移除“双分类”。
5. 本地测试通过后，在明确授权的 test1 用 Runner 跑 quick、业务 canary 和 60 分钟观察。

## 本期不做

- 不删除账号自己的首次 baseline 与成员关系。
- 不改变“历史群管理”页面的账号维度含义。
- 不修改 WhatsApp 协议的连接和收群机制。
- 不把链接导入误认为账号已经上控该群。
- 不在未授权时部署、跑真库迁移、操作真实账号或改 IAM。

## 成功信号

- 新数据中双分类数量恒为 0。
- A/B 账号无论随后怎样观察，群的首次分类不漂移。
- 重放、重连和并发不会重复分类或重复副作用。
- 历史迁移每一类都有计数，歧义记录可追溯。
- 群列表只显示一个分类且筛选结果与后端一致。
