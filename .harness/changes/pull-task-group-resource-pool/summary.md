# 变更记录：拉人任务群组资源池

- 日期 / 分支：2026-08-22 / `1.0.3-snapshot`
- 状态：开发验证完成，待部署

## 变更概述

保留普通拉人任务原 `PASTED_LINK` 群链接流程，新增独立 `RESOURCE_POOL` 模式。任务执行时从创建时选择的自定义群组分组动态领取群组；成功转入“已使用群组”，群封禁转入未分组并为原 TXT 新建一次从头执行记录。

## 影响模块

- 群组分组：系统“已使用群组”、移动和删除保护、可用群查询。
- 普通拉人任务：创建模式、运行时取群、等待群资源、手工继续、成功及封禁流转。
- 执行明细：同一 TXT 的 `attempt_no` 重试记录及最新尝试聚合。

## 数据库变更

- `group_folder.system_builtin`：标识不可改名、不可删除的系统分组。
- `pull_task_group_execution.attempt_no`：支持群封禁后保留失败记录并新建执行记录。
- 调整执行行唯一键；活动占用键优先使用群 JID，保留旧群链接模式按链接占用的行为。

## API 变更

- 创建模式新增 `RESOURCE_POOL`。
- 普通任务状态新增 `WAIT_GROUP_RESOURCE`，可调用原继续接口恢复执行。
- 草稿计划接口接收创建模式；资源池模式只生成 TXT 执行行。

## Redis 变更

- 无。未新增 Redis 锁、锁表或后台自动唤醒机制。

## 关键约束

- 全局占用由数据库活动执行行唯一键兜底；冲突方放弃本次领取并由后续调度重试。
- 被占用群组不可手工移动；运行中的资源池分组不可删除。
- 仅处理已确认的群封禁状态；其他异常不扩展为自动换群。
- 新补入分组的群在用户点击继续后参与后续动态领取。

## 回滚方案

- 应用回滚到上一版本后停止使用 `RESOURCE_POOL` 创建新任务。
- 数据库新增列和扩展后的唯一键可保留，不影响存量 `PASTED_LINK` 任务；不执行破坏性降级迁移。
