# 账号勾选导出与控端移除：需求分析

日期：2026-09-18。状态：已在主仓库实现，未提交、未部署。以下原分析保留作为背景，最终实施口径见本节。

## 最终实施口径（用户后续澄清优先）

- 业务人员自行批量离线。导出按钮和后端只检查 `login_state=OFFLINE`，绝不发送下线或解绑命令，也不强制要求某种下线来源标记。
- “批量操作 → 导出账号并移除”，仅处理明确勾选 ID；表头全选为当前页。空选不导出，最多 500 个账号，原始材料总量最多 4MB。
- 以原始导入材料生成五段/六段、Android/iOS 全参、JSON 分文件 ZIP。导出当前运行时最新凭据不在本次实现范围；不承诺账号跨控端登录成功。
- 文件先持久化，再将账号标记为导出预占。下载不删号；客户端完整接收并触发保存后才提交移除。HTTP 环境校验 ZIP 标识和字节数，HTTPS 环境再验证 SHA-256。该回执不代表操作系统最终落盘。
- 移除为账号、运行凭据软删除，保留导入原文及历史记录；导出文件保留 24 小时，后台每分钟有界清理。未交付作业可取消；到期自动取消并恢复原业务状态，不自动上线。
- 不在账号/分组查询上使用 `SELECT FOR UPDATE`：无锁生成 ZIP，再用带离线、原业务状态、归属及任务占用条件的 UPDATE 复核；影响行数不符整批回滚。仅单条导出作业在确认/取消/清理时使用 `FOR UPDATE` 防止同一交付冲突，该锁不覆盖 ZIP 生成或网络传输。
- 生效需要后端 Flyway `V204__account_selected_export.sql` 与前端一同发布；本轮未执行任何真实账号操作。

## 1. 需求口径

以本次用户要求为准：账号列表支持单选、多选、全选；只导出明确选中的账号；按照导入凭据格式导出（六段、全参、JSON），混合格式拆文件放入同一个 ZIP；先下线，确认离线后才能导出；交付后从控端删除。

这里的交付物是账号凭据文件。账号列表中的昵称、分组、状态等展示列不作为凭据文件的字段定义。

## 2. 已核实的当前实现

本次只读检查本地当前工作树，不代表测试环境的运行版本，也没有查真实账号、下载凭据或操作远程服务。后端当前分支为 `1.0.3-snapshot`，存在较多其他任务在途修改，包括导入解析相关改动；本文依据当前文件内容，不依据纯 HEAD。

| 事项 | 当前事实 | 本次缺口 |
| --- | --- | --- |
| 勾选 | 表格已有 selection；列表重新加载时清空选中集合 | 可复用单选、多选、当前页全选；未实现跨页保留选择 |
| 账号列表导出 | 只有 `POST /api/accounts/export-ws-phones`，下载手机号 TXT | 不是凭据导出，也不执行下线和移除 |
| 导入记录导出 | `exportDetails(batchId, scope)` 从导入明细的原文生成 TXT/ZIP | 按导入批次范围查询，不能直接用于账号勾选导出 |
| 原格式 | 批次保存 `import_format`，明细保存 `account_id/raw_payload/source_entry_name` | 需要按当前账号 ID 精确关联成功导入记录，不能按手机号或整个批次扩展范围 |
| Android 全参 | 原始全参保存在导入明细，运行时凭据转换为六段 | 不能用 `account_credential.cred_format` 单独判断原格式，更不能从六段反造全参 |
| iOS 全参 | 原始全参保留，运行时格式为独立的 `ios_native_full` | 应与 Android 全参分文件，不能互相转换 |
| 批量下线 | 修改 desired_login_state、取消待发上线命令、写下线 outbox | 接口受理不等于实际离线，需要命令和终态关联确认 |
| 离线状态 | `login_state=2` 还涵盖 RECONNECTING、NEED_REAUTH 等不可用状态 | 单看列表“离线”不等于不会重连，需要确认主动停止及重连取消 |
| 删除 | 只允许特定账号业务状态且未派发；SQL 只改 `account.deleted_at` | 普通离线账号不能直接删除；凭据、导入原文、协议缓存不会随之完整清理 |
| Web 凭据 | `creds.update` 保存最新运行时凭据，已有协议导出路由 | 原始导入 JSON 不一定等于当前凭据；部分 transient 模式下 offline 会删除 creds/keys |

## 3. 建议交互与范围

新增“导出账号并移除”入口，与“导出 WS 号”区分。用户确认框展示选中总数、各格式数量、待下线数量、阻断原因，以及交付后从控端移除的后果。

范围只允许明确 ID 集合：

1. 单选、多选、表头全选均取实际勾选 ID；没有勾选则禁用，不回退为全部账号或当前筛选结果。
2. 本次建议表头全选沿用“当前页全选”。如果需要跨页全选，增加明确的“选择筛选结果全部 N 个”，后端在确认时固化 ID 快照，后续新增匹配账号不能自动进入导出。
3. 提交后冻结 ID 快照，不受翻页、刷新、筛选改变影响；租户和数据权限在服务端重新验证，ID 去重但不可静默丢弃不存在、越权或已删除的 ID。
4. 第一版建议整批成功语义：缺材料、格式无法确定、被任务占用或下线失败时，不交付部分账号、不删除部分账号；展示具体阻断项。已经完成的下线不自动反向上线。
5. 预校验先检查全部材料与占用，尽量在下线前发现问题。任务占用需覆盖账号派发及分组占用，不能只看 ONLINE/OFFLINE。

## 4. 文件规则

建议统一生成一个 ZIP，即便本次只有一种格式，方便重试和核对。目录示例：

```text
accounts-时间-导出编号.zip
├── 六段.txt
├── 全参-Android.txt
├── 全参-iOS.txt
└── JSON/
    ├── 账号A.json
    └── 账号B.json
```

只生成存在数据的文件。六段及全参按账号逐行；JSON 一号一文件，避免多份对象直接拼接成非法 JSON。全参虽然语法也是 JSON，仍按导入的业务格式分类，不能仅以扩展名分组。原始五段导入保持五段原文，不伪造第六段；如需严格分开，独立输出“五段.txt”。

以成功导入明细的原文和批次格式为首选材料来源。不能取整个原文件，因为原文件可能包含未勾选、重复或导入失败的账号。JSON 数组导入当前已按元素保存，承诺账号内容及格式一致，不承诺原文件逐字节、数组外壳和排版一致。

文件名由服务端安全生成，禁止直接信任来源路径；确保无路径穿越、重名覆盖、遗漏、重复账号。凭据文件不添加列表字段、说明表头或错误日志。

历史账号没有 raw_payload、没有唯一成功来源记录，或来自注册/配对而没有导入格式时，先标为不可按原格式导出，不能静默输出空文件或强制换格式。是否支持这些来源，需要单独定义可验证的格式来源；材料覆盖率尚未查询真实环境。

## 5. 状态与交付流程

建议采用后台导出作业：

```text
冻结选中范围 → 校验格式/材料/权限/占用 → 暂停账号调度
→ 停止上线和重连、请求下线 → 确認全部实际离线
→ 按格式封装并校验 ZIP → 持久化可下载产物
→ 客户端完整接收并回执 → 提交控端移除 → 完成
```

持久化产物和控端删除无法与 HTTP 下载组成一个原子事务。不能下载接口一被调用就删号，也不能把前端点击链接当作下载已完成。

建议客户端下载完整 Blob 并校验大小/摘要后回执，服务端幂等提交删除。该回执只能证明客户端接收，不证明操作系统最终保存到磁盘，因此仍保留短期重下载。删除提交失败，账号继续保持不可调度的导出锁，作业重试；下载失败不删除；响应丢失可通过作业状态查询确认，不重建另一批导出。

若用户要求必须确认实际落盘后才删，需增加显式“已保存，完成移除”步骤；普通浏览器下载方式不能自动证明落盘。

“离线”必须与本次停止命令或协议终态证据对应。重连中、待上线、状态未知、仅 desired=OFFLINE 均不足。导出锁需被手动上线、自动重试、任务调度等所有入口共同遵守，并以数据库条件更新/事务复核防止导出检查后再次被占用。晚到 ONLINE 事件不得解除移除或导出锁。

## 6. Web JSON 的特殊问题

保留原始输入格式和保留最新可用凭据是两个不同要求：

- 按原文还原可以复用导入明细，但不能由此承诺其他控端能再次登录。
- 如果目标是迁移后继续使用，应在协议停止连接且最终凭据落稳后导出最新材料，保持对应 JSON 格式，并做重新导入/实际登录验证。
- Web 协议现有 offline 在 transientCreds 模式下会清理 creds/keys，因此不能简单先调用原下线接口、再请求实时凭据导出。需要具备“停止连接、保存最终快照、确认离线、交付后清理”的交接能力，且检查目标 JSON 格式是否承载需要的 keys。
- 本次只确认代码中存在这一行为；未验证具体环境账号是否使用该模式，也未验证实际迁移登录。
- 移除控端记录不得误调用 Web `logout()` 或 Android 解绑设备接口；这些操作可能撤销导出凭据对应的身份。应主动离线并移除本地控制关系。

建议业务按“原格式、可继续使用的账号交付”验收；如果仅要求原文件回收，可缩小为原文导出，但需明确不包含运行时更新。

## 7. 删除范围：待用户确认

已通过问题卡确认以下两种范围，暂未收到选择：

1. 建议：从账号列表和可调度资源中移除，禁止再上线/任务使用；保留历史结果、审计及短期重下载。账号身份可采用软删，历史任务关联保留。控端活动凭据与协议控制关系必须失活；不将“主表软删”直接等价为完整移除。
2. 彻底清除：额外清理运行凭据、导入原文、协议缓存及最终 ZIP。需明确清理时点；彻底清除后不能继续提供原文件重下载。原导入批次的导出也必须执行相同删除策略，避免从旧入口取回已清除的材料。

无论哪种范围，账号移除与历史任务结果保留要分别处理，避免破坏历史统计和审计。

## 8. 影响范围与落地拆分

- 前端：账号列表入口、导出预览、明确范围、作业进度、下载/回执、结果刷新；不沿用批量上下线的“无勾选则按查询范围”逻辑。
- 后端账号域：新增导出编排服务、来源材料查询、格式分组、ZIP 生成、导出锁、离线终态收敛、交付与移除幂等。
- API 建议：`POST /api/accounts/exports/preview`、`POST /api/accounts/exports`、`GET /api/accounts/exports/{id}`、`GET /api/accounts/exports/{id}/file`、`POST /api/accounts/exports/{id}/complete`。路径为建议，未实现；所有接口绑定租户、操作人及对应数据权限，独立导出权限需沿用当前权限体系定义。
- 数据：现有导入材料字段复用。建议新增账号导出作业及账号明细归属，记录范围、阶段、命令关联、产物引用与摘要、回执和清理结果；属于账号交接聚合。现有 marketing_task_export_job 服务营销数据导出，不宜塞入账号生命周期副作用；现有 outbox 只表达命令投递，无法替代整个交付状态。最终表/索引设计待实现前核对，用 Flyway，不在本轮加表。
- 协议层：最新材料模式需要安全交接快照与移除契约；原文模式也要确认停止重连、清理归属和晚到事件处理。
- 存储：受限下载产物、短期有效、授权重下载；日志和列表不记录凭据，不能复用公开素材下载链接。缓存只辅助，不作为删除依据。
- 部署：涉及协议交接能力时，协议先提供兼容能力，后端再启用，前端最后开放入口；按用户指定环境逐一验证，本轮无部署。
- 回滚：关闭新作业入口，已存在作业继续提供下载/恢复能力。不得把已交付移除的账号自动重新上线，也不能直接回滚 schema 导致未完成作业丢失。

## 9. 验收与验证计划

1. 单选、多选、当前页全选、空选、切页、切筛选、提交后列表变化；导出 ID 集合严格等于确认快照，ZIP 各文件账号集合不重不漏。
2. 六段、五段、Android 全参、iOS 全参、JSON 对象/数组/ZIP 来源及混合导出；导出解包后使用现有解析器再次导入，核对数量、身份和格式。
3. 缺原文、失败/重复导入行、跨租户 ID、无效 ID、软删账号、特殊文件名、重名，全部明确拒绝且不删账号。
4. 下线受理但未完成、RECONNECTING、未知状态、下线超时、并发上线、任务抢占、晚到回调；禁止提前交付或移除。
5. ZIP 生成失败、下载中断、完整下载后回执丢失、删除事务失败、服务重启和重复提交；结果可查询、可重试，不重复删除、不丢产物。
6. 真实 Mapper + 租户插件 + H2 验证集合范围、事务与幂等；协议测试验证停止与快照时序。指定测试环境使用可控账号完成解包、导入及登录验证，不以 ZIP 可打开代替账号可使用。

本轮验证：仅静态代码和规则文档核对。未修改业务代码、未运行测试、未查询真实数据、未对任何账号执行下线/导出/删除。
