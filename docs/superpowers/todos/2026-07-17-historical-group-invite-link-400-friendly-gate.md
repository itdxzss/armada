# TODO：历史群邀请链接 400 友好提示与写操作门禁

- 记录日期：2026-07-17
- 状态：TODO / 未实施
- 影响范围：`armada-protocol`、`armada-api`、`wheel-saas-pure-web`
- 关联功能：历史群详情与成员管理、单群拉人、营销发送

## 问题背景

历史群详情读取邀请链接时，WhatsApp 对标准的群邀请链接查询返回
`400 bad-request`。当前协议层将该异常落入通用兜底并返回
`500 INTERNAL_ERROR`，后端继续透传技术错误，前端再把错误码、错误信息和
禁用原因拼接展示，最终出现不友好的提示：

`群链接硬门禁未通过 / INTERNAL_ERROR / internal server error`

已确认同一次详情请求中的群 metadata 可以正常读取，固定操作账号是目标群管理员；
现有证据不支持将该 400 归因于 Armada 请求参数、错误账号或非管理员权限。
WhatsApp 原始响应没有提供比 `bad-request` 更细的原因。

## 已确认的产品行为

群邀请链接不可用时，详情抽屉仍可打开，并保留以下只读能力：

- 查看群详情和成员列表。
- 刷新详情。
- 关闭抽屉。

以下写操作必须全部禁用：

- 成员选择、提升管理员、降级管理员和移除成员。
- 配置和创建单群拉人任务。
- 选择营销模板和触发营销发送。

前端只展示一次友好提示，不向业务用户展示 WhatsApp 原始
`400 bad-request`、协议层堆栈或 `500 INTERNAL_ERROR`。

## 建议实现方案

### 协议层

- 仅在群邀请链接查询接口识别 WhatsApp 的 `400 bad-request`。
- 转换为稳定错误码 `GROUP_INVITE_LINK_UNAVAILABLE`，建议使用 HTTP 422；
  原始状态码和原始错误摘要仅保留在结构化日志或受控诊断字段中。
- 其他未知异常继续走现有统一错误处理，避免扩大错误归类范围。

### Armada 后端

- 将 `GROUP_INVITE_LINK_UNAVAILABLE` 映射为稳定的业务状态和友好中文原因。
- 群详情接口继续成功返回可查看的数据，同时设置：
  `inviteUrl=null`、`linkAvailable=false`、`operationAllowed=false`。
- 成员管理和拉人创建接口保留服务端写前校验；即使绕过前端，也必须拒绝执行并
  返回友好业务错误。

### 前端

- 主提示标题改为“暂时无法获取群邀请链接”。
- 建议提示内容：

  > WhatsApp 暂未返回该群的有效邀请链接。当前仅支持查看和刷新详情，成员管理、
  > 拉群和营销操作已禁用。请稍后刷新，或在 WhatsApp 群设置中重新生成邀请链接后重试。

- 主提示只读取一个后端业务禁用原因，不再拼接错误码、技术错误和禁用原因。
- 清除拉群区域重复展示的同类错误；门禁失败不是一次拉群执行错误。
- 所有写控件使用同一群链接门禁状态，读详情和刷新不受影响。

## 验收标准

- WhatsApp 邀请链接查询返回 `400 bad-request` 时，协议接口不再返回
  `500 INTERNAL_ERROR`。
- 历史群详情仍能展示群信息和成员列表。
- 页面只出现一次友好提示，不显示原始 400 或通用 500 文案。
- 成员管理、拉群和营销的全部写入口均不可操作。
- 直接调用后端成员管理或拉人创建接口同样会被服务端拒绝。
- 协议层、Armada 后端和前端分别补充失败映射、门禁及重复提示测试。

## 本 TODO 不包含

- 将 WhatsApp 原始 400 推断为请求参数错误、权限错误或账号选择错误。
- 生产环境部署或真群写操作验证。
