**我们的号给陌生人发消息（尤其是首次联系）会被封或受限。目标：找到不被封的发送方式，并弄清楚什么样的号质量高。**

## 分支 2：perf2 两个发送号为什么被封、什么时候封的　✅ 已查清

- 测试发送分组两个 Android 号（5699…25、2349…57）11-02 17:24/17:29 给陌生号（8432…78）首次发送 → 约 2–6 秒后服务器 `stream:error 503` 断开 → 快速重连 → 登录失败 403 → 封号。
- 商家号 2763…86 在 10-31 首次给 receiver-01 发纯文本 URL，同样被封。
- **反例**：同一批号 11-01 先发 “Hi”、对方回复后，再发约 64 条按钮/链接没被封。所以“首次联系就封”不是必然。
- 这几个号登录 `<success>` 的 creation 距封号只有 1–2 天（都是新激活的号）。
- 代理：iproyal 混合国家，每 15 分钟换 IP，30 小时内约 130 次重登。这可能也是风险因素，**未单独验证**。
- 封号信号链（可用于以后自动识别）：消息 ACK → 503 → 重连 → 403。

### 5b 商家资料批量查询（实测，11-03 18:21）　✅
- 用一次性探针查了 70 个 WB Pro 号的商家资料：
  - 发 >200 条的 33 台：31 台返回空（大概率个人号），2 台商家号。

## 分支 6：能不能拿到号的注册时间　🟡

| 方法 | 结果 |
|---|---|
| Android 主设备登录 `<success creation>` | = 该号在这台设备注册/激活的时间（与 member_since 对比佐证），号商重新激活会刷新，**不是最初号龄** |
| Web 分身登录 `<success creation>` | **实测** = 分身绑定时间（只比服务器时间早 3–4 秒），没用 |
| 商家资料 `member_since_ts` | **实测**可用：任何在线号能查任何商家号，精确到秒；个人号/已封号为空 |
| 个人号 | 没有可直接查的字段（Baileys、whatsmeow 都没有）|
| GDPR“申请账户信息”报告 | 含注册时间和条款接受时间，但只能号主在手机上申请，约 3 天，可能是最近一次注册；协议里怎么发起未知 |
| 简介设置时间 / 头像时间 | 只是最后修改时间，不可靠 |

- 探针脚本：`creation-probe/probe.mjs`（在会话临时目录，见交接文档“工具”一节；建议拷到私有目录保存）。
