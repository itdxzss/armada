# 不可用 IP 单轮重检 200 条设计

## 背景

Armada 已有不可用 IP 定时重检任务，默认每 15 分钟执行一轮，当前单轮最多处理 20 条。代码默认值、应用配置和测试/生产 Compose 模板都保留了 20 的默认值；其中 Compose 同时向容器传入 `IP_PROXY_UNAVAILABLE_RECHECK_BATCH_SIZE` 与 Spring 可直接绑定的 `ARMADA_IP_PROXY_UNAVAILABLE_RECHECK_BATCH_SIZE`，因此只修改 Java 或 `application.yml` 不能保证标准部署实际使用 200。

## 目标

- 单轮最多重检 200 条不可用 IP。
- 调度频率继续保持每轮结束后等待 15 分钟。
- 标准测试部署和生产离线包中的后端容器固定收到批量值 200，不受宿主机 `.env` 中旧值影响。
- 保持现有顺序检测、跨租户上下文恢复、成功转空闲和失败保持不可用的行为不变。

## 非目标

- 不增加并发检测能力。
- 不调整代理检测超时、调度线程池或失败重试规则。
- 不连接测试服或生产服务器，不修改远端 `.env`，不执行部署。

## 方案比较

1. **同步默认值，并在标准 Compose 中固定为 200（采用）**：仓库默认口径一致，标准部署不会被旧 `.env` 覆盖，同时保留应用在非标准部署方式下的配置能力。
2. **只修改远端 `.env`**：改动少，但测试、生产和新环境容易产生配置漂移，并且需要逐环境操作。
3. **删除批量配置并在任务代码中硬编码 200**：约束最强，但失去非标准部署下的紧急调节能力，超出本次需要。

## 详细设计

### 应用配置

- `IpProxyUnavailableRecheckJobProperties` 的 `batchSize` 默认值改为 200，并同步 Javadoc。
- `application.yml` 中 `IP_PROXY_UNAVAILABLE_RECHECK_BATCH_SIZE` 的回退值改为 200。
- 调度任务继续读取 `properties.batchSize()`，不改变服务接口和检测数据流。

### 标准部署配置

- `armada-deploy/docker-compose.rds.yml` 中两个批量环境变量都改为字面量 `200`。
- `armada-deploy/prod/app/docker-compose.yml` 做同样修改。
- 不再对这两个 Compose 条目使用 `${...:-20}`。Compose 的显式 `environment` 值会覆盖同服务 `env_file` 中的旧值，因此标准部署容器固定收到 200。

### 数据流与错误处理

任务仍跨租户选取最多 200 条 `UNAVAILABLE` 代理并逐条调用现有真实检测逻辑。单条异常继续只计入本轮失败，不阻塞同批其它代理；检测成功恢复为 `IDLE`，检测失败继续保持 `UNAVAILABLE`。

固定延迟语义不变：本轮完成后再等待 15 分钟。由于仍为顺序检测，200 条慢代理可能拉长单轮执行时间；本次不引入并发或额外线程池。

## 测试与验证

- 先把属性默认值测试期望改为 200，确认测试因生产默认值仍为 20 而失败，再修改生产配置使其通过。
- 为测试部署配置校验增加断言，锁定两个容器环境变量均为字面量 200。
- 为生产离线包模板测试增加同样断言。
- 运行资源调度相关单测、部署配置校验和生产打包脚本测试；不执行远程部署。

## 回滚

将 Java、`application.yml` 和两个 Compose 模板中的批量值恢复为 20，并回退对应测试断言即可。无数据库、Redis 或 API 回滚事项。
