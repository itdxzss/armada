# 手动接码开发任务书

日期：2026-11-05。状态：已离线实现，待真实验收（见 [变更记录](../../.harness/changes/2026-11-05-sms-activation.md)）。替代同日的 [Armada 接码能力开发任务书](./2026-11-05-Armada接码能力开发任务书.md)（那一份按"对外交付服务"设计，范围过大，不再执行）。

接口事实参考：[Grizzly SMS API 能力说明](../business/2026-11-05-Grizzly-SMS-API能力说明.md)。

## 1. 要做什么

运营在后台点一下取一个 WhatsApp 号，页面上看到号码，拿去注册；页面自动刷新，验证码到了就显示出来；用完点"完成"，不用就点"取消"。

一句话流程：**选国家/价格 → 取号 → 显示号码 → 轮询出码 → 完成 / 取消**。

### 不做

- 不做预算预留、总额上限、批量取号（一次一个号，人工操作）。
- 不做幂等键、交付事件、ACK、OTP 加密、对账入口、活动订单列表。
- 不做后台定时任务；刷新由前端轮询触发。
- 不接入自动注册流水线（Cobalt / iOS 设备），不写 `account_registration_*` 表。
- 首版不做"再收一条短信"（`setStatus 3`），见第 9 节。

## 3. 数据表

新建一张表 `sms_activation`，归属 `account` 域，一行 = 一次取号。不复用 `account_registration_item`：那张表会被注册 worker 的 `nextWork` 扫走。

```sql
-- V221__sms_activation.sql（提交前核对版本号未被占用）
CREATE TABLE IF NOT EXISTS sms_activation (
  id BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
  tenant_id BIGINT NOT NULL COMMENT '租户ID',
  activation_id VARCHAR(40) NOT NULL COMMENT 'Grizzly订单ID',
  phone_number VARCHAR(32) NOT NULL COMMENT '完整号码,禁止日志输出',
  service_code VARCHAR(64) NOT NULL COMMENT '供应商服务代码,当前为WhatsApp',
  country_id VARCHAR(16) NOT NULL COMMENT '供应商国家目录ID',
  cost DECIMAL(30,12) NOT NULL COMMENT '供应商返回实际花费,不隐含币种',
  currency INT NOT NULL COMMENT '供应商返回ISO4217数字币种',
  state TINYINT NOT NULL COMMENT '1等码2已收码3已完成4已取消5已过期',
  sms_code VARCHAR(16) DEFAULT NULL COMMENT '收到的验证码,禁止日志输出',
  received_at BIGINT DEFAULT NULL COMMENT '收到验证码时间epoch毫秒',
  cancel_after BIGINT NOT NULL COMMENT '最早可取消时间epoch毫秒',
  expires_at BIGINT NOT NULL COMMENT '号码到期时间epoch毫秒',
  created_by BIGINT DEFAULT NULL COMMENT '取号操作人用户ID',
  created_at BIGINT NOT NULL COMMENT '创建时间epoch毫秒',
  updated_at BIGINT NOT NULL COMMENT '变更时间epoch毫秒',
  PRIMARY KEY (id),
  UNIQUE KEY uq_sms_activation (activation_id),
  KEY idx_sms_activation_page (tenant_id, created_at, id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='后台手动接码订单';
```

说明：

- 验证码只有几分钟有效，存明文没问题；但它和号码一样**禁止进日志、异常消息**。
- `cancel_after`：`activationCancel - activationTime` 的差加到当前时间；字段缺失或解析失败就用当前时间（让供应商自己拒绝过早取消）。
- `expires_at`：`activationEnd - activationTime` 的差加到当前时间；缺失或解析失败就按 20 分钟。
- 供应商时间不带时区，所以只用差值，不直接当时间点。
- 有 `tenant_id`，走租户拦截器，不用登记白名单。
- 改表后重跑 `.harness/wiki/gen_datamodel.py` 刷新数据模型文档。

## 4. 后端接口

新增 `account/controller/SmsActivationController`，路径 `/api/sms-activations`，权限 `@PreAuthorize("hasAuthority('tenant:account:edit')")`，与新号注册一致。分层：`Controller → SmsActivationService → SmsActivationMapper`，响应信封、分页、错误码沿用项目现有写法。

| 接口 | 作用 | 逻辑 |
|---|---|---|
| `GET /options` | 页面初始化 | 返回 `serviceCode`、`countries`（来自 `catalog()`）、`balance`（`getBalance()`，失败返回空并给出原因）、`purchaseEnabled`、`disabledReason` |
| `GET /price-tiers?countryId=` | 价格档 | 转发 `priceTiers(countryId)` |
| `POST /` | 取号 | 见 4.1 |
| `GET /` | 分页列表 | 本租户记录，按 `created_at` 倒序；不调用供应商 |
| `GET /{id}` | 查单个并刷新 | 见 4.2；前端轮询这个接口 |
| `POST /{id}/complete` | 完成 | 只允许 `已收码`；`setStatus(COMPLETE)` 成功 → `已完成` |
| `POST /{id}/cancel` | 取消 | 只允许 `等码` 且当前时间 ≥ `cancel_after`，否则提示"还需等待 N 秒"；`setStatus(CANCEL)` 成功 → `已取消` |

所有按 `{id}` 的接口通过租户拦截器查本租户的行，查不到返回 404。前端只传内部 `id`，不接受前端传 `activation_id`。

### 4.1 取号 `POST /`

入参：`countryId`（必填）、`maxPrice`（必填，正数，一般取所选价格档的价格）、`providerId`（可选，数字）。

1. 检查开关，关闭则直接报错，不调用供应商。
2. 校验 `countryId` 在 `catalog().countries()` 里。
3. 调 `grizzly.acquireNumber(new GrizzlyNumberRequest(serviceCode, countryId, maxPrice, new Options(null, providers, List.of(), List.of())))`。
4. 成功：写一行，`state=等码`，返回该行。
5. 失败：
   - `NO_NUMBERS` / `NO_BALANCE` / 配置类错误：返回明确提示（"当前价格无号，请换价格档"、"余额不足"），不写表。
   - `isOutcomeUnknown()` 为真（超时、断连、解析失败）：提示"取号结果不明，请稍后刷新列表或到 Grizzly 后台核对"，**不自动重试**，不写表。
6. 供应商成功但写库失败：`WARN` 日志只打 `activationId`（不打号码），然后返回错误，方便人工到平台取消。

取号在请求线程内同步完成（客户端读超时 20s）。前端在请求期间禁用按钮，防止连点。

### 4.2 查询并刷新 `GET /{id}`

- `state` 不是 `等码` → 直接返回，不调用供应商。
- `等码` 且当前时间 ≥ `expires_at` → 改为 `已过期` 返回，不调用供应商。
- `等码` 且未过期 → 调一次 `getStatus(activationId)`：
  - `RECEIVED` → 写 `sms_code`、`received_at`，`state=已收码`
  - `CANCELLED` → `state=已取消`
  - `WAITING_CODE` / `WAITING_RETRY` / `WAITING_RESEND` → 不变（`WAITING_RETRY` 带的旧码不写入）
  - 调用失败 → 不改状态，正常返回当前行（只记 WARN 日志），下一轮轮询再查，不抛 500
- 状态更新用条件更新 `WHERE id=? AND state=1`，多个标签页同时轮询也不会把状态改回去。

### 4.3 状态

```
等码 ──收到码──▶ 已收码 ──完成──▶ 已完成
 │
 ├──取消──▶ 已取消（供应商侧取消也落到这里）
 └──到期──▶ 已过期
```

`setStatus` 失败（例如 `BAD_STATUS`、ACK 不匹配、结果不明）时不改本地状态，把原因提示给用户，用户可刷新后重试。

## 6. 前端页面

仓库 `wheel-saas-pure-web`，先读该仓库 `AGENTS.md` 和 `.harness/rules/前端架构.md`、`编码规范.md`。

文件：

- `src/api/sms-activation.ts`：封装上述接口，页面不直接调 axios。
- `src/views/account/sms-activation/index.vue`：页面壳，控制在 400 行以内。
- `src/views/account/sms-activation/composables/useSmsActivation.ts`：取号、轮询、完成/取消逻辑。
- 需要时拆 `components/`（取号栏、号码卡片、记录表格）。

布局：

1. **顶部取号栏**：余额、国家下拉、价格档下拉（显示价格和库存）、可选商家、"取号"按钮。`purchaseEnabled=false` 时显示 `el-alert` 提示原因，按钮禁用。
2. **进行中卡片**：列出本页 `等码` / `已收码` 的记录。显示号码（带复制按钮）、到期倒计时、验证码（收到后大字高亮，带复制按钮）、"完成" / "取消"按钮（取消按钮在 `cancel_after` 前禁用并显示倒计时）。
3. **记录表格**：`el-table` + 分页，列：号码、国家、花费、状态、验证码、创建时间、操作人。

轮询：只对 `等码` 的记录每 4 秒调一次 `GET /{id}`；收到码、终态或离开页面就停（`onUnmounted` 清定时器）。
