# 拉手受限后的原群补拉：分析与确认范围

- 日期：2026-09-17。
- 范围：用户后续确认在主仓库修复代码；不处理旧任务，不部署、不重拉、不修改远程记录。
- 用户要求：不引入常规主动查群；原调用明确返回拉手受限时换健康拉手重试未成功人员。
- 结论：一般 UNKNOWN 不等于确定失败；本次实现按原因限定、保留原事实的有界恢复策略。下面 87 人的现场证据仅用于定位，不发起补拉。

## 修复前缺口与代码证据

- `PullTaskPullCallParticipantResultService.applyAccountFailure`：受限后已有账号限制及粘性拉手失效逻辑，换号能力已存在。
- 同类的 `aggregateTarget` / `attemptTarget`：UNKNOWN + UNCERTAIN 被保留未知并关闭；仅 NOT_STARTED 进入释放/重试分支。
- `PullTaskPullCallMemberAttemptMapper.xml/selectRetryCandidatesByWaveInternal`：仅允许指定明确失败、未开始未知、名单确认不在群的未知；账号限频未知不在筛选范围。
- `PullTaskPullWaveSettlementTransactionService.collect`：没有重试候选就推进后续阶段，因此未知人员未被补拉，群执行仍能收口。
- `PullTaskRetryPolicy`：已有每人每群最多 4 次尝试（含首轮），波次间隔 60/120/240 秒；属于当前代码规则，不能宣称是 WhatsApp 安全阈值。
- `promoteLateSuccess`：已有迟到成功保护和撤销未提交新计划，但无法撤回已发出的新请求。
- Web `group-participants-executor.ts` 和 Android `group_participants_sender.go` 均把调用后的账号限频异常归为 UNKNOWN + UNCERTAIN；测试也锁定该行为。不要为了重试伪造为 NOT_STARTED 或确定 FAILED。
- 群成员 add 事件已有群域持久化路径，但未接到任务人员结果；可复用被动事实，不能用事件缺失证明失败。

## 本次确认的规则

| 原因与证据 | 本次处理 |
|---|---|
| 已确认成功或收到成功回执 | 从补拉候选剔除，成功不可被迟到失败覆盖；群事件接入任务结果不在本次范围 |
| 调用前账号封禁/离线，协议确认 NOT_STARTED | 复用有界重试，换健康拉手 |
| 原批次明确回报 RATE_LIMITED / ACCOUNT_REACHOUT_RESTRICTED | 允许按账号受限策略进入有界换号补拉；保留原 UNKNOWN 事实，承认它不是无重复风险的确定失败重试 |
| 请求已经发出，随后封禁/断线/超时 | 不能仅凭账号状态判整批失败；不把通用 UNKNOWN 全部自动重试 |
| 隐私限制、目标未注册等成员级确定失败 | 不因换号就自动重试 |
| 群封禁、群不可用 | 走独立群级处理，不在原群反复补拉 |

不新增常规主动查询。复用已有成功状态和迟到成功回执剔除目标；群域的被动入群事实尚未接入任务回写，本次不扩展该链路。

只针对受影响人员创建新 attempt / commandId，原命令同一次投递重试继续沿用原键。禁止全包重跑；禁止清空历史台账。一次只允许同一人员一个活动 attempt，按执行行事务锁串行规划、回调与结算。保留现有次数和间隔，换号不清零预算；无健康拉手进入等待资源。

修复后收到的新受限回执会释放相关人员，由现有波次结算创建后续计划。历史 CLOSED 未知记录不重新开启，已结束任务不恢复；不新增指定人员恢复入口。另一个会话的群级失败换群逻辑会复制整份 TXT，本次不复用或修改该实现。
