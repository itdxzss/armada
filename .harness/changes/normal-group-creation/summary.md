# 新建普群

## 目标

在 Armada 群组列表提供“新建普群”异步任务能力。管理员账号不复用；成员账号允许跨群复用；每个群一次请求携带完整初始成员创建；Web 与 Android 账号由现有统一协议 Routing Port 自动路由。

## 已确认口径

- 每群成员数 `K <= 可用成员数 M` 才能提交；`M > K` 时仅随机选择 K 人，不报错。
- 空群模式固定选择 1 个成员。
- 群名模板必填；未选择群组分组时进入“未分组”。
- 双向联系人保存成功即视为好友准备成功，不遍历完整通讯录。
- 默认权限：所有成员可发言、普通成员不可修改群资料、所有成员可添加成员、关闭入群审批、关闭限时消息。
- 邀请链接权限不属于 V1，不展示、不接收、不调用。
- 建群人退群前必须提权一名真实群成员，并回查确认群内已有其他管理员。

## 实现边界

- 新增联系人准备、一次性建群、群后处理三个 Armada Kafka 主 Topic，共用一个 DLT。
- 阶段消费者直接调用现有 `ContactPort`、`GroupCreatePort`、`GroupSettingsPort`、`FixedAccountGroupMetadataPort`、`GroupParticipantPort`、`GroupLeavePort`。
- 不新增协议命令 JSON、协议 Outbox、协议结果 Topic 或协议端第二套状态机。
- 新增任务、计划群明细、计划群成员三张 Flyway 表；Controller 只做鉴权/参数校验/响应封装，业务在 Service，数据访问在 Mapper。
- 冻结的 `protocol_backend` 通过既有 Routing Port 自动选择 Web/Android Adapter；现有两套协议端口已满足本期能力，因此不修改 Web/Android 协议仓公共逻辑。
- Kafka 发布使用异步回调；每分钟只按索引恢复最多 100 条漏发或租约过期记录，不使用 1 秒高频业务表扫描。
- `PROCESSING` 使用 `processing_started_at` 执行租约：只有 PREPARE 过期可恢复待发布；CREATE 过期转 `RESULT_UNKNOWN`，POST_PROCESS 过期转 `CREATED_PARTIAL`，避免重放可能已经完成的建群、提权或退群副作用。
- 协议返回有效群 JID 后先保持 CREATE 租约做数据库条件落库，再保存全部逐成员回执，最后才开放 POST_PROCESS 派发；JID 落库失败视为结果未知，不能降级为普通失败。
- 协议步骤使用租户内账号级 Redis 锁并按令牌看门狗续租；锁冲突或 Redis 暂不可用走 Kafka 有限重试，协议动作完成时停止续租并串行校验/释放全部令牌，失去锁所有权时按不可安全重放结果收敛。
- 所有阶段完成、失败和释放重试写入都以 `last_event_id` 做 fencing；旧消费者不得覆盖新租约。每阶段默认最多尝试 3 次，达到上限后转明确终态，数据库补偿不会把 DLT 消息无限重新发布。
- V1 只接受 `NORMAL` 速度；单任务限制为最多 1000 个群、每群最多 1024 个成员且成员快照总行数不超过 10000。
- 创建、查看、重试分别使用 `tenant:normal_group:create/view/retry` 方法级权限；前端按钮只作辅助控显。
- “新建普群”前端入口同时要求 create 与 view，确保提交成功后具备读取和轮询任务的权限；失败项重试仍独立要求 retry。
- 创建入口默认限制单租户 20 个活动任务、5000 个在途群、每分钟 10 次提交，且单用户每分钟 5 次；Redis 限流和账号候选查询先于租户准入行锁，同租户最终容量读取与任务/快照批量插入由该行锁串行；锁后活动任务使用 `FOR UPDATE` 当前读，避免 MySQL RR 旧快照穿透上限。Redis 多 Key Lua 使用共同租户 hash tag，限流不可用时失败关闭。
- 协议异常与非协议异常落库和返回页面只使用稳定错误码及白名单业务文案，不透传下游响应正文、端点或敏感信息；服务端日志只记录异常类型和定位字段。
- 退群调用发出后如发生超时等不确定结果，明细转 `RESULT_UNKNOWN` 等待人工对账，不自动重放整个后处理。

## 验收锚点

1. 重复 `Idempotency-Key` 只创建一个任务。
2. 管理员不足、成员不足、群名为空、分组不存在时拒绝提交并给出明确错误。
3. 同一任务管理员不复用；同群成员不重复；跨群成员允许复用。
4. 每个计划群严格按 PREPARE → CREATE → POST_PROCESS 推进；重复/越序消息幂等跳过。
5. Web 账号只调用 Web Adapter，Android 账号只调用 Android Adapter；失败重试不换协议账号。
6. 建群请求一次携带全部冻结成员；已有 `group_jid` 绝不再次创建。
7. 创建成功群登记到现有群组列表，并按可选 folder 归组。
8. 默认五项权限显式设置并回查；邀请链接权限不参与。
9. 建群人退群前确认其他真实管理员；不满足条件则保留建群人并记录告警。
10. 变更通过针对性单测、Mapper/Flyway 测试、Web/Android Adapter 契约测试和前端类型检查。
11. 相同幂等键并发提交只返回原任务；MySQL RR 下唯一冲突回读使用当前读。
12. partial 或缺失成员回执不得默认成功；最终结果为 `CREATED_PARTIAL`。
13. 共享 DLT 不绑定来源分区号，由 Kafka 选择可用分区，避免不同来源 Topic 分区数不一致导致二次失败。
14. 只有 `FAILED` 明细允许人工重试；`RESULT_UNKNOWN`、`CREATED_PARTIAL` 必须先人工对账，不能直接重放协议副作用。
15. 仅有群列表查看权限不能创建或重试；租户活动任务、在途群或提交频率达到上限时，创建在协议副作用前被拒绝。
16. 不同幂等键并发创建不能穿透租户活动任务或在途群硬上限；Redis Cluster 下限流脚本不发生 `CROSSSLOT`。
17. 组件卸载、切换任务或同一任务发生并发刷新后，旧进度响应不得恢复轮询或覆盖最新状态；重试提交成功但详情刷新失败时不得误报“重试失败”。
