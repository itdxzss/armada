## 1. WhatsApp 官方客户端里的相关查询

来源：iOS 26.34.72 的 Argo 响应结构，`wa-biz-compat-v8-extension/docs/analysis/contacts-20260908/notes/mutual-wire-all.json`。都按"对方 jid"查（`xwa2_fetch_wa_users`）。

| 查询（iOS doc id） | 返回字段 | 理解 |
|---|---|---|
| `IntegrityAIInputsQuery`（26576471731949397） | **`reputation_score`（浮点）**、`is_country_mismatch` | 最像"账号权重"。iOS 把每个聊天对象的 `senderReputation` 存进本地库 |
| `IntegrityQuery`（24966207873007786） | `is_banned`、`is_suspicious`、**`join_date_ms`**、`trust_tier`、`integrity_tags`（带日期）、Meta 认证、FB/IG 粉丝数 | 偏商家号。`trust_tier` 从代码里的名字看至少有超高、中、可疑几档（推断） |
| `StartChatContextIntegrityQuery`（26038899055732942） | **`is_new_account`**、**`join_date_ms`**、`is_suspicious_start_chat` | 陌生人发消息时界面上那张"非联系人、刚加入"的安全提示卡 |
| `FetchAccountReachoutTimelock` | 是否受限、受限到几点、受限类型 | Android 端每次登录后已经在查并上报 |

如果 `join_date_ms` 对个人号也能查到，分支 6 一直没解决的"个人号号龄"就有办法了（11-03 已确认：Android `creation` = 在这台设备上激活的时间，商家资料 `member_since` = 成为商家号的时间，都不是最初号龄）。

## 2. zhuan 里已经做了一半

`whatsapp-server-feature-android-zhuan/internal/service/app/safemex.go`：

- `SendIqMex`，注释"查询商业版账号权重"，Android doc id `24897449816559062`
- `SendContactIntegrityQuery`，doc id `8370845569632382`
- 变量格式现成：`{"input":{"query_input":[{"jid":"号码"}],"telemetry":{"context":"INTERACTIVE"}}}`

但都没真正用起来：

- 结果解析在 `internal/service/node/nodes/iq.go:481` 整段注释掉了；它读的是 `integrity_tags`、`dates_ms`，说明以前至少拿到过一次商家号的结果。
- 调用方 `CheckUserStatusService` 没接到任何接口，发出去也不读结果。

## 3. 和首次联系实验相关的一条

iOS 有个配置项 `reachoutTimelocksPrivacyTokenSendingEnabled`，看名字是把"隐私令牌"和"陌生人发送受限"挂在一起（只从名字推断）。
注意 11-04 的实测已经更正：接收方在消息前收到的那条 `privacy_token` 通知是服务器生成的，不是 iPhone 发送方先签发的（见 [2026-11-04-真手机首次联系报文实测-iPhone.md](2026-11-04-真手机首次联系报文实测-iPhone.md)）。

## 4. 还不知道的

- iOS 的 doc id 从分身（Web 协议）或 Android 协议发，服务器认不认。zhuan 注释说受限状态查询的 Web、Android 编号可以混用，有希望，未验证。
- 能不能查**别人**的分数（我们想查自己的发送号），还是只对给你发过消息的人返回。
- 个人号查不查得到。

## 5. 建议下一步

写一个只查不发的小探针（照 [`wa-probe/old-creation-probe/probe.mjs`](wa-probe/old-creation-probe/probe.mjs) 的 `--biz` 模式）：扫码挂一个分身，对一批号码发上面几个查询，返回原样存下来。号码分三组：perf2 已封的号、能正常发的号、用户主号作对照。
能查到的话，把信誉分和"发了多少条才死"放一起比，就是号质量规律最直接的指标。

扫码用哪个号由用户定。接收号 / 查询号不要用曾在我们协议上登录过的号（原因见上面那份实测文档）。
