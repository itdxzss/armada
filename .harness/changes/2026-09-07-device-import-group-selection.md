# 手机上传前选择分组

## 目标与范围

用户要求手机点击上传后查询分组，选择目标分组并携带账号参数上传。基于已集成主线的 `0d46f939`，在 `codex/device-import-ingest-integration` 工作树实施；原全参工作树与其他会话修改保持独立。

当前接口契约及手机交接见 [联调提示词](../../docs/2026-09-07-control-side-ingest-agent-prompt.md)。本次要求替代旧设计的固定分组和单路径限制。账号参数沿用现有 phone/payload；机型、申报类型和 IP 策略继续由服务器配置。

## 设计与影响

- 增加 `GET /api/device-imports/groups`，复用 `AccountGroupService.options()` 及真实 Mapper 的租户过滤与软删过滤，仅返回 id/name，不创建分组。
- POST 增加必填正整数 `accountGroupId`。构造现有 `AccountImportDTO`，复用 `requireExisting()` 在写入前验证分组，账号及批次使用所选 ID。缺失或无效选择不回退默认组。
- 令牌配置删除 accountGroupId；绑定租户、机型、类型、IP 不变。专用安全链精确覆盖两个 URI，令牌不能访问管理员分组 API。
- nginx 两条精确路径共用安全代理配置，分别限制 GET/POST 及本地 OPTIONS，其他路径继续拒绝。
- 无新 SQL、表、列、Flyway、Redis 或协议实现。保留既有单次事务、原文保存、六段转换、QUEUED 与调度行为。

## 手机源码对接修正

用户继续要求实现手机端。读取实际 V8 源码发现：导出字段 phone 为纯数字，jid 为 phone@s.whatsapp.net，原设备入口纯数字 jid 约束会拒绝所有此类导出。设备转换器现强制 phone 与纯数字/电话域 jid 一致，仅在内存副本中归一化供现有转换器使用，原始 payload 不变；管理员既有转换口径不扩张。

新增 H2 用例首先复现参数校验失败，修正后定向回归及打包 140 项通过。包含空 lid 的实际 V8 字段形态、六段运行凭据、原文保持及伪造/不同号码/LID/设备后缀拒绝。手机联调仍不等于真实协议上线。
