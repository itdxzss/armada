### normal_group_creation_admission_lock（新建普群租户容量准入锁）

每租户固定一行，仅用于在创建任务事务的最终落库段串行执行“重新读取活动容量 → 批量插入任务和冻结明细”。Redis 限流、账号候选查询和内存分配必须在取锁前完成。该表不保存计数器，容量真值来自锁后对活动任务 `total_count` 的 `FOR UPDATE` 当前读及 Java 聚合（活动任务数另受硬上限约束），禁止使用会复用 MySQL RR 旧快照的普通聚合读；事务提交或回滚即自动释放行锁。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| tenant_id | bigint | PRIMARY KEY | 租户 ID，同时作为准入锁定目标 |
| created_at | bigint | NOT NULL | 首次创建时间(epoch毫秒) |

### normal_group_creation_task（新建普群异步任务）

保存任务级资源快照、五项群权限默认值、幂等键和聚合进度。管理员与成员账号分组只用于提交时选择候选，执行阶段不得重新按分组换人。

| 关键约束/索引 | 字段 | 类型 |
|---|---|---|
| uq_normal_group_creation_task_idem | tenant_id, idempotency_key | UNIQUE |
| idx_normal_group_creation_task_status | tenant_id, deleted_at, status, created_at, id | INDEX |

`group_count` 是请求提交后冻结且不可变的计划群数；`total_count` 是实际生成的明细数，供任务汇总展示。二者在当前版本通常相等，但语义不可混用。幂等键在租户内永久唯一，软删除任务也不允许复用原键。

### normal_group_creation_item（新建普群计划群明细）

每个目标群一行，冻结唯一建群账号及其 `protocol_backend`，并保存阶段、Kafka 发布状态、群 JID、部分成功标记、执行租约起点、群列表 ID 和最终错误摘要。三个阶段消费者始终按冻结 backend 通过统一 Routing Port 选择 Web 或 Android Adapter。

| 关键约束/索引 | 字段 | 类型 |
|---|---|---|
| uq_normal_group_creation_item_no | tenant_id, task_id, item_no | UNIQUE |
| uq_normal_group_creation_creator | tenant_id, task_id, creator_account_id | UNIQUE |
| idx_normal_group_creation_item_dispatch | dispatch_status, next_dispatch_at, id | INDEX |
| idx_normal_group_creation_item_processing | dispatch_status, processing_started_at, id | INDEX |
| idx_normal_group_creation_item_task | tenant_id, task_id, deleted_at, id | INDEX |
| idx_normal_group_creation_item_jid | tenant_id, group_jid | INDEX |

`contact_prepare_failed` 在进入建群阶段时按成员方向状态一次性算出，标记本群是否存在未成功的加好友方向；加好友是尽力而为的可选动作，失败不阻断建群，所以该标记为 1 时 `status` 仍可能是 `CREATED`。`create_partial` 保存协议建群是否部分成功；`processing_started_at` 是 PREPARE/CREATE/POST_PROCESS 阶段执行租约起点，`last_event_id` 同时承担当前消费者 fencing token。租约过期时只有 PREPARE 可恢复为待发布；CREATE 必须转为 `RESULT_UNKNOWN`，POST_PROCESS 必须转为 `CREATED_PARTIAL`，禁止自动重放可能已完成的建群、管理员移交或退群副作用。三个 attempt 字段限制阶段自动尝试次数，达到上限后转终态并停止补偿发布。

### normal_group_creation_item_member（新建普群初始成员快照）

保存每个计划群的一次性初始成员、协议后端、双向联系人准备状态和建群逐成员结果。成员可跨群复用，但同一群内不重复；失败重试复用原快照。

| 关键约束/索引 | 字段 | 类型 |
|---|---|---|
| uq_normal_group_creation_member | tenant_id, item_id, member_account_id | UNIQUE |
| idx_normal_group_creation_member_task | tenant_id, task_id, member_account_id | INDEX |
| idx_normal_group_creation_member_item | tenant_id, item_id, member_order | INDEX |

该快照表不做软删除，不包含 `deleted_at`。`member_order` 用于稳定恢复原始参与人顺序，不作为唯一约束；同一群内成员账号由唯一索引保证不重复。

加好友失败原因按方向独立保存在 `creator_save_error_code/creator_save_error_message` 与 `member_save_error_code/member_save_error_message` 上：两个方向共用一对列会被对向的成功回执覆写为 NULL，而加好友失败已不再终止明细，必须逐方向保留。`last_error_code/last_error_message` 是 V110 之前的共用列，现已无写入方，留待后续清理迁移删除。
