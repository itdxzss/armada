## 关键设计决策

- 账号关联和台账只保存 Armada 账号 ID，不保存手机号、协议账号 ID 或凭据。
- 本批采用 test1 后端主机上的一次性受控脚本直接调用协议 HTTP 接口；数据库只读，不创建 Armada 普通建群任务或手工写业务表。
- Web 调用协议 master，并通过请求中的 `accountId` 路由到 owner worker；Android 调用 Zhuan 原生 `/ws/v1/*` 接口。
- 所有协议写动作按计划群串行且原则上只调用一次；未知结果先只读对账，再决定是否补偿。
- 联系人阶段按执行账号建立独立 FIFO：同账号最多一个请求在途，不同账号按 Android=6、Web=2 的独立池并发；每个账号完成请求后随机冷却 1–3 秒。
- HTTP 429 仅冻结命中的执行账号并指数退避，其他账号继续推进；结果按方向、actor Armada ID、target Armada ID 追加到脱敏 JSONL。
- live 只能复用包含 dry-run checkpoint 的同一远端账本；冻结后分组增删成员或切换 strict/ready-only 均会被硬门禁拒绝。
- 联系人完成口径是冻结矩阵中每个账号对的两个方向都明确成功；不可用账号不能静默排除。
- 每个群的次管理随机结果必须在建群前冻结；失败重试沿用原名单，不重新随机。
- 分组 110 的“全量”按执行启动时冻结的完整有效成员定义；任一账号不可用时默认阻止启动，而不是缩小成员集。
- 提权或设置返回未知时先读取实时群 metadata，禁止盲目重放有副作用操作。
- 当前普通建群链路支持发送消息、编辑资料、添加成员、批准新成员、消失消息五项设置，但不支持同名的“发送/查看消息记录”权限。
- 当前 Baileys 可获取/吊销邀请链接，但未暴露“允许通过邀请链接”同名独立设置；需先确认业务口径。
- 当前普通建群请求只有一个 `memberAccountGroupId` 和固定 `memberCount`，无法直接满足两个来源的组合成员规则。
