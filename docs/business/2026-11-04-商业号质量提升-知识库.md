# 商业号质量提升 知识库（2026-11-04）

本文整理 2026-11-04 一天的结果：账号权重（trust_tier）实测、公开资料调研、提升号质量的官方办法（客户先开口、企业验证、Meta 认证、官方 Cloud API）。

- 手机号一律打码（前 4 位…后 2 位）。原始记录只在原电脑 `armada/_tools/wa-probe/runs/integrity-*`，含真实号码，不进仓库。
- 标"推断"的是根据名字、排列或少量样本推出来的，没有官方说明。
- 官方规则会变，用之前对照文末链接核对一次。

## 一、结论

1. 商业号的"档位"是 WhatsApp 服务器给的，从低到高推断为：SUSPICIOUS（可疑）< TIER_0 < TIER_1 < TIER_2 < TIER_3；另有 UNTIERED（未分档）。个人号永远是 UNTIERED。
2. 我们的号很多在**还没发消息时**就是可疑或未分档。WhatsApp 在注册那一刻就会判断号码来源和注册网络，**问题主要在号源**，不在后来怎么发。
3. 网上没有任何"怎么把档位升上去"的公开资料。官方公开的规则都指向同一件事：**看收件人的反应**（回复、拉黑、举报）和**企业身份是否真实**。
4. 提升号质量的正路有四条：让客户先开口、企业验证、Meta 认证、大批量营销走官方 Cloud API（详见第四节）。



## 二、账号权重实测（11-04）

### 2.1 怎么查的

- 工具：`_tools/wa-probe/integrity-probe.mjs`（交接目录里有去掉号码的副本 `docs/handoff/wa-probe/`）。手机扫码挂成分身，只发查询、不发消息，查完自动退出关联。
- 能用的查询（查询编号来自 iOS 26.34.72 安装包，从网页版协议发也能用）：

| 查询 | 编号 | 拿到什么 |
|---|---|---|
| IntegrityQuery | 24966207873007786 | **档位 trust_tier**、是否可疑、是否封号、注册时间、号码国家、是否订阅 Meta 认证、一组按天的标记 |
| StartChatContextIntegrityQuery | 26038899055732942 | 注册时间（只对商业号返回） |
| IntegrityAIInputsQuery | 26576471731949397 | 本应有信誉分 reputation_score，**实测从来不返回** |

- 限流：一次查 20～30 个号以后，返回的字段会变空，或者超时、断连。每次查 5～20 个号、间隔 4 秒比较稳。
- 已封的号查不了，返回 `NOT_ALLOWED`；`is_banned` 从来没出现过 true。
- 同一个号隔几小时再查，结果一样（6395…19 上午、下午都是未分档），不是随机的。
- 查询期间会出现几次"发出了消息"的提示，那是扫码号发给自己其他设备的同步请求（category=peer），没有发给任何别人。

### 2.2 个人号还是商业号，看服务器，不看我们的标签

服务器返回的类型 `XWA2User` = 个人号，`XWA2BusinessUser` = 商业号。我们库里的标签不可靠：wbpro 里标"个人号"的大发送量号，服务器认定全是商业号。perf2 的 `account_type` 也有标错的。

### 2.3 档位一共几种

- 本机 WhatsApp Mac 版（26.31.27，和手机版同一套代码）里，商家信任档位的名单是 `SUSPICIOUS, TIER_0, TIER_1, TIER_2, TIER_3` 五个；服务器另外还会返回 `UNTIERED`。
- 代码里有"中等信任档或以上"（hasMidTrustTierOrAbove）和"超高信任档"（hasUltraHighTrustTier）两个判断，旁边单独列着 TIER_1、TIER_2、TIER_3。推断 TIER_1 起算"中等以上"，TIER_3 是"超高"。
- 已知用途：可疑档位的商家，对方看不到商家标识和商家名称（开关名 `hide_business_indicators_for_suspicious_trust_tier`、`hide_business_push_name_for_suspicious_trust_tier`）；中等以上、超高档位影响订单状态的展示。**和发送限额、封号有没有关系，没有证据。**
- 注意别混淆：代码里的 `MV4B_TIER_1~4` 是 Meta 认证的付费套餐档，不是信任档位。

### 2.4 实测分布（按服务器认定的类型，去重）

| 档位 | 个人号 | 商业号 | 特点 |
|---|---|---|---|
| UNTIERED | 全部 | 7 个 | 个人号一律这个；商业号里多是新号 |
| SUSPICIOUS | 0 | 7 个 | perf2、test1 的号，**都是还没发过消息就被标记** |
| TIER_0 | 0 | 8 个 | wbpro 里只发过 3～6 条的号 |
| TIER_1 | 0 | 14 个 | wbpro 发送量 594～4902 条的号都在这档 |
| TIER_2 / TIER_3 | 0 | 0 | 没出现过 |

"发得多的是 TIER_1、发得少的是 TIER_0"只基于二十来个号，可能是号正常用久了档位升上去，不能当成规律。

## 三、公开资料里查到的：WhatsApp 怎么判号

### 3.1 档位本身没有公开说明

官方文档、新闻、GitHub 都搜过，`trust_tier` 没有任何公开说明。GitHub 上的逆向项目（wa-spec、whatspec、Cobalt）只收录了网页版的一个查询 `WAWebMexFetchIntegritySignalsQuery`（编号 26438847999065394），只取两个字段：是否新号（`is_new_account`）、首次发起聊天是否可疑（`is_suspicious_start_chat`）。网页版用它在陌生号第一次发消息时，**给收件人显示一张安全提示卡**。所以新号、可疑号给陌生人发消息，对方会先看到警告，更容易拉黑、举报。

### 3.2 号在注册时就会被判

WhatsApp 2019 年的反滥用白皮书写明：机器学习系统在**注册时、发消息时、收到举报时**三个阶段封号；注册时会看这个号码最近是否被滥用过、注册用的网络是否关联过可疑行为；"注册 5 分钟就在 15 秒内发 100 条"几乎可以断定是滥用。当时每月封约 200 万号，其中约 20% 在注册阶段，约 75% 不需要用户举报。

### 3.3 2025 年起的硬限制（档位再高也绕不开）

- **给陌生人、对方没回复的消息有月度上限**：2025-10 起在多个国家测试，个人号、商业号都算；对方回复后，这些消息就不再计入；快到上限时 App 弹窗提醒，超了暂时不能再给新的人发。具体数字没公布。
- **广播限制**：2025-03 起测试，测试时举例是每月 30 条；商业号会有付费广播。
- **营销消息按收件人限额**（官方 API）：每个收件人能收到的营销模板数量有上限，按这个人最近的互动情况自动调整，对所有商家合并计算。欧洲经济区、英国、日本、韩国暂不适用。

### 3.4 自己这个号还剩多少额度，有查询能查（未实测）

- 出处：GitHub 仓库 [oxidezap/whatspec](https://github.com/oxidezap/whatspec) 的 `generated/mex/index.json`，条目 `FetchNewChatMessageCappingInfo`（网页版原名 `WAWebMexFetchNewChatMessageCappingInfoJobQuery`，编号 27910975521856601）；[vinikjkkj/wa-spec](https://github.com/vinikjkkj/wa-spec) 里也有。这两个项目每天从 WhatsApp 网页版代码里自动提取接口，不是 Meta 官方文档。
- 返回字段：额度状态 `capping_status`、本周期起止时间、总额度 `total_quota`、已用额度 `used_quota`、Meta 认证状态 `mv_status`、订阅状态等。应该就是上面那个"陌生人未回复消息月度上限"的额度。
- 返回里带着认证状态，推断额度可能和 Meta 认证挂钩。**我们还没调用过这个查询。**

### 3.5 官方 API 的额度和质量规则（公开）

- 额度按企业组合（business portfolio）计算，组合下所有号码共用：250 → 2,000 → 10,000 → 100,000 → 无限，单位是每 24 小时能发起联系的不同用户数。
- 250 升到 2,000：完成企业验证；或者 30 天内用高质量模板给 2,000 个不同用户发出（在客服窗口之外）。
- 2,000 以上自动升档：消息质量高，且最近 7 天用掉当前额度的一半，6 小时内升一档。
- 质量评分看收件人的拉黑率、举报率；某个模板被拉黑、举报太多会被暂停。
- 新企业组合最多注册 2 个号码，企业验证后或额度到 2,000 后升到 20 个。

## 四、提升号质量的办法（操作手册）

### 4.1 让客户先开口

客户主动发第一条，就不是"陌生人首次联系"：对方不会看到安全提示卡，不计入陌生人月度上限，回复多、拉黑少，正好是 WhatsApp 看重的信号。

**① wa.me 链接（不用申请，谁都能用）**

- 格式：`https://wa.me/号码`，号码写完整国际格式，不带 +、0、括号、横线。例如 `https://wa.me/639xxxxxxxxx`。
- 带预填文字：`https://wa.me/639xxxxxxxxx?text=你好，我想了解XX`（文字要做 URL 编码）。客户点开后文字已经填在输入框里，他点发送就行，也可以先改。
- 放在：网站、落地页、社媒简介、邮件签名、短信、商品详情页。
- WhatsApp 不提供点击统计，要统计就套一层自己的短链。

**② WhatsApp Business App 自带的短链接和二维码（不用申请）**

- 路径：WhatsApp Business App → 设置（或右上角三个点）→ 商家工具 → 短链接；同一页面里点二维码。
- 可以设置一条默认的预填消息；可以复制链接、直接分享，或者下载二维码打印出来（门店、包装、传单、名片）。
- 注意：重置短链接后，旧链接和旧二维码就失效了，印出去的要重新印。

**③ 官方 API 号的二维码和短链接**

- 在 WhatsApp Manager（Meta 商务套件）里创建，或者调用接口 `POST /<号码ID>/message_qrdls`，参数 `prefilled_message`（预填文字）、`generate_qr_image`（SVG 或 PNG）。
- 预填文字最多 140 字；每个号码最多 2,000 个二维码或短链接；可以只改预填文字、不换二维码图片。

**④ 点击跳转 WhatsApp 的广告（Click-to-WhatsApp，在 Facebook、Instagram 上投）**

- 从 Business App 投（最简单）：商家工具 → 在 Facebook 上投放广告 → 选商品目录里的商品或手机里的图片、视频 → 设置受众、预算、时长 → 付款。需要先把 WhatsApp 号码和一个 Facebook 主页绑定。
- 从广告管理工具（Ads Manager）投（功能更全）：创建广告 → 转化位置选 WhatsApp → 选绑定的号码 → 上传素材、写文案 → 可以自定义客户点进来后看到的问候语和快捷问题 → 发布。
- **中国大陆企业**：不能直接在 Meta 开广告账户，要通过 Meta 在中国的官方代理商开户（报道称约 11 家，名单以 Meta for Business 官网的合作伙伴目录为准）。同一主体下有账户违规被封，关联账户可能被一起封。
- 如果号码在官方 API 上：客户从这种广告点进来发消息后，会开一个**最长 7 天的免费窗口**，窗口内回复营销、工具、验证、客服类消息都不收费（仅限客户用手机 App 点进来，网页版、电脑版不算）。

### 4.2 企业验证（Meta Business Verification，免费）

- 入口：Meta 商务套件 → 设置 → 安全中心 → 企业验证 → 开始验证。按钮是灰的，通常是企业资料不全（名称、地址、电话、网站）。
- 材料：中国大陆接受公司注册证书、商业登记摘录、营业执照类文件；地址、电话可以用银行对账单、水电费单等证明。名称、地址必须和材料一致。最好先做网站域名验证。
- 审核时间：几个工作日到 4 周不等。被拒可以在安全中心联系支持，准备好案件编号和截图。
- 作用：API 额度直接从 250 升到 2,000；号码上限从 2 个升到 20 个；也是申请认证标志的前提之一。

### 4.3 Meta 认证（Meta Verified，付费订阅）

- 入口：WhatsApp Business App → 工具 → Meta Verified。符合条件的话，会让你绑定付款方式、付第一期；Meta 验证不通过会退还第一笔钱。
- 条件（第三方整理，以 App 里显示为准）：年满 18 岁；号码所在国家开通了这个服务；号码在 Business App 上用了一定天数、最近发过消息；有商家名称和头像；没有其他冲突的付费订阅。
- 价格：按号码按月收，第三方报的起步价约 14.99 美元/月，有几档套餐；**以 App 里显示的价格为准**。开通国家各方说法不一致，同样以 App 为准。
- 好处：认证标志、防冒充保护、人工客服。我们查到的号，返回里是否订阅认证（`is_mv_subscribed`）都是 false；额度查询里也带认证状态（推断可能有关）。
- 官方 API 号码另有一条免费申请认证标志的路径（需企业验证、显示名称已审核、开两步验证等），以 Meta 官方页面为准。

### 4.4 大批量营销走官方 Cloud API

**开通步骤（自己对接 Meta）**

1. 有 Facebook 账号，注册 Meta 开发者账号。
2. 在应用面板创建应用，用途选"通过 WhatsApp 联系客户"，选择或新建企业组合。
3. 点"开始使用 API"，先用 Meta 给的测试号码发一条 `hello_world` 模板试通。
4. 添加正式号码，填写显示名称（要审核），用短信或语音收验证码注册，设置两步验证 PIN。
5. 在商务设置里建系统用户，生成长期访问令牌（权限 `business_management`、`whatsapp_business_messaging`、`whatsapp_business_management`）。
6. 绑定付款方式；配置 Webhook 接收消息和状态回执；创建、提交消息模板审核。

**号码要求**

- 号码必须归自己所有，有国家和地区代码，**能接收短信或语音电话**（注册、迁移都要收验证码）。
- 已经在 WhatsApp 或 Business App 上用着的号码，要先删除账号才能注册到 API；被封的号要先申诉解封。
- 另一个办法是**共存（Coexistence）**：号码继续在 Business App 上用，同时接入 API。要求 Business App 版本 ≥ 2.24.17，通过服务商（解决方案合作伙伴或技术服务商）的嵌入式注册流程接入；有服务商说号码要在 App 上正常用满 7 天（官方文档没写）。App 里发的消息仍免费，API 发的按 API 价格收费。

**也可以找服务商（BSP）代接**：360dialog、WATI 等官方合作伙伴提供现成后台和接口，开户、模板审核、共存接入都能代办，代价是服务费。

**消息类型和计费（2025-07-01 起按条计费，送达才收）**

| 类型 | 用途 | 什么时候能发 |
|---|---|---|
| 营销 | 促销、活动、上新 | 用模板，随时可发（受按人限额约束） |
| 工具 | 订单、物流、账单通知 | 用模板，随时可发 |
| 验证 | 验证码 | 用模板，随时可发 |
| 客服 | 回复客户 | 只能在客服窗口内发，不用模板 |

- 客服窗口：客户每发一条消息，就开（或续上）一个 24 小时窗口，窗口内可以自由回复。
- 2026-10-01 起，客服消息恢复收费，每个号码每月前 1,000 条免费。
- 价格按收件人国家和消息类型定，每年 1、4、7、10 月的 1 日才可能调价。

**营销规则**

- 主动发营销消息前必须拿到对方同意（opt-in）：明确告诉对方"你同意接收某某商家的 WhatsApp 消息"，写明商家名称。网站勾选、短信、电话、线下登记都可以。
- 质量长期偏低会被限流，模板被拉黑、举报太多会被暂停。

## 五、对我们现状的影响

1. **号商批量号很难走官方路径**：出生就可疑；以后要长期能收验证码，号码也要归我们自己所有。走官方 API 需要真实注册、由我们控制的号码。
2. **走我们协议（zhuan、Web）登录的号用不了共存**：共存要求号码在官方 Business App 上正常使用。
3. **企业验证要真实企业材料**：一个企业组合对应一个真实主体，材料要和企业资料一致。
4. **获客方式要改**：从"我们找陌生人"改成"客户先找我们"（广告、链接、二维码），这是唯一能同时绕开安全提示卡、陌生人月度上限、按人营销限额的办法。
