# 接码注册对接 Go 开发任务书

日期：2026-11-05。状态：**已按本文实现（离线）**，实现记录与差异见 [变更记录](../../.harness/changes/2026-11-05-sms-registration.md)；真实注册待 Go 就绪后验收。**替代** [ARMADA 接码与 Go 注册对接方案（简版）](../business/2026-11-05-ARMADA接码与Go注册对接方案-简版.md) 中的复杂部分（每条记录租约、并行 lane、"取消中"状态、释放到人工等），以本文为准。背景核对见 [手动接码与 Go 注册三接口对接核对](../business/2026-11-05-手动接码与Go注册接口对接核对.md)。

**核心原则：不要过度设计，不加任何锁。** 部署里只有一个后端容器，`@Scheduled(fixedDelay)` 自己不会和自己重叠；防重靠幂等键和唯一键，不靠租约。

## 1. 要做什么

在现有手动接码页面，运营取到号码后点一次"开始注册"，后台自动：**占一个代理 IP → 让 Go 发验证码 → 等号商出码 → 把码交给 Go 验证 → 显示注册结果**。关闭页面也继续跑；可同时办理很多个号码。

成功的边界是 **Go 返回 REGISTERED 且 `result_available=true`**。账号导入、自动上线、IP 转正式账号绑定不在本任务内。

## 2. 前置条件（Go 侧，本任务不改 Go 代码）

Armada 按下面的合同编码，可以对着本地 HTTP 替身开发和测试；**真实注册要等 Go 全部就绪**，在此之前 `enabled=false`，按钮禁用。把本节原样转给 Go 会话。

1. **真实网络 Transport**（✅ 已写，2026-11-05 晚：字段组装、ENC 加密、经代理发 HTTPS、响应归类，并新增 `cmd/registration-profile` 导入设备配置；**未对真实服务器验证**，联调以 Go 日志里的 `registration response`（status/reason）为准，步骤见 Go 仓库 `doc/registration-api.md` 的“联调步骤”）。
2. **`code-requests` 首次形式新增 `proxy` 字段（✅ 已在 Go 实现，2026-11-05，见 Go 仓库 `doc/registration-api.md`；字段名即 `proxy`，首次必填、重发不得再带、加密保存、纳入幂等指纹）**：完整代理 URL（带协议头，如 `socks5://user:pass@host:port`）。Go 加密存进事务，发码和验码**都走同一个代理，不得直连**；缺失或不可用时拒绝，不回退直连。字段名以 Go 最终合同为准，Armada 只在一个适配类里拼装。
3. **`max_concurrent` 配置为 64**（`REGISTRATION_CONFIG_FILE`，合法范围 1–64；这是部署配置，Go 文档示例已改为 64，代码默认值仍是 3，部署时必须显式配置）。
4. **确认**：首次发码因并发额度返回 429 时，没有任何外部请求发出，可用原键、原参数重试。当前代码如此（`workflow.go` 先抢并发位、后保存发送意图），但需 Go 会话确认不会被改动。
5. **同号占用释放**：Go 对"租户+号码"有永久唯一占用，失败和取消都不释放，而号商会把同一号码再租出来 → 第二次发码永远 409。需要"失败且未注册的事务可释放占用"的能力。Go 目前对同号冲突与其它冲突都返回 409/`CONFLICT`，Armada 无法区分，统一记为 `GO_CONFLICT`；若 Go 能给出独立的 `error_code`（如 `PHONE_CLAIMED`），Armada 再拆分。不阻塞本任务。

## 3. 不做

- 不做重发验证码、换码、补买号码、自动取消订单、COMPLETE 重试。
- 不做租约、锁、`next_run_at`、"取消中"状态、操作表、批量采购、任务引擎。
- 不新增菜单，不新增 `GET /registration` 接口（状态直接放进现有订单 VO）。
- 不改 Cobalt 流程和 `account_registration_*` 表；同一订单只能走其中一条。
- 不走 coordinator（它没有注册事务路由），直连一个受控 Go 注册服务地址。
- 不做导入、上线、IP 转正式账号。

## 4. 数据

### 4.1 新表 `sms_registration`（account 域，一订单最多一条）

```sql
-- V223__sms_registration.sql（提交前核对版本号；当前最新为 V222）
CREATE TABLE IF NOT EXISTS sms_registration (
  id BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
  tenant_id BIGINT NOT NULL COMMENT '租户ID',
  sms_activation_id BIGINT NOT NULL COMMENT '接码订单,一单最多一条',
  state TINYINT NOT NULL COMMENT '1申请中2等码3验证中4已注册5需处理',
  go_profile_id BIGINT NOT NULL COMMENT 'Go配置ID,开始时固定',
  proxy_id BIGINT DEFAULT NULL COMMENT '本次占用的代理,发码前必须已写入',
  go_transaction_id VARCHAR(36) DEFAULT NULL COMMENT 'Go事务ID',
  go_version BIGINT DEFAULT NULL COMMENT '发码成功时Go返回的version,只写一次,验码永远用它',
  failure_code VARCHAR(40) NOT NULL DEFAULT '' COMMENT '需处理原因,固定分类',
  created_by BIGINT DEFAULT NULL COMMENT '点击开始的操作人',
  created_at BIGINT NOT NULL COMMENT '创建时间epoch毫秒',
  updated_at BIGINT NOT NULL COMMENT '变更时间epoch毫秒',
  PRIMARY KEY (id),
  UNIQUE KEY uq_sms_registration_activation (sms_activation_id),
  KEY idx_sms_registration_state (state, id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='接码订单的Go注册办理';
```

- 号码、验证码、供应商订单号只留在 `sms_activation`，**本表不复制**。`sms_activation.state` 不新增取值。
- `go_version` 只在"申请中→等码"时写一次，**验证中的任何查询都不得改写它**；验码重放永远用这个值。
- 有 `tenant_id`，走租户拦截器。改表后重跑 `.harness/wiki/gen_datamodel.py`。
- 失败码用一个小枚举，建议：`ORDER_NOT_WAITING`、`ORDER_EXPIRED`、`SMS_CANCELLED`、`GO_REJECTED`、`GO_CONFLICT`、`GO_UNAVAILABLE`、`GO_OUTCOME_UNKNOWN`、`GO_ACTION_REQUIRED`、`NO_RESULT_BEFORE_EXPIRY`、`PROXY_UNAVAILABLE`。

### 4.2 代理占用（resource 域，必须新增，不能复用配对占用的键）

`ip_proxy.pairing_session_id` 有全局唯一键 `uq_ip_proxy_pairing_session`，且与 `promotion_pairing_session.id` 是两个不同的自增序列。**把订单 ID 塞进 `allocatePairingEndpoint(pairingSessionId, ...)` 会和真实配对会话撞号**，要么占不上，要么误释放别人的 IP。

做法：参照 `IpProxyMapper.xml` 的 `reserveForPairing` / `confirmPairingAllocation` 和 `IpProxyService` 的 `allocatePairingEndpoint` / `releasePairingAllocation`，在 resource 域新增一套"注册占用"：独立的占用列（键为接码订单 ID，唯一）、`allocateRegistrationEndpoint`、`releaseRegistrationEndpoint`，复用同一套空闲代理选择算法。必须保证：

1. 被占用的 IP 不会分给别的账号、配对会话或另一次注册。
2. 国家用 `CountryService.resolveIpRegionByPhonePrefix(号码)` 解析，**不回退其它国家**（`allowOtherRegionFallback=false`）；无库存直接报错，不创建注册记录、不调 Go。
3. 释放按（订单 ID, 代理 ID）精确匹配，幂等。
4. 池里 http 与 socks5 并存时，分配结果必须是 Go 声明支持的协议（默认 socks5）；若现有算法不能按协议过滤，需加这个条件。
5. 代理 URL 由 `proxy_id` 现取现拼，保证同一记录每次拼出的字符串完全一致（Go 的幂等指纹包含它）。代理被改动或删除导致不一致时，按 Go 的 409 处理，进入"需处理"。

## 5. 接口

`SmsActivationController` 增加一个方法，权限沿用 `tenant:account:edit`：

`POST /api/sms-activations/{id}/registration`，无业务正文，返回 `SmsActivationVO`。

流程：
1. 校验：本租户订单；`state=等码`；未过期；尚无 `sms_code`；Go 注册已启用，否则返回 `disabledReason`。
2. 按号码国家占代理（4.2）；无库存直接报错。
3. 插入 `sms_registration`（`state=1`，写入 `proxy_id`、`go_profile_id`）。`sms_activation_id` 唯一键冲突 = 重复点击：释放刚占的 IP，返回已有记录。插入失败而 IP 已占：释放 IP 后抛错。
4. 返回。真正调 Go 由定时任务下一轮接手，**接口里不调 Go**。

`SmsActivationVO` 增加 `registrationState`、`registrationFailure` 两个字段（列表 LEFT JOIN）；`options()` 增加 `registrationEnabled`。

**占用规则**（替代一切锁）：`sms_registration.state ∈ {1,2,3}` 时订单被占用，此时：
- `complete`、`cancel` 返回冲突"注册进行中"；
- `refresh` 不再调号商，只读本地（由 worker 负责写码）。

进入 4 或 5 后不再占用，旧的完成/取消按钮自动恢复可用，这就是运营的出口，不要另加动作。

## 6. 后台推进（一个定时任务，无锁）

新增 `AccountSmsRegistrationScheduler`：`@Scheduled(fixedDelay=5s)`，开关 `armada.account.sms-registration.enabled`（默认 false）。**不要继承旧调度器的 `@Profile("kafka")` 条件**，除非确认这个功能确实依赖 Kafka。

每一轮：取出所有 `state ∈ {1,2,3}` 的记录，并取出终态但 `proxy_id` 尚未清空的记录，在**固定大小线程池**里并发处理（并发数配置项，默认 32，不得超过 Go 的 64），等本轮全部做完才结束。终态记录只补偿代理释放。一轮没结束下一轮不会开始，所以同一条记录不会被两处同时处理。线程池线程里要自己 `TenantContext.set(row.tenantId)` 并在 finally 清理，参照 `AccountRegistrationWorker.tick()`。HTTP 调用不放在数据库事务里。

**重驱动原则**：状态 1 和 3 每轮都用**同一把键、同样的参数**重新调一次 Go。Go 保证同键同参返回原操作的结果，所以"超时没拿到响应""进程重启""Go 还在处理"全都用同一个动作覆盖，不需要额外的恢复逻辑。键：`sms-go-v1:{tenantId}:{sms_registration.id}:send` 与 `:verify`。

| 状态 | 每轮做什么 |
|---|---|
| 1 申请中 | 订单不再是等码或已过期 → 5（`ORDER_NOT_WAITING`/`ORDER_EXPIRED`）并释放 IP。否则调 `code-requests`（`phone` 补 `+`、`profile_id`、`proxy`）。**200 且 WAITING_CODE** → 保存 `go_transaction_id`、`go_version` → 2。**202 处理中、429、网络超时** → 保持 1，下一轮同键同参重来。**202 结果未知、422、409、503、其它** → 5 并释放 IP |
| 2 等码 | 订单取消/过期 → 5。否则查一次号商：`RECEIVED` 且有新码 → 一个短事务内把码写入 `sms_activation`（沿用 `transition`，状态 → 已收码）并把本记录改为 3，随后调验码。`WAIT_RETRY` 的旧码不提交；`WAIT_RESEND` 不代表发了新短信，不处理 |
| 3 验证中 | 调 `code-verifications`（`code` 字符串保留前导零、`expected_version=go_version`、`:verify` 键）。**200 REGISTERED 且 `result_available`** → 4，随后调一次号商 COMPLETE。**202 处理中、429、超时** → 保持 3。**其它** → 5 并释放 IP。订单到期后仍无明确结果：GET 核对一次，REGISTERED → 4，否则 → 5（`NO_RESULT_BEFORE_EXPIRY`） |

注意：
- **COMPLETE 只在进入 4 的那一轮调用一次**，失败不重试：`sms_activation` 保持已收码，运营用旧"完成"按钮收尾；崩溃在两步之间同理。
- 按用户最终确认，进入 4 或 5 **都归还代理池**；释放成功后清空 `proxy_id`，失败保留标记供原定时任务重试，重启后继续回收。发码、等码、验码期间使用同一代理分配；接受供应商粘性到期后的出口变化，不额外保持旧出口。
- 状态 1 若长时间拿不到明确结果，到订单过期同样转 5。
- 号码、验证码、代理、token、Go 响应原文一律不进日志和异常消息。

## 7. Go 适配类

`platform/registration/go/`（独立于 `cobalt/`）：一个只含三个方法的接口加 HTTP 实现，业务代码不依赖 HTTP DTO。请求头 `Authorization: Bearer` 和 `Idempotency-Key`（1–128 个可见 ASCII）；JSON 严格：`snake_case`，响应在 `Code/Data/Msg` 里。

HTTP 语义：200/Code 0 才是确定结果；202（`OPERATION_IN_PROGRESS` 或 `OUTCOME_UNKNOWN`）**不是成功**；422 明确拒绝；409 冲突（统一 `GO_CONFLICT`，Go 目前不区分同号冲突）；429 本地限流；503 缺能力。以 `Data.state`、`error_code` 为准，参见 Go 的 `doc/registration-api.md`。

配置（`armada.account.sms-registration.*`）：`enabled`、`base-url`、`concurrency`、按租户的 Bearer 和 `profile-id`。不同租户不得共用同一个 Go 归属；有未完成记录时不要改地址、身份映射或密钥。凭据不进代码、不进日志。

前置调用（Go 侧 `max_concurrent`）：Armada 并发数不得超过它。号商调用频率上限目前没有资料，默认每轮每条等码记录查一次，**批量放量前先向号商确认频率限制**。

## 9. 验收（只跑相关测试，不跑全量）

Java 存储用 H2 跑真实 Mapper/事务；Go 与号商用本地 HTTP 替身。至少覆盖：

1. 单号正常：1→2→3→4，COMPLETE 只调一次。
2. 同时办理多个号码，乱序到码不串号（用并发，不是顺序模拟）。
3. 重复点击"开始注册"：不重复占 IP、不重复发码。
4. 发码未拿到响应、验码未拿到响应、进程重启：下一轮请求的键、参数、`expected_version`、验证码与第一次**逐项相同**。
5. 首次发码 429：保持申请中，下一轮成功。
6. 422、409（同号）、503、结果未知：进入需处理、释放 IP；之后旧"取消"按钮可用。
7. 订单过期/取消：停止提交，进入需处理。
8. 已注册但 COMPLETE 失败：保持已注册，订单仍为已收码，旧"完成"可用，worker 不再重试。
9. 无 IP 库存：不创建记录、不调 Go。
10. 代理占用不与配对会话撞号：构造 `pairing_session_id` 与订单 ID 相同的数据，两边互不影响。
11. 日志与异常消息不含号码、验证码、代理、token。

**不在本任务内**：真实单号、并发实测，需要 Go 就绪后由用户指定环境、号码数和次数。未经授权不得调用真实号商或 Go，不得部署。

## 11. 当前约定

| 项 | 默认 | 说明 |
|---|---|---|
| 注册结束后的 IP | 成功、失败均归还 | 用户已确认；释放失败由原定时任务补偿，不长期占住代理 |
| 无对应国家库存 | 不回退其它国家 | 号码国家与出口地区一致更接近真实手机 |
| Armada 并发数 | 默认 32，上限 64 | 必须不超过 Go 的 `max_concurrent` |
| 代理字段名 `proxy` | 暂定 | 以 Go 最终合同为准 |
