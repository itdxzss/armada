# 营销任务按钮推广链接展示设计

- 日期：2026-07-20
- 状态：已确认，待实施
- 范围：Armada 营销任务列表接口；前端沿用现有推广链接列

## 1. 背景与目标

营销任务列表当前把模板表的 `promotion_link` 作为
`marketingTemplatePromotionLink` 返回。普通超链和图文模板可正常展示，但按钮超链模板保存时会清空
`promotion_link`，实际跳转地址位于 `buttons` JSON 中 `LINK_JUMP` 按钮的 `param`，因此列表错误展示为 `—`。

目标是在不新增数据库字段、不扩大前端接口模型的前提下，让推广链接列展示模板的有效推广地址：

- 普通超链、图文模板继续展示 `promotion_link`；
- 按钮超链模板按按钮顺序展示第一个 `LINK_JUMP` 按钮的 `param`；
- 没有链接跳转按钮时返回空，前端继续展示 `—`。

## 2. 方案选择

采用“后端统一解析有效推广链接”：在营销任务 VO 组装处根据模板消息类型计算
`marketingTemplatePromotionLink`。

未采用：

1. 前端接收并解析完整按钮 JSON：会把模板存储格式泄漏到任务列表页面，并增加跨端重复规则。
2. 新增按钮链接专用字段：同一列表列需要在两个字段间选择，扩大接口且没有额外业务价值。

现有字段继续表达“营销任务列表应展示的有效推广链接”，对当前前端和旧调用方保持兼容。

## 3. 数据流与规则

`MarketingTaskServiceImpl` 加载当前页模板后，在组装 `MarketingTaskVO` 时执行：

1. 模板不是按钮超链：返回模板 `promotionLink` 原值。
2. 模板是按钮超链：解析模板 `buttons` JSON，按数组顺序查找第一个类型为 `LINK_JUMP` 且 `param` 非空的按钮。
3. 找到时返回该 `param`；找不到或按钮 JSON 无法解析时返回空。

按钮解析复用营销域现有 `MarketingTemplateConverter.buttonsFromJson` 规则，不新增第二套 JSON 模型或解析器。列表、详情、创建及任务状态变更均经过统一 VO 组装逻辑，避免不同接口口径分叉。

前端继续消费 `marketingTemplatePromotionLink`，保留单行省略、悬停查看完整链接、仅 HTTP(S) 可点击及新窗口安全跳转行为。

## 4. 异常与兼容

- 历史坏按钮 JSON 按现有转换规则降级为空，不影响任务列表其它字段返回。
- `COPY_CONTENT`、`QUICK_REPLY` 按钮不作为推广链接。
- 多个 `LINK_JUMP` 按钮只取第一个，顺序与模板按钮配置一致。
- 不修改表结构、Mapper SQL、租户隔离或模板保存规则。

## 5. 测试与验收

先增加失败测试，再实现：

1. 按钮模板混合快捷回复、复制内容和链接跳转时返回第一个跳转链接。
2. 多个链接跳转按钮只返回第一个。
3. 没有链接跳转按钮时返回空。
4. 普通超链和图文模板仍返回 `promotionLink`。
5. 现有营销任务列表模板信息测试继续通过。

验收时确认前端推广链接列对按钮超链任务显示对应 URL，悬停可见完整值并可点击跳转；无跳转链接仍显示 `—`。

## 6. 回滚

回退有效推广链接解析和对应测试即可；无数据库或配置回滚。
