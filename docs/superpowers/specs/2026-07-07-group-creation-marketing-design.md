# 建群营销任务设计

## 背景

运营需要一个新菜单，用于选择账号分组、上传多个料子文件，并自动为账号创建 WhatsApp 群。每个执行单元由一个协议账号和一个料子文件组成：账号负责创建一个新群，料子文件中的号码作为建群初始成员。建群成功后，系统要立即使用现有营销模板向新群发送营销消息。

现有能力可复用：

- 协议层已有 `POST /v1/groups/create`，支持 `accountId + subject + participants[]` 创建群并添加初始成员。
- Armada 后端已有营销模板、营销消息 composer、营销发送 attempt 和协议 outbox。
- 前端已有账号分组、营销模板、群营销任务页面模式，以及料子文件读取交互。

## 目标

新增“建群营销”任务能力：

- 业务人员选择账号分组、选择营销模板、上传多个料子文件。
- 前端按上传顺序展示文件，并显示账号与文件的自动匹配结果。
- 后端创建任务并生成 `账号 + 文件` 执行项。
- Worker 按执行项创建群；建群成功后立即下发营销消息。
- 列表和详情能查看任务整体状态、每个执行项状态、失败或放弃原因。

## 非目标

- 不做手动账号和文件拖拽映射。
- 不把多余账号作为后续补位账号。
- 不阻止“账号数和文件数不一致”的创建。
- 不改协议层建群接口语义。
- 不替换现有群营销任务；这是一个独立的建群后营销流程。

## 账号与文件匹配规则

前端保留文件上传顺序。后端按账号分组内 `account.id ASC` 取账号，与上传文件顺序一一配对。

- 账号数大于文件数：只使用前 N 个账号，N 为文件数；多余账号不生成执行项。
- 文件数大于账号数：只使用前 N 个文件，N 为账号数；多余文件在页面提示为“未匹配，不会执行”，后端不落执行项。
- 可匹配数量为 0：拒绝创建任务，提示账号分组无可用账号或没有上传有效文件。

后端必须重新执行匹配规则，不能只信任前端提示。

## 后端架构

新增 `group_creation_marketing_task` 主表和 `group_creation_marketing_item` 明细表。

主表保存任务名称、账号分组快照、营销模板快照、总执行项数、成功数、失败数、放弃数、状态、备注和时间字段。

明细表保存执行项：

- 账号 ID、账号号码、协议账号 ID。
- 文件名、文件顺序、解析出的号码 JSON 或规范化文本。
- 创建出的群 JID、本地 group_link ID。
- 建群命令和营销发送 attempt 的追踪字段。
- 状态、失败原因、重上线尝试次数、创建/更新时间。

新增服务边界：

- Controller：`/api/group-creation-marketing-tasks`，负责列表、创建和详情；创建成功后任务自动进入待执行队列。
- Service：校验模板、读取账号分组内账号、解析文件号码、生成任务和执行项。
- Worker：按执行项推进状态机，调用协议层建群接口，建群成功后写入群池并下发营销 outbox。
- Mapper：任务和执行项的读写、待执行项领取、计数更新。

## 执行状态机

执行项状态：

- `PENDING`：待执行。
- `ONLINE_RETRYING`：账号离线，正在尝试重上线。
- `GROUP_CREATING`：正在建群。
- `MARKETING_SENDING`：群已创建，营销发送命令已生成或等待结果。
- `SUCCESS`：营销发送成功。
- `FAILED`：协议建群或营销发送失败。
- `ABANDONED`：账号封禁、不可用、重上线 2 次后仍离线，或缺少协议账号 ID。

账号处理规则：

- 封禁、不可用、风控、禁用、缺协议账号 ID：执行项直接 `ABANDONED`。
- 离线：触发现有账号上线逻辑，最多重上线 2 次；仍未在线则 `ABANDONED`。
- 在线：调用协议层建群接口。

建群成功后：

1. 将新群登记到本地群池，来源为自建群。
2. 写入账号与群的 membership 快照。
3. 使用所选营销模板生成营销消息 attempt。
4. 写入 `message.send.requested` 协议 outbox，实现建群后立即营销。

## 前端设计

新增任务中心菜单：`建群营销`，路径为 `/task/group-creation-marketing`。

页面结构跟现有任务列表保持一致：

- 顶部筛选：任务 ID、任务名称、状态、创建时间。
- 列表：任务名称、账号分组、模板、执行项数、成功/失败/放弃数、状态、创建时间、操作。
- 新建抽屉：
  - 任务名称。
  - 账号分组选择。
  - 营销模板选择。
  - 上传多个 `.txt/.csv` 料子文件。
  - 匹配预览表：账号、文件名、文件顺序、号码数、匹配状态。
  - 未匹配文件提示：文件数超过账号数时列出多余文件。
  - 群名规则：默认使用任务名称加序号，可选填写固定前缀。
  - 备注。
- 详情抽屉：按执行项展示账号、文件名、号码数、群 JID、状态、原因、重上线次数和营销发送结果。

前端只做提示和预览，最终执行项以后端创建结果为准。

## 错误处理

- 文件为空或没有有效号码：该文件不参与匹配，并在页面提示。
- 建群接口失败：执行项 `FAILED`，记录协议错误码和错误消息。
- 部分号码因为隐私或无效未入群：建群接口仍返回群 JID 时视为建群成功，营销继续发送；详情保留 participant 结果摘要。
- 营销模板配置无效：执行项进入 `FAILED`，原因使用现有 composer 校验错误。
- Worker 重复执行：领取待执行项时使用状态条件更新，保证同一执行项只被一个 worker 推进。

## 测试

后端：

- 创建任务时账号数多于文件数，只生成文件数个执行项。
- 创建任务时文件数多于账号数，只生成账号数个执行项，并返回未匹配文件摘要。
- 无可匹配执行项时拒绝创建。
- 离线账号触发最多 2 次重上线，失败后放弃。
- 封禁或不可用账号直接放弃。
- 建群成功后写群池、membership、营销 attempt 和 outbox。

前端：

- 上传多个文件后按上传顺序展示匹配预览。
- 文件多于账号时展示未匹配文件提示但允许提交。
- 创建 payload 保留文件顺序和内容。
- 详情能展示执行项状态和失败原因。
