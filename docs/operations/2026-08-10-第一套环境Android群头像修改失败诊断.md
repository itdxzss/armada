# 第一套环境 Android 群资料修改失败诊断

## 1. 事件摘要

- 发生日期：2026-08-10
- 环境：`test1 / 第一套环境`
- 页面：任务中心－群组列表－群组信息
- 测试群：`India Community 84`
- 群 JID：`120363431468293974@g.us`
- 用户操作：更换群头像，以及后续修改群名称、群备注
- 页面结果：红色提示“群资料修改失败”
- metadata 状态：`SUCCEEDED`
- 最近同步时间（页面原始值）：`1786374919695`

## 2. 结论

本次头像和群名称失败的高概率根因是：**群资料修改能力没有按账号协议后端路由。**

`India Community` 批量群使用 Android 原生协议创建和管理。群详情业务会从数据库选择一个在线且仍在群内的执行账号；该账号可能是 Android 协议账号。但头像修改使用的 `GroupProfilePort` 当前只注册了 Web/Baileys 的 `HttpGroupProfileAdapter`，没有 Android profile backend，也没有 `WEB/ANDROID` 路由层。

因此实际链路很可能是：

```text
Android 群
  -> 自动选择 Android 在群管理员
  -> GroupDetailServiceImpl.updateAvatar
  -> 单一 HttpGroupProfileAdapter
  -> 请求 Web/Baileys armada-protocol
  -> Web 协议层找不到该 Android 账号或无法执行该群操作
  -> 返回非 TIMEOUT、非 GROUP_PERMISSION_DENIED 的协议异常
  -> Armada 统一转换为“群资料修改失败”
```

这不是图片大小或文件类型校验失败。图片校验失败时页面应分别显示：

- `请选择群头像`
- `只能上传图片文件`
- `群头像不能超过 5 MiB`
- `群头像读取失败`

本次页面收到的是通用协议失败提示，说明请求已经通过了前置文件校验并进入协议调用链。

## 3. 证据

### 3.1 页面证据

测试截图显示：

- 群名称为 `India Community 84`；
- 群 JID 为 `120363431468293974@g.us`；
- metadata 状态为 `SUCCEEDED`，说明本地 metadata 快照可用；
- 点击更换头像后提示“群资料修改失败”。

因此可以排除“群详情尚未同步”导致按钮误用。

### 3.2 Android 群来源

项目内 `India Community` 批量建群方案明确使用 Android 原生协议流程。该系列群的创建、管理员加入、权限设置和成员拉入均通过 Android 原生接口完成。

相关设计：

- `docs/superpowers/specs/2026-08-10-india-community-30-group-batch-design.md`
- `docs/superpowers/plans/2026-08-10-india-community-30-group-batch.md`

### 3.3 执行账号选择逻辑

`GroupExecutionAccountSelector` 从数据库查询在线、正常且仍在群内的账号，优先管理员。选择结果包含账号的真实协议后端，但头像业务本身没有按该后端选择 profile adapter。

相关代码：

- `armada-api/src/main/java/com/armada/group/service/GroupExecutionAccountSelector.java`

### 3.4 头像业务链路

`GroupDetailServiceImpl.updateAvatar` 的处理步骤：

1. 校验图片 MIME 和 5 MiB 大小限制；
2. 解析群目标；
3. 自动选择执行账号；
4. 图片编码为 Base64；
5. 调用 `protocolPorts.profile().updatePicture(...)`；
6. 成功后尽力更新本地头像 URL；
7. 排队刷新 metadata。

相关代码：

- `armada-api/src/main/java/com/armada/group/service/impl/GroupDetailServiceImpl.java`

### 3.5 Profile 协议端口只有 Web 实现

当前 `ProtocolConfiguration` 的 `GroupProfilePort` 直接返回：

```java
return new HttpGroupProfileAdapter(protocolHttpExecutor);
```

项目中只有：

```text
HttpGroupProfileAdapter implements GroupProfilePort
```

没有：

- `AndroidNativeGroupProfileAdapter`
- `GroupProfileBackend`
- `RoutingGroupProfilePort`

对比来看，群设置和群成员操作已经具备：

- Web backend；
- Android backend；
- 根据 `ProtocolAccountRef.backend()` 路由的统一端口。

因此头像和群名称是当前群详情功能中尚未完成多协议路由的缺口。

### 3.6 群名称与群备注并非同一条后端链路

页面“保存群资料”会把群名称和群备注拆成两个相互独立的请求，并使用
`Promise.allSettled` 等待两个结果：

```text
群名称发生变化
  -> POST /api/group-links/{id}/subject
  -> 调用协议修改 WhatsApp 真实群名称

群备注发生变化
  -> PATCH /api/group-links/{id}
  -> 只更新 group_link.remark
```

群名称与头像共用 `GroupProfilePort`，所以 Android 群修改群名称与头像属于同类路由问题。

群备注是纯数据库操作，不经过 Web/Baileys 或 Android 协议，不应该受到上述协议路由缺口影响。

页面显示的通用错误“群资料修改失败”只由协议资料修改异常转换产生，不是群备注接口的错误文案。因此，仅凭该提示不能认定群备注也失败。可能存在以下情况：

1. 实际只修改了群名称，群备注值未变化，前端根本没有发送备注请求；
2. 名称请求失败、备注请求成功，但用户只注意到红色失败提示；
3. 名称和备注分别产生一条失败/成功消息，消息展示时间重叠；
4. 备注请求确实另有数据库、权限或部署版本问题，需要查看独立 PATCH 请求响应。

备注应按以下方式隔离复现：

1. 保持群名称完全不变；
2. 只在群备注输入唯一测试文本；
3. 点击“保存群资料”；
4. 预期只产生 `PATCH /api/group-links/{id}`；
5. 预期提示“群备注已保存”；
6. 关闭并重新打开抽屉，备注仍应存在；
7. WhatsApp 客户端不会出现该备注，因为它是 Armada 本地字段。

如果隔离测试仍失败，应记录该 PATCH 请求的 HTTP 状态、响应 `code` 和 `message`，另行定位本地资料更新链路，不能归因于 Android 协议路由。

### 3.7 页面通用错误的来源

头像协议异常经过 `profileMutationFailure` 转换：

```text
TIMEOUT                  -> 协议调用超时，操作结果待确认，请刷新
GROUP_PERMISSION_DENIED  -> 群操作权限不足
其他协议错误             -> 群资料修改失败
```

页面显示“群资料修改失败”，说明后端收到的是“其他协议错误”。这与 Android 账号被错误发送给 Web 协议层后产生的账号不可用、账号不存在或后端不匹配错误相符。

## 4. 影响范围

### 4.1 明确受影响

- Android 协议群更换头像；
- Android 协议群修改群名称，因为群名称与头像复用同一个 `GroupProfilePort`。

### 4.2 不受该缺口直接影响

- 群备注：纯 Armada 本地数据库操作；
- Android 群“发送新消息”权限；
- Android 群“添加其他成员”权限；
- Android 群设置管理员、取消管理员和踢出成员；
- metadata 读取和成员快照刷新。

上述协议操作已经有 Android backend 或本身不调用协议。

### 4.3 Android 当前明确不支持

- 限时消息；
- 编辑群组设置权限；
- 通过链接邀请权限；
- 管理员批准新成员。

这些能力应返回“不支持”，与本次错误路由问题不同。

## 5. 远端日志验证状态

本次尝试只读连接第一套环境查询 `armada-backend` 最近日志，但本机没有第一套环境 SSH 私钥：

```text
ubuntu@65.2.123.53: Permission denied (publickey)
```

因此尚未取得本次请求的精确 `ProtocolErrorCode`。当前根因结论基于页面错误类型、群来源和代码路由结构，置信度高；仍建议在具备服务器权限后补充以下日志：

```text
群头像更新失败 groupLinkId=... accountId=... code=...
```

预计错误码可能是：

- `ACCOUNT_NOT_FOUND`
- `ACCOUNT_UNAVAILABLE`
- `ACCOUNT_NOT_ONLINE`
- 或其他 Web 协议账号路由失败错误

最终文档应以真实日志中的 `code` 更新该项。

## 6. 建议修复方案

### 6.1 推荐方案：补齐多协议 Profile 路由

参照群设置和群成员操作的结构增加：

```text
GroupProfileBackend
  |- HttpGroupProfileAdapter            (WEB)
  `- AndroidNativeGroupProfileAdapter   (ANDROID)

RoutingGroupProfilePort
  -> 根据 ProtocolAccountRef.backend() 选择 backend
```

同时建议把 `GroupProfilePort` 的方法参数从单一 `String protocolAccountId` 调整为 `ProtocolAccountRef`，避免业务层丢失协议后端、WS 号等路由信息。

### 6.2 Android 能力确认

已确认 Android Zhuan 具备以下原生接口：

- 修改群名称：`POST /ws/v1/groups/settings/name/{wsPhone}`；
- 修改群头像：`POST /ws/v1/groups/settings/avatar/{wsPhone}`。

Android Zhuan 当前没有独立查询群头像 URL 的接口；该项能力返回稳定的：

```text
GROUP_CAPABILITY_UNSUPPORTED
```

前端据此禁用按钮或显示明确说明，不能继续返回泛化的“群资料修改失败”。

### 6.3 临时规避

在正式修复前：

- 不在 Android 群中使用“更换群头像”和“修改群名称”；
- 或确保系统选择到真实在群的 Web/Baileys 管理员后再执行；
- 页面根据执行账号协议后端返回 capability，提前禁用不支持的群资料按钮。

不建议通过伪造 Web 协议账号、跨协议改号或盲目重试来规避。

## 7. 验收标准

修复后至少验证：

1. Web 群修改头像成功；
2. Android 群修改头像成功，或返回明确“不支持”；
3. Web 群修改名称成功；
4. Android 群修改名称成功，或返回明确“不支持”；
5. 协议调用成功后 metadata 任务进入 `SUCCEEDED`；
6. 重新打开群详情后显示的新头像与 WhatsApp 客户端一致；
7. 无权限管理员返回 `GROUP_PERMISSION_DENIED`；
8. 账号不在线时返回可识别的账号错误，不再统一显示“群资料修改失败”；
9. 上传非图片和超过 5 MiB 图片仍在协议调用前被拒绝。
