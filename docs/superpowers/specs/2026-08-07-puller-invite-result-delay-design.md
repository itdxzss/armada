# 管理员邀请拉手回执后延迟设计

## 目标

普通群链接拉群任务中，每次管理员邀请拉手收到协议结果后，固定等待 3 秒才允许提交下一条邀请。避免按首次提交时间计算间隔时，慢回执返回后立即连续发起下一条群邀请。

## 范围

- 仅调整普通群链接任务的“管理员邀请拉手”阶段。
- 固定使用 3 秒，不新增页面配置、数据库字段或协议字段。
- 不改变拉手批量拉料子的 `pullIntervalSeconds` 规则。

## 设计

`PullTaskPullerInviteResultServiceImpl` 接收一条邀请协议回执并写入动作、在群状态后，使用回执发生时间 `callback.occurredAt` 作为基准，将执行行的 `nextRunAt` 写为 `callback.occurredAt + 3_000ms`。

因此，第一条邀请的协议结果时间是 `T` 时，调度器最早在 `T + 3 秒` 才会处理下一条邀请。该时间不再依赖前一条动作的提交时间。

## 错误与兼容性

无论邀请回执为成功、失败或未知，只要回执已被当前状态机接收并完成事实写入，下一次邀请均遵守 3 秒间隔。重复终态回执仍保持无操作，不重新安排执行行。

## 测试

更新 `PullTaskPullerInviteResultServiceImplTest`：构造提交时间为 `1000ms`、回执时间为 `1100ms` 的成功回执，断言写入的 `nextRunAt` 为 `4100ms`。该测试在现有实现下会失败（当前为 `2000ms`），修改生产逻辑后通过。
