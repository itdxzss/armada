# ADR-0007：用草稿任务承载创建页预览计划，不建独立预览计划表

日期：2026-08-02
状态：已接受

## 背景

ADR-0005 要求群链接与 TXT 的随机匹配由服务端生成、由用户在创建页确认、最终创建时原样冻结，并且禁止只在浏览器中随机后信任客户端提交的配对。

第一版数据模型为此设计了独立的 `pull_task_standard_plan` 表：预览时写入一行并返回 `plan_token`，最终创建时校验归属、状态和过期时间后再绑定 `task_id`。该方案带来四项连带成本：

- 执行行的 `task_id` 在预览期必须可空，导致任务详情分页索引和后台调度索引都要容忍 NULL。
- 需要 `plan_status` / `expires_at` 状态机和一个预览过期清理作业。
- 由于 TXT 原文不落库、最终创建不重传文件，规范化号码必须在预览期就写入 `pull_task_material_member`；被弃用的预览会留下成规模的死行，而现有索引都以 `task_id` 打头，清理作业没有可用索引。
- `plan_token` 是一套只为这个流程存在的、需要防猜测的对外标识。

## 决定

- 不建 `pull_task_standard_plan` 表，不引入 `plan_token`。
- `pull_task.status` 增加 `DRAFT`。创建页首次生成匹配计划时直接落一条草稿任务，执行行、料子成员和解析统计全部挂在这条草稿任务下，`pull_task_group_execution.task_id` 全程非空。
- 最终创建 = `DRAFT → WAIT_START` 一次状态迁移：同一事务内写 `pull_task_standard_setting`、复用或插入 `group_link` 并回填 `group_link_id`、把执行行 `execution_status` 从 `0=草稿` 改为 `1=待启动`。不重新随机。
- 任务列表、任务看板和一切统计一律过滤 `status <> 'DRAFT'`；草稿只在创建页可见。
- 一个用户同一时刻只保留一个 `STANDARD` 草稿：重新进入创建页复用同一行，创建页的“清除全部”删除该草稿的全部执行行。
- 草稿期不写 `group_link`，草稿不污染群入口池。
- 草稿期的执行行 `link_occupancy_key` 为 NULL，不占用群链接；占用从 `WAIT_START` 起生效。

## 影响

- 幂等由状态前置校验承担：`DRAFT → WAIT_START` 的更新带状态前置条件和乐观锁版本，重复提交不会产生第二个任务，不需要 `plan_token` 唯一键。
- 不需要预览过期清理作业。遗留草稿的上限是每个用户一行，是常量级而不是随预览次数增长。
- 创建页“清除全部”和单行移除有了明确语义：删除草稿任务的执行行。
- 需要在任务列表、看板、详情和所有聚合查询上统一加 `status <> 'DRAFT'` 过滤，遗漏会让未提交的草稿出现在业务列表里。这一条要有测试覆盖。
- 草稿任务的 `config_json` 允许为 `{}`，因为草稿期配置可能尚未填完。

## 被否决方案

- **独立预览计划表 + `plan_token`**：见背景中的四项连带成本。
- **预览完全不落库，最终创建时浏览器重传文件与配对**：违反 ADR-0005“禁止信任客户端配对”，且要求用户重传已上传的 TXT。
- **预览落 Redis**：需要引入一套与 MySQL 不一致的过期与恢复语义，且冻结时仍要把料子成员写回数据库，没有省掉写入量，只是把可见性变差。
