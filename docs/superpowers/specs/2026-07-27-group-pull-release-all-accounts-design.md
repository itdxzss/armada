# 拉群营销释放全部账号设计

## 背景

第一套测试环境中，拉群营销任务 50 已点击“释放账号”，公共任务状态已经关闭，
但一条已冻结群名的执行持续在建群阶段重试“营销账号群额度确认失败”。现有释放服务只取消
尚未冻结群名的准备执行，并等待其他活动执行自然结束，因此任务长期停留在资源“释放中”，
建群账号占用和营销分组整组锁未释放，后续任务 51 无法启动。

线上数据和当前代码进一步确认了额度异常来源：多个执行共用
`group_pull_marketing_account_stat` 的汇总预留计数。执行已经确认额度、进入添加料子及后续阶段后，
如果最终失败，结算器仍调用 `cancelMarketingQuota`，会错误扣减属于后续执行的预留额度。

## 已确认口径

- 点击“释放账号”表示终止当前拉群营销任务并最终释放该任务下的全部建群账号及营销分组锁。
- 释放开始后不得再启动新的协议操作、后续执行阶段或业务重试。
- 已经开始的单次协议调用允许完成当前调用，随后必须取消执行并释放资源，避免账号在协议调用尚未返回时被其他任务复用。
- 额度异常、已冻结群名或已进入正式建群流程均不得造成无限等待。
- 营销发送侧仍沿用现有安全边界：取消尚未投递的命令，等待已经投递的命令回执后再释放整组资源。

## 方案

### 1. 执行 worker 协作停止

执行 worker 抢到一条执行的租约后，先读取任务资源状态。资源状态为“释放中”时，不再调用好友、
建群、加人、群设置等协议能力，而是进入统一的任务释放取消结算。

这样可以复用现有执行租约：释放按钮与正在进行的协议调用并发时，当前调用可以完成；下一次调度
取得租约后只做取消结算，不会继续下一阶段。无需强制删除正在使用的占用，也不新增数据库租约字段。

### 2. 统一取消活动执行

结果结算器新增“因任务释放而取消”入口，对准备中或执行中的记录执行一次条件终态更新：

1. 状态改为“已取消”，记录任务释放原因和完成时间；
2. 归还尚未最终使用的料子；
3. 仅在额度仍处于预留阶段时取消预留；
4. 删除当前执行的建群账号占用，并记录执行资源已释放。

现有释放服务继续即时取消尚未冻结群名的准备执行。已冻结群名或正式建群中的执行由 worker 在租约
边界取消。所有活动执行结束后，释放服务继续执行现有的残留账号清理、营销分组条件解锁和资源状态
更新，因此任务最终统一进入“已释放”。

### 3. 修正额度结算

额度确认与执行阶段推进位于同一事务：成功确认额度后，执行至少进入“添加料子”阶段；
在“好友准备、创建群组、添加营销账号”阶段，额度仍是预留状态。

因此失败或任务释放取消时按当前阶段处理：

- 阶段早于“添加料子”：调用 `cancelMarketingQuota` 归还预留；
- “添加料子”及后续阶段：额度已经确认，不再扣减汇总预留计数。

这会阻止已确认额度的失败执行偷走后续执行的预留额度。任务整体释放后，额度统计只作为历史事实，
不参与其他任务资源互斥。

## 并发与异常处理

- 执行终态更新继续使用执行 ID、期望状态和期望阶段做条件更新；并发状态变化时不重复归还资源。
- worker 只在成功取得租约后判断释放状态并取消，避免与另一个 worker 同时结算同一执行。
- 释放服务最后仍执行任务级残留占用删除，作为单条执行释放失败或历史脏数据的兜底。
- 营销分组只由当前任务按占用类型和任务 ID 条件解锁，不能误清其他任务的锁。
- 取消结算异常保留在调度重试链路中；下一次扫描继续尝试，不恢复任何业务协议步骤。

## 数据与接口影响

- 不新增或修改数据库表、列、索引。
- 不修改前后端 API 和按钮文案。
- 不修改协议层契约。
- 仅调整拉群营销后台状态流转、额度结算和单元测试。

## 测试与验收

- 失败执行在“添加料子”及后续阶段不再取消预留额度。
- 失败执行在额度确认前仍会归还预留额度。
- 任务资源为“释放中”时，worker 不调用协议端口，直接取消执行并释放账号。
- 正常执行任务仍按原状态机推进。
- 释放服务在全部执行和消息尝试收口后释放残留账号、营销分组锁并标记资源已释放。
- 部署第一套测试环境后，任务 50 的执行 4 自动取消，账号占用和分组 96 锁自动释放；随后验证任务 51 可启动。

## 回滚

代码回滚到上一版本即可恢复原状态机，无数据库回滚。若回滚时存在“释放中”任务，旧版本仍可能等待
正式执行自然结束，因此回滚后需只读核对活动执行、账号占用和分组锁状态。
