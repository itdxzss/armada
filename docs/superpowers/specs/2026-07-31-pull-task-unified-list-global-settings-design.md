# 拉群任务统一列表与全局设置设计

日期：2026-07-31
状态：已在当前本地 checkout 实现并验证，未提交、未部署
目标仓库：`armada`、`wheel-saas-pure-web`

## 1. 背景

本设计只处理《拉群营销 PRD V1.2》的“拉群任务”公共一级列表，以及该列表顶部的“全局设置”能力。目标页面是前端 `src/views/task/pull-task/` 对应的“拉群任务”菜单，不是独立的“拉群营销”菜单。

当前前端已经按静态原型放置了十个列表列组和一批可选营销统计字段，但后端 `/api/pull-tasks` 仍只查询独立 `pull_task` 配置表，并返回普通拉群任务的最小字段。拉群营销创建页目前是未接通提交接口的前端草稿，不会产生后端任务记录。独立“拉群营销”菜单的数据属于另一套建新群营销业务，不得并入本列表冒充本 PRD 的历史老群/自收群接管任务。

## 2. 已确认业务口径

1. 拉群任务列表是普通拉群任务和拉群营销任务的公共入口。
2. 一级列表固定为九个合并列：任务信息、任务状态、群组处理进度、拉人结果、营销进度、消息发送、异常情况、剩余资源、时间/操作。
3. 拉群营销的任务状态、群组来源、统计口径和资源语义独立管理；普通拉群任务保留原有语义。
4. 列表顶部保留“新建拉群任务”，点击后先选择任务类型。
5. 列表顶部增加“全局设置”，原样恢复 PRD 的三个租户级字段：营销静默时间、群组封控时间、单群营销账号上限数量。
6. 全局设置首次没有系统默认值。未配置时不得创建拉群营销任务，页面引导有权限的用户先完成配置。
7. 全局配置修改只影响修改后创建的任务。营销静默时间和群组封控时间在任务中只读；单群营销账号上限可设得更小，但不得超过全局值。任务快照的真正写入随拉群营销创建接口实现，不在本列表切片中伪造。
8. 不合并、不迁移独立“拉群营销”菜单的旧任务数据。
9. 不伪造执行统计或任务操作结果；未知值与真实零值必须区分。

## 3. 方案选择

### 3.1 采用：公共任务主表 + 类型专属统计表

现有 `pull_task` 继续作为公共拉群任务主表，增加任务类型、群组来源、主要阶段、阻塞原因和最近业务执行时间。新增一张与拉群营销任务一对一的聚合统计表，承载一级列表和未来任务详情顶部需要的营销统计。

优点：

- 公共身份、分页和状态入口集中在一张任务主表。
- 营销专属统计不会把普通拉群任务主表扩成大量可空列。
- 一级列表只读取任务主表和一张一对一聚合表，不扫描号码、消息和单群明细。
- 聚合表缺失与统计值为零具有明确区别。

### 3.2 不采用：只扩展前端 DTO

只增加可选字段会让营销列长期显示 `--`，无法形成真实的前后端契约，也无法验证统计口径。

### 3.3 不采用：运行时合并独立拉群营销任务

现有 `marketing_task`、`group_pull_marketing_task` 表表达的是另一套建新群营销业务。其群组来源、状态、成功标准和资源释放规则与本 PRD 不一致，直接 `UNION` 会产生错误统计、ID 冲突和错误行操作。

## 4. 数据模型

### 4.1 公共任务主表 `pull_task`

在现有字段基础上增加：

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `task_type` | `VARCHAR(32) NOT NULL` | `STANDARD` 或 `GROUP_MARKETING`；历史数据回填 `STANDARD` |
| `group_source` | `VARCHAR(32) NULL` | `HISTORICAL`、`SELF_COLLECTED`、`MIXED`；普通任务为空 |
| `primary_stage` | `VARCHAR(64) NULL` | 当前主要业务阶段，不与任务状态合并 |
| `blocking_reason` | `VARCHAR(255) NULL` | 当前阻塞、暂停或停止原因，展示优先于主要阶段 |
| `last_business_executed_at` | `BIGINT NULL` | 最近一次真实业务步骤完成或提交时间 |

历史任务的 `last_business_executed_at` 不使用创建时间或更新时间回填，避免把页面刷新、普通更新等事件冒充业务执行。

拉群营销状态采用：

- `DRAFT`
- `WAIT_START`
- `VALIDATING`
- `WAITING_RESOURCE`
- `EXECUTING`
- `PARTIAL_COMPLETED`
- `PAUSED`
- `STOPPED`
- `COMPLETED`
- `FAILED`

普通拉群任务保留现有状态语义，不通过数据迁移强行改写历史状态。

### 4.2 拉群营销统计表 `pull_task_group_marketing_summary`

该表是任务级聚合读取模型，不是执行日志或明细事实表。`task_id` 与 `pull_task.id` 一对一，并带 `tenant_id` 参与租户隔离和索引。

字段按统计口径分组：

| 分组 | 字段 |
| --- | --- |
| 群组处理 | 目标群组、转移成功、转移待收口、转移部分完成、转移失败、执行中、等待执行 |
| 拉人结果 | 计划目标、有效目标、新增成功、已在群内、隐私限制、无效号码、未注册、结果未知、剩余待拉 |
| 营销进度 | 待开始、进行中、已暂停、已完成、异常停止群组数 |
| 消息发送 | 最终成功、最终失败、结果未知消息数 |
| 异常情况 | 去重异常群组、缺少拉手群组、去重封禁账号数 |
| 剩余资源 | 剩余有效目标数据、可用拉手、目标数据/拉手/水军/管理员/营销账号不足标志 |
| 审计 | `created_at`、`updated_at` |

规则：

- 没有统计行表示该类型不适用或统计尚未形成，API 返回空统计，前端显示 `--`。
- 已存在统计行中的计数使用非负整数，真实零值显示为 `0`。
- “已处理群组数”由转移成功、转移待收口、转移部分完成、转移失败四类终态之和计算，不把执行中、等待执行或暂停未形成结果的群计入。
- 有效成功率由“新增成功人数 ÷ 有效目标人数”计算；分母未知或不大于零时不返回百分比。
- 缺少拉手群组是异常群组的子集，不与异常群组相加。
- 消息成功、失败、结果未知互斥；同一业务消息最终成功时只计一次成功。
- 聚合统计由未来的任务执行与结果收口逻辑更新，并可从事实明细重建。本列表切片只建立表、查询契约和测试，不伪造执行生产者。

### 4.3 全局设置表 `pull_task_group_marketing_setting`

每个租户最多一行：

| 字段 | 约束 |
| --- | --- |
| `tenant_id` | 主键或唯一键；只能来自当前租户上下文 |
| `marketing_silence_minutes` | 非负整数 |
| `group_lockdown_minutes` | 非负整数 |
| `max_marketing_accounts_per_group` | 正整数 |
| `created_by` / `updated_by` | 当前用户 ID |
| `created_at` / `updated_at` | epoch 毫秒 |

表中没有记录即表示“未配置”，后端不得用硬编码业务默认值兜底。保存使用租户内原子新增或更新。

## 5. 后端接口设计

### 5.1 拉群任务列表

`GET /api/pull-tasks`

查询参数：

- `page`、`pageSize`
- `id`
- `keyword`：任务名称或群名称
- `status`
- `taskType`
- `groupSource`
- `operator`

删除当前前端存在但后端不执行的“是否交单”和“群组是否封禁”筛选，避免无效条件误导用户。

列表行使用明确的列表 VO，不再用 `Map<String, Object>` 拼装。响应按九列语义组织：

- 任务身份：ID、名称、类型、群组来源。
- 状态：状态码、主要阶段、阻塞原因。
- 群组处理统计及悬浮明细。
- 拉人结果及有效成功率悬浮明细。
- 营销状态统计。
- 消息最终结果统计。
- 异常统计。
- 剩余资源和不足类型。
- 最近业务执行时间及后端实际支持的操作集合。

后端只返回当前确实可执行的行操作。没有任务执行器支持的动作不通过前端假按钮冒充成功；以后接入执行器时，由类型专属服务扩展操作集合和命令接口。

分页、筛选和排序全部下推 SQL。查询必须由当前租户隔离，默认按任务 ID 倒序。

### 5.2 全局设置

`GET /api/pull-tasks/group-marketing-setting`

- 需要拉群任务查看权限。
- 未配置时返回 `configured=false` 和空值，不创建默认记录。

`PUT /api/pull-tasks/group-marketing-setting`

- 需要新权限 `tenant:pull_task:settings`。
- 三个字段必须同时提交并通过范围校验。
- 保存成功返回当前生效配置。
- 不更新或回写任何历史任务。

### 5.3 现有接口兼容

- 普通拉群任务创建、详情、导出和现有生命周期接口保留原契约。
- 批量删除由后端按任务类型和状态重复校验：拉群营销只允许删除草稿；普通任务保留现有删除规则。
- 独立 `/api/group-pull-marketing-tasks` 及其表不修改。

## 6. 前端设计

### 6.1 查询区

保留任务 ID、任务名称、任务状态，并在展开条件中提供任务类型、群组来源和操作员。删除无效的“是否交单”和“群组是否封禁”。

### 6.2 操作区

- “新建拉群任务”先打开任务类型选择。
- 普通拉群任务继续使用既有创建契约。
- 拉群营销进入现有 `/task/pull-task/create` 独立页面。
- “全局设置”打开 Element Plus 弹框，只有 `tenant:pull_task:settings` 权限用户可以保存。

### 6.3 九列列表

1. 任务信息：任务名称；`#任务ID｜任务类型｜群组来源`。
2. 任务状态：状态标签；优先显示阻塞/暂停/停止原因，否则显示主要阶段。
3. 群组处理进度：已形成转移结果群组数/目标群组数及进度条；悬浮显示各转移状态数量。
4. 拉人结果：新增成功/计划人数、有效成功率；悬浮显示完整号码分类统计。
5. 营销进度：进行中、完成；悬浮显示待开始、暂停和异常停止。
6. 消息发送：成功、失败、未知；未知为零时可隐藏。
7. 异常情况：异常群组、其中缺少拉手群组、封禁账号；三者不错误相加。
8. 剩余资源：目标数据、可用拉手和明确的不足标签。
9. 时间/操作：只展示最近业务执行时间，并渲染接口返回的实际可用操作。

不再把“时间”和“操作”拆成两个独立列，也不默认展示创建时间。

### 6.4 全局设置与新增页联动

- 弹框打开时读取当前租户设置；保存成功后关闭并提示。
- 所有字段使用 Element Plus 数字输入，静默/封控允许 `0`，营销账号上限从 `1` 开始。
- 拉群营销新增页读取设置。未配置时展示阻断提示；已配置时只读展示静默和封控时间，任务级营销账号上限默认取全局值且不能超过它。
- 当前创建页尚未接入后端保存，仍使用明确的“接口未接通”提示。本切片不得只保存局部任务配置或伪造配置快照。

## 7. 错误处理与一致性

- 所有写入必须从租户上下文取得 `tenant_id`，禁止信任前端传租户。
- 设置参数非法、无权限、任务类型或状态不允许操作时抛业务异常。
- 列表统计读取失败时整个请求失败并记录非敏感上下文，不返回静态演示数据。
- 设置保存采用事务；并发首次保存由租户唯一键保证单行。
- 数据库变更只通过实施时确认的下一个可用 Flyway 版本执行，不手改共享数据库。

## 8. 测试与验收

### 8.1 后端

- Flyway 脚本结构、约束和历史数据 `STANDARD` 回填测试。
- H2 MySQL 模式加载真实 Mapper XML，验证租户隔离、分页下推、条件筛选、无统计行、真实零值和九列统计映射。
- Service 测试覆盖已处理群组数、有效成功率、异常子集、资源不足标签和实际操作集合。
- 全局设置测试覆盖未配置、首次保存、更新、租户隔离、三个字段边界和权限。
- Controller 契约测试覆盖列表及设置接口的 camelCase 响应。

### 8.2 前端

- 纯函数测试覆盖空值与零值、进度、成功率、状态/来源文案、消息未知零值隐藏和资源不足标签。
- 页面测试覆盖九列、合并“时间/操作”、查询条件、任务类型选择、状态操作和权限。
- 全局设置弹框测试覆盖读取、校验、取消、保存、未配置状态以及新增页联动。
- 执行 TypeScript、Vue TypeScript、相关测试和生产构建。

### 8.3 人工验收

- 普通任务和拉群营销任务在同一列表分页，独立“拉群营销”菜单不受影响。
- 营销任务九列口径与 PRD 一致，悬浮信息完整，未知值不冒充零。
- 最近执行时间不使用创建时间或普通更新时间替代。
- 全局设置未配置时新增页明确阻断；保存后可正确读取和限制任务级上限。

## 9. 边界与后续

本设计不实现拉群营销完整创建、群组接管、资源调度、消息执行或协议层能力。统计表的生产更新、任务配置快照落库、暂停/恢复/停止命令需要在对应执行切片中实现。本切片只建立真实、可扩展、无假数据的公共列表与全局设置纵切。

不执行部署、SSH、真库验证或共享环境数据修改；如后续需要部署，必须另行确认目标环境。
