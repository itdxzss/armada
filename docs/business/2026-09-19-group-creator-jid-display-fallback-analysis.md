# 老格式群 JID 创建者及国家、洲兜底分析

日期：2026-09-19。后续已按用户指令在主仓实现后端统一兜底及来源优先级，145项聚焦测试通过；未提交、推送或部署。最终实现与扩展回归边界见 [变更记录](../../.harness/changes/group-creator-jid-fallback/summary.md)。下文保留分析过程。

## 补充需求后的有效方案

用户补充：首次上线读取历史群、群变更事件触发读取时，都要在无法取得创建者 PN 的情况下，用老格式群 JID 补齐号码，再解析国家和洲。因此，下文原“仅前端展示”方案已不足以覆盖本次范围；以本节为准。

### 已核对的入口与复用能力

- Android 首次/全量同步 `internal/armada/groups_fetcher.go`、单群快照 `group_snapshot_client.go`、事件协调器 `group_snapshot_coordinator.go` 共用创建者解析与 `reportedGroupProfile`，资料负载含群 JID。
- Web `worker/group-profile-event.ts` 的 `groupProfileReported` 被完整参与群同步、完整 `groups.upsert` 资料投影、快照命令等复用；资料负载含群 JID。轻量列表或部分字段事件不保证包含完整创建者信息。
- 后端 `GroupProfileReportedSinkAdapter.writeCreator` 当前遇到空 `creatorPhone` 即跳过；其事件已有群 JID，可在后端创建者处理环节统一兜底，不必为了截取 JID 在多个协议仓库各写一套规则。
- HTTP 资料刷新等非事件入口也需接入同一规则。轻量列表登记、精确变更事件应检查其群入口关联与调用位置，不能仅修改一个完整资料事件入口就宣称覆盖所有路径。
- `CountryServiceImpl.resolveActiveCountriesByPhoneNumbers` 已使用 libphonenumber 校验国际号码，映射有效国家主数据，再返回国家与洲；直接复用，不新增国家推断服务。

### 建议处理与持久化规则

1. 继续优先使用现有明确创建者 PN、同一人的成员 PN、可信 LID 映射结果。
2. 无可用号码时严格匹配老格式群 JID，生成来源为 `JID_DERIVED` 的候选号码；保留协议未解析或冲突原因，不将候选伪装成协议成功返回的 PN。
3. 写入时对比既有来源：真实号码优先于推导号码；空响应、推导响应不能降级已保存的真实号码。两个不同真实号码仍保留现有冲突保护。
4. 当前库没有持久化创建者来源优先级，不能直接复用“不同号码不覆盖”的 SQL。建议增加最小来源标记，并让所有创建者写入口遵守相同规则；若实施，须通过 Flyway 变更。已有非空号码先按既有保护级别保留，不批量猜测其历史来源。
5. 真实 PN 替换推导号码时，国家、洲按新号码一起重新计算。若新号码暂时无法解析国家，清除旧推导号码对应的国家、洲，避免错配；手机号本身仍可保留。
6. 当前国家校验及主数据查找可能无结果，因此“取得号码”不等于“国家、洲必然都有值”；未知项继续显示 `-`。国家表示号码归属，洲来自国家主数据，不表示建群人的实际所在地。
7. 推导结果不能自动升级为群管理员角色、当前在群身份或操作权限的证据。现有 SQL 使用创建者兼容列做关系分类，实施时需结合来源审查并保护这些消费者。

### 范围与验收

推荐后端统一兜底及来源优先级写入，前端继续消费三项字段；协议原始解析结果保持可区分。首次上线、事件触发刷新、手动刷新/HTTP 快照均需验证。已有存量空值在后续有效同步后可补齐；若要立即补齐全部老数据，需要单独有范围的回填或读取侧补齐方案，不能把发布当成存量自动修复。

关键验收包括：正常 PN 不变；PN 缺失时老 JID 补齐三项；新格式或非法 JID 不误解析；推导值后到不能覆盖真实值；真实 PN 后到可替换推导值及国家、洲；无 PN 的部分事件不清空已有值；同租户及跨租户边界保持；角色/在群判定不因推导被误确认。

当前仅核对本地代码。以下保留初版展示分析，作为范围变化记录，不作为当前实施建议。

## 需求与结论

优先展示接口实际返回的创建者；创建者为空时，严格匹配 `号码-时间戳@g.us`，取号码部分；均无可用值时显示 `-`。

建议在前端群列表使用独立展示函数实现。JID 推导结果只用于本次要求的“创建者”文字，不修改接口原始对象或持久化创建者事实。这样已有历史行只需重新加载页面，不依赖重新获取群资料；后续接口提供真实创建者时自然优先显示真实值。

## 当前代码事实

- 前端 `src/views/group/list/components/GroupListTable.vue:302` 为 `row.creatorPhone || "-"`。
- 前端 `src/api/group.ts` 的 `GroupListRow` 已包含 `creatorPhone` 和 `groupJid`，列表适配未做该兜底。
- 后端 `GroupListCurrentMapper.xml` 从 `legacy_preview.owner_phone` 读取号码；`GroupConverter.toGroupLinkVO` 将号码放入 `creatorPhone`。
- `GroupCreatorPhones.phone` 仅接收裸数字及 PN JID，不接收群 JID；这是身份解析边界，不应为展示需求放宽。
- `GroupLinkPreviewMapper.xml` 的 `confirmedCreator` 仅允许原号码为空或与新号码相同的更新。因此把推算值写入同一字段，可能阻止后续不同的真实号码写入。
- `GroupListCurrentMapper.xml` 还使用持久化创建者号码判断创建者在群关系及进行关键词匹配；将推断写入该字段会扩大需求影响。
- 后端列表响应会基于已有号码补齐国家/洲。本次若仅做前端展示兜底，推算号码不会触发该补齐。

以上来自两个主仓库 `1.0.3-snapshot` 当前工作区，包含既有未提交修改，不代表截图环境的运行版本。没有重新读取截图目标群的接口、数据库或协议日志，不能据此确定这些群缺少创建者的具体协议原因。

## 建议实现规则

1. `creatorPhone` 去除首尾空白后非空，直接使用，不比较或覆盖它。
2. 否则对去除首尾空白的 `groupJid` 用 `/^([0-9]+)-([0-9]+)@g\.us$/` 完整匹配，返回第一组字符串。
3. 不匹配时显示 `-`。不把整群 ID、LID、管理员号码当成兜底。
4. 号码保留字符串，不转整数；不将时间戳部分用于修改建群时间。
5. 空包含 null、undefined、空串和纯空白。接口中的非空异常值不是本需求已经定义的空值，不擅自扩展清洗规则。
6. “读取失败”仅指行数据仍可用、创建者字段缺失的场景；整次列表请求失败仍沿用原错误处理，不能以解析 JID 冒充请求成功。

可选提示：仅对推导值增加悬浮说明“根据群 JID 推算”。号码本身仍按需求展示。推导值属于历史号码线索，不作为当前管理员、在群状态或操作权限的证明。

## 影响与验证

- 最小范围为前端展示函数、群列表调用与针对性测试。API、数据库、协议、租户隔离和任务状态不变；无迁移或数据回填。
- 国家、洲、建群时间、后端搜索筛选不随推导号码变化。若之后需要这些能力，需另外定义推导来源与真实来源的优先级，不能直接回填当前字段。
- 必测：示例 JID + 空创建者；真实创建者与前缀不同；null/空串/空白；无连字符的新式群 ID；错误域名；非数字或多个连字符；先显示推导值后接口返回真实值。
- 前端发布后，有符合格式 JID 的已有列表行可立即获得展示兜底；这不等于协议原始创建者信息已恢复。
- 回滚只需回退展示函数及调用，没有数据库恢复工作。实施及发布尚未执行。
