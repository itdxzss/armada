# 普通营销任务允许在线抢登账号设计

> 状态：已确认
>
> 日期：2026-07-17
>
> 目标仓库：`armada`
>
> 用户确认口径：普通营销任务允许选择在线的正常、被抢登、抢登中账号；离线账号仍不可选择

## 1. 背景与目标

普通营销任务“新增营销任务”抽屉通过
`GET /api/marketing-tasks/account-tree` 加载账号节点。当前后端只有
`account_state=2（正常）`且`login_state=1（在线）`的账号会返回
`selectable=true`，创建任务时固定群组和账号动态两种目标查询也只接受正常账号。

抢登中账号收到协议 `ONLINE` 事件后会保持 `account_state=7（抢登中）`，同时把
`login_state` 更新为在线。因此它虽然具备发送条件，仍会被普通营销任务的正常状态门禁排除。

本次目标是把普通营销任务允许的账号生命周期状态扩展为：

- `2`：正常。
- `6`：被抢登。
- `7`：抢登中。

三种状态都必须当前在线。离线、风控、禁言、群同步未完成、缺协议账号、被其他普通营销任务占用等现有门禁全部保留。

## 2. 范围

### 2.1 包含

- 普通营销任务账号树的账号可选性判断。
- 普通营销任务固定群组目标的创建校验。
- 普通营销任务账号动态目标的创建校验。
- 与上述候选状态一致的 Mapper 查询条件和回归测试。

### 2.2 不包含

- 不修改建群营销、历史群营销或其他任务的账号候选口径。
- 不允许离线账号进入普通营销任务。
- 不改变风控、禁言、baseline、协议账号和账号占用规则。
- 不改变账号状态机及抢登自动续上线流程。
- 不新增接口字段，不改变前端页面结构，也不调整账号树状态文案。
- 不修改数据库结构或存量数据。

## 3. 方案选择

### 3.1 采用：后端统一放开状态集合

账号树服务把可选择生命周期状态从“仅正常”改为“正常、被抢登、抢登中”，同时继续要求机器状态为在线。
创建任务使用的固定群组候选和账号动态候选 SQL 同步接受相同的三个状态，避免出现前端能勾选、后端创建失败。

前端已经完全以响应字段 `selectable` 控制节点禁用和默认勾选，因此不需要生产代码改动。

### 3.2 不采用：只改前端

只改前端会允许用户勾选账号，但创建接口仍因账号状态不是正常而拒绝请求，造成前后端口径不一致。

### 3.3 本期不采用：新增抢登状态展示

账号树当前 `status/statusText` 主要表达在线、离线、风控、封禁、禁言等发送机器状态。
本次只调整可选性，不扩展 API 契约或页面文案，保持变更聚焦。

## 4. 数据流与业务规则

账号树数据流保持不变：

```text
账号分组
  -> MarketingTaskMapper.selectAccountTreeAccounts
  -> MarketingAccountTreeRealtimeService.selectable
  -> MarketingTreeAccountVO.selectable
  -> GroupMarketingCreateDrawer 禁用/勾选账号节点
```

调整后的可选条件为：

```text
未被其他普通营销任务占用
AND login_state = ONLINE
AND account_state IN (NORMAL, LOGIN_REPLACED, TAKING_OVER)
AND group_baseline_state != PENDING
AND protocol_account_id 非空
AND 无风控
AND 无禁言
```

其中账号树服务继续负责组合展示状态、baseline、协议账号和占用规则；Mapper 创建候选继续负责账号分组归属、在线、生命周期状态、风控、禁言等数据库事实校验。

## 5. 接口、数据与安全影响

- API：路径、请求体和响应结构均不变，仅 `selectable` 的业务取值范围扩大。
- 数据库：无表结构、索引、Flyway 或数据修复。
- 租户隔离：沿用现有 MyBatis 租户拦截和账号分组归属条件。
- 占用：仍由 `MarketingAccountOccupancyService` 阻止同一账号被多个普通营销任务占用。
- 回滚：回退本次 Java/Mapper 条件及测试即可恢复“仅正常在线可选”。

## 6. 测试设计

按 TDD 先增加失败测试，再改生产代码：

1. `MarketingAccountTreeRealtimeServiceTest`
   - 在线被抢登账号返回 `selectable=true`。
   - 在线抢登中账号返回 `selectable=true`。
   - 离线抢登中账号仍返回 `selectable=false`，原因仍为“离线”。
2. `MarketingTaskCreateReadDbTest`
   - 在线被抢登账号可以创建账号动态营销目标。
   - 在线抢登中账号可以创建账号动态营销目标。
   - 离线抢登中账号创建仍被拒绝。
3. `MarketingTaskMapperSqlShapeTest`
   - 固定群组和账号动态创建候选使用相同的允许状态集合。
4. 运行相关单元测试和真库 DbTest；缺少真库环境时必须明确报告，不能用 mock 结果代替真库证据。

## 7. 验收标准

- 正常、被抢登、抢登中账号在当前在线且满足其他现有条件时，都能在新增普通营销任务中勾选并成功创建。
- 上述任一状态当前离线时都不能勾选；绕过前端提交也会被后端拒绝。
- 其他异常状态和既有门禁行为不变。
- 不产生前端生产代码、API 契约或数据库迁移改动。
